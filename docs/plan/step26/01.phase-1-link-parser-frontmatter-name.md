# Phase 1: link-parser.js frontmatterName 파싱

## Phase 1: frontmatterName 파싱 (FR-26-002)

### 목표
`link-parser.js`의 `buildLinkTree()` 함수가 frontmatter `name:` 필드를 파싱하여 트리 노드에 `frontmatterName` 속성을 추가한다. Phase 2, 3의 선결 조건이다.

## 기존 코드 재사용 힌트

- `link-parser.js` **L216-220**: 기존 `title:` 파싱 정규식 — `name:` 파싱도 동일 패턴 사용
  ```javascript
  // 기존 title 파싱 (L216-220)
  const frontmatterMatch = content.match(/^---\s*\n[\s\S]*?title:\s*(.+)\n[\s\S]*?---/);
  if (frontmatterMatch) {
    title = frontmatterMatch[1].trim().replace(/^["']|["']$/g, '');
  }
  // → name: 파싱도 동일 패턴으로, title 블록 바로 아래에 추가
  ```
- `link-parser.js` **L212**: 파일 미존재 반환 노드 — `frontmatterName: null` 추가 필요
- `link-parser.js` **L227**: globalSeen leaf 노드 — `frontmatterName` 추가 필요
- `link-parser.js` **L245**: 루트 반환 노드 — `frontmatterName` 추가 필요
- `link-parser.js` **L92**: `buildDirectoryTree()` 파일 노드 생성 — `frontmatterName: null` 추가 필요

  // name 필드 파싱 (title 파싱 블록 바로 아래 추가)

  }

## 언어+버전 주의사항
- Node.js 20, CommonJS (require/module.exports)
- 정규식 `[\s\S]*?` — greedy 방지 필수. frontmatter 내 필드 순서 무관하게 동작해야 함
- `name:` 값에 YAML 따옴표 `"` `'` 포함 가능 — `.replace(/^["']|["']$/g, '')` 제거 처리 필수

---

## LLM 코딩 주의사항
- **Simplicity**: 별도 함수 추출 금지. 기존 title 파싱 패턴을 그대로 복사하여 `title` → `name`만 변경.
- **Surgical**: title 파싱 블록(L216-223) 이후에 name 파싱만 추가한다. 기존 로직 수정 없음. `globalSeen` leaf 반환(L227) 위치 이전으로 파싱 코드 이동 시 L215-L229 범위 내에서만 수정.

## 테스트 시나리오

### 정상 케이스
- Given: frontmatter에 `name: "내 문서"` 있는 .md 파일
  When: `buildLinkTree(filePath)` 호출
  Then: 반환 노드의 `frontmatterName === "내 문서"`

### 예외 케이스
- Given: frontmatter 없거나 `name:` 필드 없는 파일
  When: `buildLinkTree(filePath)` 호출
  Then: 반환 노드의 `frontmatterName === null`

### 경계값 테스트
- Given: `name: ""` 또는 `name: '   '` (공백만)인 파일
  When: `buildLinkTree(filePath)` 호출
  Then: `frontmatterName === null`
- Given: `name: "이름"` 있는 파일이 globalSeen에 이미 등록된 경우 (leaf 노드)
  When: `buildLinkTree(filePath)` 호출
  Then: leaf 노드에도 `frontmatterName === "이름"` (null 아님)
