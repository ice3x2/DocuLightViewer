# Step 26 아키텍처 설계

## 개요

Step 26은 렌더러 프로세스(`src/renderer/`)와 메인 프로세스(`src/main/link-parser.js`)에 걸친 증분 확장이다. 기존 아키텍처를 그대로 유지하며 최소한의 지점만 수정한다.

---

## 변경 범위

```
src/
├── main/
│   └── link-parser.js         ← FR-26-002: frontmatterName 필드 추가
└── renderer/
    ├── viewer.html             ← FR-26-001: 토글 버튼 HTML 추가
    ├── viewer.js               ← FR-26-001, FR-26-003: 토글 로직, 하단 박스
    ├── viewer.css              ← FR-26-001, FR-26-003: 토글 버튼, #doc-nav-box CSS

    ├── en.json

```

## 데이터 흐름

```
link-parser.js
  buildLinkTree() / buildDirectoryTree()
    → 파일 노드에 frontmatterName 추가
    → IPC: onSidebarTree 이벤트

viewer.js
  onSidebarTree 핸들러
    → window.DocuLight.state.sidebarTree 저장
    → renderSidebarTree(tree) 호출
    → updateDocNavBox() 호출 [신규]

  #btn-sidebar-name-toggle 클릭
    → window.DocuLight.state.showFrontmatterName 토글
    → renderSidebarTree(tree) 재호출
    → updateDocNavBox() 재호출 [신규]

  onRenderMarkdown 핸들러
    → state.currentFilePath 업데이트
    → updateDocNavBox() 호출 [신규]

  updateDocNavBox() [신규 함수]
    → collectAllFiles(sidebarTree) → files[]
    → 현재 파일 인덱스 탐색
    → prev/next 파일 결정
    → #doc-nav-box DOM 업데이트
```

---

## 신규 함수 목록

| 함수 | 위치 | 역할 |
|------|------|------|
| `collectAllFiles(node)` | viewer.js | 사이드바 트리 DFS, 파일 노드 목록 반환 |
| `updateDocNavBox()` | viewer.js | #doc-nav-box 생성/업데이트/숨김 |
| `getDisplayName(node)` | viewer.js | showFrontmatterName 상태 고려한 표시명 반환 |

---

## 의존성 순서

```
Phase 1: link-parser.js frontmatterName 파싱
    ↓ (트리 노드에 frontmatterName 필드 존재해야)
Phase 2: 사이드바 이름 토글 (renderTreeNode 수정 + 버튼 추가)
    ↓ (showFrontmatterName 상태 + getDisplayName 함수 필요)
Phase 3: 하단 이전/다음 박스 (collectAllFiles + updateDocNavBox)
```
