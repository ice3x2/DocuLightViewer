# Step 26 기술 결정 기록 (ADR)

## ADR-001: frontmatterName 파싱 위치

**결정**: `link-parser.js`의 `buildLinkTree()` 함수에서만 파싱 추가

**이유**: `buildDirectoryTree()`는 파일 내용을 읽지 않는다. `buildLinkTree()`는 이미 파일 내용(`content`)을 읽고 `title`을 파싱하므로 추가 I/O 없이 같은 정규식 확장으로 `name` 필드를 추출 가능.

**trade-off**: 디렉토리 트리 전용 모드에서는 `frontmatterName`이 `null`이 됨. SRS 범위 내(디렉토리 트리는 파일명 기준 표시)이므로 허용.

**구현**: `buildLinkTree()` 내 title 파싱 블록 바로 아래에 `name:` 필드 파싱 추가.

## ADR-002: showFrontmatterName 상태 저장 위치

**결정**: `window.DocuLight.state.showFrontmatterName` (렌더러 메모리)

**이유**: SRS FR-26-001에서 "창 세션 한정, 새 창 시 초기화, 창 간 공유 없음"으로 명시. electron-store 불필요.

---

## ADR-003: #doc-nav-box 삽입 전략

**결정**: JS로 동적 삽입 (`#content` 다음 형제로), 기존 박스 재사용

**이유**: 마크다운 렌더링 시마다 `#content.innerHTML`이 교체되므로 내부 삽입 불가. 외부 형제로 유지하여 렌더링 생명주기와 독립.

**재사용**: `updateDocNavBox()` 첫 호출 시 DOM 생성, 이후 호출 시 텍스트/href 업데이트만 수행 (완전 재생성 금지 - NFR-26-001).

---

## ADR-004: getDisplayName 헬퍼 함수

**결정**: `renderTreeNode`와 `updateDocNavBox` 양쪽에서 표시명 결정 로직을 공유하기 위해 별도 헬퍼 함수 `getDisplayName(node)` 추출

**이유**: 동일한 조건 로직(`showFrontmatterName && node.frontmatterName && node.frontmatterName !== ''`)이 두 곳에서 필요하므로 중복 방지.

---

## ADR-005: collectAllFiles 순환 참조 처리

**결정**: 트리는 이미 `buildSidebarTree()`에서 DAG임이 보장되므로 visited set 불필요

**이유**: link-parser.js의 `globalSeen`으로 중복 확장이 이미 방지됨. DFS 순회 시 단순 재귀로 충분.
