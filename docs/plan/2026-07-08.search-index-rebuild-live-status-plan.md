# Search Index Rebuild Live Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 검색 인덱스 다시 만들기 흐름을 "전체 인덱스 재작성"으로 명확히 만들고, Settings 관리 화면에서 진행 상태와 현재 인덱싱 파일을 실시간으로 보여주며, 중단/종료/신규 문서 추가 상황까지 검증한다.

**Architecture:** Settings UI는 rebuild action을 시작한 뒤 빠른 상태 폴링으로 worker status를 표시한다. Electron main process는 status payload를 사용자 표시용으로 정규화하고, worker/controller는 full rebuild session의 total/current/currentPath와 durable keyword rebuild job recovery를 관리한다. 검색 인덱스의 물리적 교체는 staged generation을 사용해 실패나 crash 시 마지막 committed index를 보존하고, 성공 후 semantic/link/HNSW derived state를 지운 뒤 active documents를 다시 queue한다.

**Tech Stack:** Electron main process CommonJS, renderer HTML/CSS/JS, worker_threads 기반 `search-index-worker.js`, `better-sqlite3`, SourceLedger SQLite, Node test scripts.

## Global Constraints

- Project file reads and writes must use UTF-8.
- Before implementation, read `docs/spec/00.index.md` and use active target `0.11.0-w2`.
- Relevant Requirement IDs: `REL-DOC-007`, `IR-APP-010`, `FR-DOC-019`, `FR-DOC-022`, `FR-DOC-035`, `SEC-DOC-003`.
- TDD is required for behavior changes: write or update failing automated tests before implementation.
- Indexing controls remain Settings IPC/UI only and must not be added to MCP tools.
- Search requests must not start long full rebuilds.
- Worker rebuild, compact, semantic indexing, and HNSW maintenance must stay outside the Electron main process.
- Raw absolute paths, userData paths, and internal index paths must not be exposed in Settings diagnostics or external payloads; use source-relative display paths or redacted path tokens.
- Current SRS conflict: `IR-APP-010` AC-3 explicitly includes a Settings clear action. Removing the visible delete button must be preceded by a new `0.11.0-w2` SRS requirement that supersedes the user-facing clear action while keeping existing MCP non-exposure guarantees.

## User Requirements Understood

1. Clicking "검색 인덱스 다시 만들기" must behave as a complete rebuild from scratch, not a partial repair.
2. When rebuild starts, Settings must show the rebuild session as fresh: indexed count starts at `0`, pending/progress updates live, and the currently indexed file is visible live.
3. Current UI does not update rebuild status fast enough; this must be verified and fixed.
4. The "검색 인덱스 삭제" button must be removed because rebuild already performs delete plus rebuild semantics.
5. If the app process exits while rebuild is incomplete, startup must recognize the incomplete rebuild and automatically start a new search index rebuild.
6. During search index rebuild, the "인덱싱 중지" button must be disabled and remain disabled until the rebuild is fully successful.
7. If a new Markdown document is added while rebuild is running, the finished index must include it; this must be tested.
8. The black "검색 인덱스 관리" button must use the same visual color treatment as the other settings buttons.
9. Earlier sub-agent findings must be addressed during implementation: ANN artifact deletion must not delete broad userData files, and status/log payloads must not leak raw absolute paths.

## Current Code Analysis

- `src/renderer/settings.html` contains `indexing-rebuild-btn`, `indexing-cancel-btn`, `indexing-retry-btn`, `indexing-compact-btn`, `indexing-open-dir-btn`, and `indexing-clear-btn`.
- `src/renderer/settings.js` refreshes indexing status every 3000 ms globally. Action execution calls `renderIndexingStatus()` once after the IPC returns, then falls back to the global interval.
- `src/renderer/settings.js` currently enables cancel when any worker state is active: `indexingCancelBtn.disabled = busy || !active || nativeRepairActive`.
- `src/renderer/settings.css` makes `.indexing-manage-button` black via `background: #24292e; color: #ffffff; border: 1px solid #24292e;`.
- `src/main/preload.js` exposes `clearSearchIndex`, and `src/main/index.js` registers `indexing:clear`.
- `src/main/search-index-worker.js` posts worker status every 250 ms, so the backend can support live updates.
- `src/main/search-engine.js` rebuild updates `phase` and `currentPath`, but `getStatus()` reports `indexedCount: this.docMeta.size`, so old committed document count remains visible during active rebuild.
- `SearchEngine.getStatus()` returns raw `currentPath`, `indexPath`, and `dataDir`; this conflicts with `SEC-DOC-003` and the earlier review.
- Startup reconciliation in `SearchEngine.reconcileStartupIndexJobs*()` resumes document indexing jobs by reading `currentPathInternal` as a file. It does not correctly resume durable `keyword_rebuild` jobs because those jobs point to a source root or index data path, not one Markdown file.
- Existing tests in `test/test-settings-indexing-contract.js` currently assert that clear UI/API exists, so they must be updated after the SRS gate.
