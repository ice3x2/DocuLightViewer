# Step 24 기술 결정 기록 (ADR)

## ADR-24-001: git 수집 위치 — index.js vs MCP 서버

**상황**: `mcp-server.mjs` (stdio)는 별도 프로세스로 실행되어 `electron-store`에 직접 접근 불가

**결정**:
- **stdio 경로**: `mcp-server.mjs` → IPC로 `projectPath` 전달 → `index.js`에서 git 수집 + 설정 확인
- **HTTP 경로**: `mcp-http.mjs`는 Electron 메인 프로세스 내 → 직접 `store.get()` + `collectGitInfo()` 호출

**근거**: 기존 아키텍처(stdio=별도 프로세스, HTTP=메인 프로세스)를 변경하지 않고 각 경로에 최적화

**영향**: Phase 3에서 양쪽 서버의 git 수집 위치가 다름. 최종 결과는 동일

## ADR-24-002: execFile vs execSync

**결정**: `child_process.execFile` (비동기)

**근거**: `execSync` 사용 시 최악 5초간 Electron 메인 스레드 블로킹 → UI 프리즈. `Promise.all` 병렬 실행으로 4개 명령을 5초 이내에 완료

---

## ADR-24-003: Promise.all vs Promise.allSettled

**결정**: `Promise.all`

**근거**: `execGit` 헬퍼가 절대 reject하지 않고 항상 `resolve(null)` 또는 `resolve(string)`을 반환하므로 `Promise.all`로 충분. `Promise.allSettled`의 `{status, value/reason}` 래핑이 불필요한 복잡성

## ADR-24-004: remote URL credential sanitization 방식

**결정**: `url.replace(/\/\/[^@]+@/, '//')`

**근거**:
- `https://user:pass@host` → `//`와 `@` 사이 제거 → `https://host`
- SSH `git@host:repo` → `//` 없으므로 매칭 안 됨 → 변환 없음
- `ssh://git@host` → 매칭됨, `ssh://host`로 변환 → URL로서 유효

**대안 검토**: `URL` 파싱 후 username/password 제거 — SSH URL은 `URL` 클래스로 파싱 불가하여 기각

---

## ADR-24-005: CJS import 방식 (ESM에서 CJS 모듈 사용)

**결정**: `mcp-http.mjs`에서 `await import('./git-info.js')` dynamic import 사용

**근거**:
- `git-info.js`는 CJS (`module.exports`)
- ESM에서 CJS를 import하면 `default` export로 래핑됨
- `const { collectGitInfo } = await import('./git-info.js')` 또는 default에서 추출
- 기존 `mcp-http.mjs`에서 `frontmatter.js`를 import하는 패턴이 있으면 그것을 따름
