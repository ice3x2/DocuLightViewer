## Phase 2: 프론트매터 확장 (`frontmatter.js`)

### 목표

`src/main/frontmatter.js`의 `injectFrontmatter` 함수 시그니처를 확장하여 git 관련 4개 필드(`projectPath`, `gitRemote`, `gitBranch`, `gitLastCommit`)를 수용한다.

### 선행 조건

- Phase 1 완료 (git-info.js 모듈이 반환하는 객체 구조 확정)

### 기존 코드 재사용 힌트

- `src/main/frontmatter.js:38` — 현재 `injectFrontmatter` 시그니처: `(content, { project, docName, description, docType })`
- `src/main/frontmatter.js:93` — `buildYamlBlock(fields)`: `Object.entries` 순회, truthy만 출력, 특수문자 자동 인용

### 구현 체크리스트

- [ ] Phase 2-1: `injectFrontmatter` 시그니처에 4개 파라미터 추가 `FR-24-003`
- [ ] Phase 2-2: `newFields` 객체에 git 필드를 올바른 순서로 삽입 `FR-24-003`

### 언어+버전 주의사항

- CJS 모듈 (`'use strict'`, `module.exports`)
- JavaScript destructuring으로 새 파라미터 추가 — 기존 호출 코드가 깨지지 않음 (undefined로 전달됨)

### LLM 코딩 주의사항

- **Simplicity**: `buildYamlBlock`는 수정하지 않음. 이미 truthy 필터링 + 특수문자 인용 기능이 있으므로 git 필드가 자동으로 처리됨
- **Surgical**: `injectFrontmatter` 함수의 destructure 리스트와 `newFields` 조립 부분만 수정. 다른 함수(`parseFrontmatter`, `parseSimpleYaml`, `buildYamlBlock`) 절대 수정 금지

### 상세 구현 명세

#### Phase 2-1: 시그니처 확장

**현재 코드** (`frontmatter.js:38`):
```javascript
function injectFrontmatter(content, { project, docName, description, docType }) {
```

**변경 후:**
```javascript
function injectFrontmatter(content, { project, docName, description, docType,
                                      projectPath, gitRemote, gitBranch, gitLastCommit }) {
```

#### Phase 2-2: `newFields` 조립 순서

**현재 코드** (약 line 42-50):
```javascript
const newFields = {};
if (project)     newFields.project = project;
if (docName)     newFields.docName = docName;
if (description) newFields.description = description;
// docType 처리...
```

**변경 후** — git 필드를 `project` 바로 뒤, `docName` 앞에 삽입:
```javascript
const newFields = {};
if (project)        newFields.project = project;
if (projectPath)    newFields.projectPath = projectPath;
if (gitRemote)      newFields.gitRemote = gitRemote;
if (gitBranch)      newFields.gitBranch = gitBranch;
if (gitLastCommit)  newFields.gitLastCommit = gitLastCommit;
if (docName)        newFields.docName = docName;
if (description)    newFields.description = description;
// docType 처리 (기존 로직 그대로)...
```

> `buildYamlBlock`는 `Object.entries(fields)` 삽입 순서대로 YAML을 출력하므로, 위 순서가 프론트매터의 필드 순서가 된다.

### 테스트 시나리오

#### 정상 케이스
- **Given**: `content = "# Hello"`, meta = `{ project: "MyApp", projectPath: "/work", gitBranch: "main" }`
- **When**: `injectFrontmatter(content, meta)` 호출
- **Then**: 결과 문자열이 `---\nproject: MyApp\nprojectPath: /work\ngitBranch: main\n...---\n# Hello` 형태

#### 예외 케이스
- **Given**: git 필드가 모두 undefined (기존 호출 패턴)
- **When**: `injectFrontmatter(content, { project: "X", docName: "Y" })` 호출
- **Then**: 기존과 동일한 결과 (git 필드 없음) — 하위 호환성 확인

#### 경계값 테스트
- **Given**: `gitLastCommit`에 YAML 특수문자 포함 (`"fix: update [config] & {data}"`)
- **When**: `injectFrontmatter(content, { gitLastCommit: "fix: update [config] & {data}" })` 호출
- **Then**: `buildYamlBlock`가 자동으로 인용부호 처리 → `gitLastCommit: "fix: update [config] & {data}"`
