## Phase 1: Git 정보 수집 모듈 (`git-info.js`)

### 목표

`src/main/git-info.js` CJS 모듈을 신규 생성한다. `collectGitInfo(projectPath)` 함수가 지정 경로에서 4개 git 명령을 병렬 실행하고, 실패/타임아웃 시 해당 필드만 graceful하게 생략한다.

### 언어+버전 주의사항

- Node.js (Electron 33.x, Node 20+): `child_process.execFile`은 콜백 기반 API. Promise 래핑 필요
- `const { execFile } = require('child_process')` — CJS require 사용 (ESM import 아님)
- `path.isAbsolute()`, `path.basename()` — Node.js path 모듈 사용

### LLM 코딩 주의사항

- **Simplicity**: `execGit`는 단순한 Promise 래퍼면 충분. `util.promisify`를 사용해도 되지만 에러 처리를 위해 수동 래핑이 더 명확
- **Surgical**: 이 파일은 신규 생성이므로 기존 코드 수정 없음. 다른 파일 수정 금지

### 상세 구현 명세

#### Phase 1-1: `execGit(args, cwd)`

```javascript
'use strict';
const { execFile } = require('child_process');
const path = require('path');

const GIT_TIMEOUT_MS = 5000;
const MAX_COMMIT_LENGTH = 200;

/**
 * git 명령을 실행하고 stdout을 반환한다.
 * 실패/타임아웃 시 null을 반환한다 (throw 없음).
 * @param {string[]} args - git 서브커맨드 + 인자 배열
 * @param {string} cwd - 작업 디렉토리 (절대 경로)
 * @returns {Promise<string|null>}
 */
function execGit(args, cwd) {
  return new Promise((resolve) => {
    execFile('git', args, { cwd, timeout: GIT_TIMEOUT_MS, windowsHide: true },
      (err, stdout) => {
        if (err) return resolve(null);
        const trimmed = stdout.trim();
        resolve(trimmed || null);  // 빈 문자열 → null
      });
  });
}
```

**핵심 설계:**
- `resolve(null)` — 절대 reject하지 않음. `Promise.all`이 하나의 실패로 전체 취소되지 않도록
- `stdout.trim()` — git 출력의 trailing newline 제거
- 빈 문자열 → `null` — detached HEAD에서 `branch --show-current`가 빈 문자열 반환하는 케이스

**실패 시나리오별 동작:**

| 시나리오 | `err` 값 | `stdout` | 반환값 |
|----------|----------|----------|--------|
| 정상 | null | `"main\n"` | `"main"` |
| git 미설치 | `ENOENT` | undefined | `null` |
| .git 없는 디렉토리 | `ExitCode 128` | undefined | `null` |
| 5초 타임아웃 | `ETIMEDOUT` / `killed` | undefined | `null` |
| detached HEAD (branch) | null | `"\n"` | `null` |
| origin 미설정 | `ExitCode 2` | undefined | `null` |
| 커밋 없는 빈 repo | `ExitCode 128` | undefined | `null` |
| cwd 존재하지 않음 | `ENOENT` (spawn) | undefined | `null` |

#### Phase 1-2: `sanitizeRemoteUrl(url)`

```javascript
/**
 * Remote URL에서 credential을 제거한다.
 * https://user:pass@host/... → https://host/...
 * https://token@host/... → https://host/...
 * git@host:... → 그대로 유지 (SSH는 credential 아님)
 * @param {string} url
 * @returns {string}
 */
function sanitizeRemoteUrl(url) {
  if (!url) return url;
  return url.replace(/\/\/[^@]+@/, '//');
}
```

**테스트 케이스:**

| 입력 | 출력 |
|------|------|
| `https://github.com/user/repo.git` | `https://github.com/user/repo.git` (변경 없음) |
| `https://user:pass@github.com/user/repo.git` | `https://github.com/user/repo.git` |
| `https://ghp_abc123@github.com/user/repo.git` | `https://github.com/user/repo.git` |
| `git@github.com:user/repo.git` | `git@github.com:user/repo.git` (SSH, 변경 없음) |
| `ssh://git@github.com/user/repo.git` | `ssh://github.com/user/repo.git` |

> **참고**: `ssh://git@host`의 경우 `git@`이 credential이 아닌 SSH 사용자명이지만, `//`와 `@` 사이에 있으므로 제거된다. 이는 의도된 동작으로, `ssh://github.com/...`로 변환되며 URL로서 여전히 유효하다.

#### Phase 1-3: `collectGitInfo(projectPath)`

```javascript
/**
 * projectPath에서 git 정보를 수집한다.
 * @param {string} projectPath - 프로젝트 디렉토리 절대 경로
 * @returns {Promise<object>} truthy 필드만 포함된 객체
 */
async function collectGitInfo(projectPath) {
  const result = { projectPath };

  // 디렉토리명을 기본 project로 설정
  result.project = path.basename(projectPath);

  // 4개 git 명령 병렬 실행
  const [remote, branch, lastCommit, repoRoot] = await Promise.all([
    execGit(['remote', 'get-url', 'origin'], projectPath),
    execGit(['branch', '--show-current'], projectPath),
    execGit(['log', '-1', '--format=%s'], projectPath),
    execGit(['rev-parse', '--show-toplevel'], projectPath),
  ]);

  // remote URL: credential 제거
  if (remote) {
    result.gitRemote = sanitizeRemoteUrl(remote);
  }

  // branch
  if (branch) {
    result.gitBranch = branch;
  }

  // last commit: 200자 truncation
  if (lastCommit) {
    result.gitLastCommit = lastCommit.length > MAX_COMMIT_LENGTH
      ? lastCommit.substring(0, MAX_COMMIT_LENGTH) + '\u2026'
      : lastCommit;
  }

  // repo root → project name (더 정확한 이름)
  if (repoRoot) {
    result.project = path.basename(repoRoot);
  }

  return result;
}

module.exports = { collectGitInfo };
```

**`Promise.all` 안전성:**

각 `execGit`는 **절대 reject하지 않으므로** `Promise.all`이 중간에 실패로 취소되지 않는다. 4개 명령이 각각 독립적으로 `null` 또는 `string`을 반환한다. 이것이 `Promise.allSettled`가 아닌 `Promise.all`을 사용할 수 있는 이유다.

### 테스트 시나리오

#### 정상 케이스
- **Given**: `projectPath`가 유효한 git 저장소 (remote, branch, commit 있음)
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: `{ project, projectPath, gitRemote, gitBranch, gitLastCommit }` 5개 필드 모두 반환

#### 예외 케이스
- **Given**: `projectPath`가 `.git` 없는 일반 디렉토리
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: `{ project: "dirname", projectPath }` — git 필드 없음, 에러 없음

- **Given**: 시스템에 git이 설치되지 않음
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: 동일하게 `{ project, projectPath }` — ENOENT가 각 명령에서 catch됨

#### 경계값 테스트
- **Given**: 커밋 subject가 300자
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: `gitLastCommit`이 200자 + `…` (201자)

- **Given**: remote URL이 `https://user:token123@github.com/org/repo.git`
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: `gitRemote`가 `https://github.com/org/repo.git`

- **Given**: detached HEAD 상태 (branch --show-current → 빈 문자열)
- **When**: `collectGitInfo(projectPath)` 호출
- **Then**: `gitBranch` 필드 없음 (null → 생략)
