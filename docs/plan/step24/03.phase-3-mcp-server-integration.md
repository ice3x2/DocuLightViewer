## Phase 3: MCP 서버 통합 (stdio + HTTP)

### 목표

`mcp-server.mjs`와 `mcp-http.mjs` 양쪽에 `projectPath` 파라미터를 추가하고, 핸들러에서 `collectGitInfo`를 호출하여 프론트매터에 git 정보를 주입한다. `index.js` IPC 핸들러와 `window-manager.js`도 git 필드를 전달하도록 수정한다.

- Phase 2 완료 (`frontmatter.js` 확장)

### 언어+버전 주의사항

- `mcp-server.mjs`는 ESM (`.mjs`): `import` 사용, `require` 불가
  - `git-info.js`는 CJS → ESM에서 import 시 `import { collectGitInfo } from './git-info.js'` 또는 `const { collectGitInfo } = await import('./git-info.js')` 사용
  - **권장**: `createRequire`를 이미 사용 중이면 그 패턴 따르기. 아니면 dynamic import
- `mcp-http.mjs`도 ESM: 동일 패턴
- `index.js`는 CJS: `require('./git-info.js')` 직접 사용 가능
- `window-manager.js`는 CJS

### LLM 코딩 주의사항

- **Simplicity**: git 수집 로직은 양쪽 서버에서 동일. 공유 함수를 만들지 않고 인라인으로 각각 구현 (파일 간 결합도 최소화)
- **Surgical**: 프론트매터 인젝션 가드 조건만 수정. 기존 파라미터 처리 로직 수정 금지. IPC 프로토콜 변경 없음

#### Phase 3-2: `mcp-server.mjs` 핸들러 수정 (stdio 경로)

> **핵심 설계**: `mcp-server.mjs`는 별도 프로세스로 실행되어 `electron-store`에 접근 불가.
> 따라서 **git 수집 + 프론트매터 주입은 `index.js` IPC 핸들러에서 수행**한다.
> `mcp-server.mjs`는 `projectPath`를 IPC에 전달만 한다.

**변경 1: 기존 프론트매터 인젝션 가드에서 `projectPath` 제외 (이중 주입 방지)**

`projectPath`가 있으면 프론트매터 주입을 `index.js`에서 수행하므로, `mcp-server.mjs`에서는 `projectPath`가 있을 때 기존 프론트매터 인젝션을 **스킵**해야 한다.

**open_markdown 핸들러** (line ~390-392):
```javascript
// 기존:
if (content && (project || docName || description || docType)) {
  content = injectFrontmatter(content, { project, docName, description, docType });
}

// 변경: projectPath가 있으면 index.js에서 처리하므로 여기서 스킵
if (content && !projectPath && (project || docName || description || docType)) {
  content = injectFrontmatter(content, { project, docName, description, docType });
}
```

**update_markdown 핸들러** (line ~470-471):
```javascript
// 기존:
if (content && !appendMode && (project || docName || description || docType)) {
  content = injectFrontmatter(content, { project, docName, description, docType });
}

// 변경: 동일하게 projectPath 있으면 스킵

```

> **이중 주입 방지 원칙**: `projectPath`가 있으면 `index.js`가 git 수집 + 모든 메타 병합 + 프론트매터 주입을 일괄 수행. `projectPath`가 없으면 기존대로 `mcp-server.mjs`에서 주입.

#### Phase 3-4: `mcp-http.mjs` 핸들러 수정 (HTTP 경로)

**`mcp-http.mjs`는 Electron 메인 프로세스 내에서 실행**되므로 `store`에 직접 접근 가능하고, `windowManager`도 직접 호출한다. git 수집 + 프론트매터 주입을 여기서 수행한다.

**open_markdown 핸들러** (line ~127):

// 기존 destructure에 projectPath 추가:
async open_markdown({ content, filePath, title, foreground, alwaysOnTop, size,
                      windowName, severity, tags, progress, noSave,
                      project, docName, description, docType,
                      projectPath }) {  // ← 추가

  // --- git 정보 수집 ---
  const pathMod = require('path');
  let gitInfo = {};
  if (projectPath && pathMod.isAbsolute(projectPath)) {
    const mcpGitInfo = store.get('mcpGitInfo', true);
    if (mcpGitInfo) {
      const { collectGitInfo } = require('./git-info');
      gitInfo = await collectGitInfo(projectPath);
    } else {
      gitInfo = { projectPath };
    }

  // project 우선순위: 명시적 > git 유래

  } else if (gitInfo.project) {
    project = gitInfo.project;
  }

  // 기존 frontmatter 인젝션 가드 수정
  if (content && (project || docName || description || docType || gitInfo.projectPath)) {
    content = injectFrontmatter(content, {
      project, docName, description, docType,
      ...gitInfo  // projectPath, gitRemote, gitBranch, gitLastCommit

#### Phase 3-6: `index.js` IPC 핸들러

**open_markdown case** (line ~609):

```javascript
case 'open_markdown': {
  // --- git 정보 수집 (index.js에서 수행) ---
  let gitInfo = {};
  const { projectPath } = params;
  if (projectPath && path.isAbsolute(projectPath)) {
    const mcpGitInfo = store.get('mcpGitInfo', true);
    if (mcpGitInfo) {
      const { collectGitInfo } = require('./git-info');
      gitInfo = await collectGitInfo(projectPath);
    } else {
      gitInfo = { projectPath };
    }
  }

  // project 우선순위
  if (params.project) {
    gitInfo.project = params.project;
  } else if (gitInfo.project) {
    params.project = gitInfo.project;
  }

  // content에 frontmatter 주입 (mcp-server.mjs 경유 시)
  if (params.content && (params.project || params.docName || params.description || params.docType || gitInfo.projectPath)) {
    params.content = injectFrontmatter(params.content, {
      project: params.project, docName: params.docName,
      description: params.description, docType: params.docType,
      ...gitInfo
    });
  }

  // 기존: windowManager.createWindow(params)에 git 필드도 전달
  const result = await windowManager.createWindow({ ...params, ...gitInfo });
  // ...
}
```

> **참고**: `mcp-server.mjs` 경유 시에는 `index.js`에서 frontmatter를 주입하고, `mcp-http.mjs`는 직접 주입한다. 이는 기존 아키텍처(IPC vs 직접 호출)의 차이에 의한 것이며, 최종 결과는 동일하다.

### 테스트 시나리오

#### 정상 케이스
- **Given**: DocuLight 실행 중, `mcpGitInfo: true`, 유효한 git repo
- **When**: stdio MCP `open_markdown({ content: "# Test", projectPath: "C:/Work/proj" })` 호출
- **Then**: 뷰어에 표시된 문서의 프론트매터에 git 필드 포함

#### 예외 케이스
- **Given**: `appendMode: true`
- **When**: `update_markdown({ windowId: "...", content: "추가", appendMode: true, projectPath: "..." })` 호출
- **Then**: 프론트매터 미주입. content가 기존 내용에 이어붙기됨

#### 경계값 테스트
- **Given**: HTTP MCP와 stdio MCP 동시 호출 (다른 projectPath)
- **When**: 양쪽에서 거의 동시에 open_markdown 호출
- **Then**: 각각 독립적으로 git 수집 후 프론트매터 주입. 간섭 없음
