# Installed And Dev Profile Concurrency Plan

> For agentic workers: implement this plan with TDD. Write or update the failing contract test first, then make the smallest runtime-profile change that passes it. Keep packaged/default behavior compatible unless an OPS-ARCH-012 acceptance criterion explicitly says otherwise.

## Goal

설치형으로 이미 실행 중인 DocuLight Viewer와 같은 소스 트리의 `npm run dev` 개발 인스턴스를 동시에 실행할 수 있게 한다. 핵심 설계는 packaged/default profile은 기존 동작을 유지하고, `npm run dev`만 development profile로 분리하는 것이다.

## Requirement Scope

| Requirement | Role |
| --- | --- |
| `OPS-ARCH-012` | Primary requirement: dev profile can run beside installed DocuLight without shared runtime state |
| `OPS-ARCH-011` | Related: `npm run dev` must run Electron native rebuild once before launch |
| `OPS-ARCH-010` | Related: native dependency packaging and rebuild lifecycle must remain intact |
| `IR-MCP-018` | Related: strict MCP save/search tool contract must not gain indexing/runtime controls |
| `CON-MCP-010` | Related: MCP client-profile conformance and default compatibility |

`OPS-ARCH-012` is currently `Status=planned`, `Stability=evolving`, `Target=0.11.0-w2`, `Verification Method=test+package-smoke`.

## User Requirements Understood

1. 설치되어 실행 중인 DocuLight Viewer를 끄지 않고도 `npm run dev`를 실행할 수 있어야 한다.
2. 단순히 runtime-free check를 제거하는 방식은 허용하지 않는다. 개발 인스턴스는 userData, IPC, MCP discovery, search index, native status를 설치형과 공유하지 않아야 한다.
3. packaged/default 실행과 `npm run start`는 기존 기본 동작을 유지해야 한다.
4. MCP stdio 클라이언트는 기본값으로 기존 packaged instance에 붙고, dev instance는 명시적으로 선택할 수 있어야 한다.
5. `npm run dev`는 Electron native rebuild를 한 번 자동 실행한 뒤 dev profile로 Electron을 시작해야 한다.

## Five-Agent Research Summary

| Research Axis | Key Finding | Planning Decision |
| --- | --- | --- |
| Electron profile / userData / single instance | `Store`, `SearchEngine`, native rebuild manager가 profile 설정 전 `app.getPath('userData')`를 사용한다. | runtime profile을 `new Store()`와 `requestSingleInstanceLock()`보다 먼저 적용한다. |
| IPC / MCP endpoint / discovery | main IPC, preflight, stdio MCP가 서로 다른 env 규칙을 쓰며 기본 pipe가 고정되어 있다. | 하나의 profile resolver에서 app/preflight/MCP pipe를 파생한다. |
| Persistence / data safety | `config.json`, `index/search-index.sqlite3`, `index/smart-search.sqlite3`, `index/hnsw`, `native-rebuild`, `mcp-port`가 모두 userData 기반이다. | dev userData를 별도 디렉터리로 바꿔 파생 데이터 전체를 분리한다. |
| npm scripts / Windows UX | `predev`와 `dev`가 별도 npm lifecycle이라 profile env 전달이 취약하고 Windows inline env 문법이 다르다. | `dev`를 Node launcher로 전환해 preflight, rebuild, Electron launch를 한 프로세스 흐름에서 실행한다. |
| TDD / verification | 기존 `test/test-sqlite-native-packaging-contract.js`가 "dev도 일반 single-instance lock"을 고정한다. | 이 계약 테스트를 RED 지점으로 바꾸고 신규 runtime isolation contract를 추가한다. |

## Current Collision Points

- `package.json`:
  - `predev` is `npm run check:runtime-free && npm run rebuild:native:electron`.
  - `dev` is `electron . --dev`.
  - This checks the default packaged pipe before dev can choose a profile.
- `scripts/check-doculight-runtime-free.js`:
  - Uses default `\\.\pipe\doculight-ipc` or `/tmp/doculight-ipc.sock`.
  - It supports `DOCULIGHT_IPC_PATH`, but there is no shared profile resolver.
- `src/main/index.js`:
  - `PIPE_PATH` is fixed at module scope.
  - `Store`, `SearchEngine`, and `nativeRebuildManager` are created before any dev profile path is applied.
  - `SearchEngine` uses `path.join(app.getPath('userData'), 'index')`.
  - native rebuild status uses `path.join(app.getPath('userData'), 'native-rebuild')`.
  - `app.requestSingleInstanceLock()` is called without profile scope.
  - `app.setAppUserModelId('com.doculight.app')` is fixed.
  - MCP HTTP port discovery file is deleted from `app.getPath('userData')/mcp-port`.
- `src/main/mcp-http.mjs`:
  - Base port is `store.get('mcpPort') || 32580`.
  - Discovery file is `{userData}/mcp-port`; this is safe only after userData is profile-specific.
- `src/main/mcp-server.mjs`:
  - Default stdio bridge pipe is fixed, with only `DOCULIGHT_MCP_IPC_PATH` override.
  - A dev profile must not accidentally auto-launch the installed packaged app.
- Tests:
  - `test/test-sqlite-native-packaging-contract.js` currently asserts the old dev/start script and single-instance policy.

## Target Architecture

### Runtime Profile Resolver

Add a small CommonJS module, recommended path:

- `src/main/runtime-profile.js`

The module must not import `electron`. It should accept `argv`, `env`, `platform`, and path inputs so it can be used by:

- Electron main process
- `scripts/check-doculight-runtime-free.js`
- `scripts/run-dev.js`
- `src/main/mcp-server.mjs` through `createRequire`
- tests

Recommended exported functions:

- `resolveRuntimeProfile(options)`
- `resolveProfileName(options)`
- `resolveIpcPath(options)`
- `normalizeProfileName(value)`
- `buildProfileEnv(profile)`

### Profile Defaults

| Field | Default / Packaged Profile | Dev Profile |
| --- | --- | --- |
| profile name | `default` | `dev` |
| selection | no env, no `--dev`, no `--profile=dev` | `npm run dev`, `--dev`, `--profile=dev`, or `DOCULIGHT_PROFILE=dev` |
| app name | existing default | `DocuLight Dev` |
| Windows AppUserModelID | `com.doculight.app` | `com.doculight.app.dev` |
| userData | Electron default | `<appData>/DocuLight-dev` or equivalent suffix path |
| sessionData | Electron default | `<dev userData>/session` |
| main IPC pipe | `\\.\pipe\doculight-ipc` | `\\.\pipe\doculight-ipc-dev` |
| Unix IPC socket | `/tmp/doculight-ipc.sock` | `/tmp/doculight-ipc-dev.sock` |
| MCP HTTP base port | 32580 | 32581 |
| MCP port file | `<default userData>/mcp-port` | `<dev userData>/mcp-port` |
| search index dir | `<default userData>/index` | `<dev userData>/index` |
| native rebuild status | `<default userData>/native-rebuild` | `<dev userData>/native-rebuild` |

Use a suffix path, not a case-only path difference. Windows and macOS are commonly case-insensitive.

### Environment Precedence

App and preflight IPC:

1. For `default` profile, legacy `DOCULIGHT_IPC_PATH` remains a supported explicit override.
2. For `dev` profile launched by `npm run dev`, use the profile-derived dev IPC path by default and ignore ambient `DOCULIGHT_IPC_PATH`.
3. Allow a dev IPC override only through a deliberately dev-scoped mechanism, for example `DOCULIGHT_DEV_IPC_PATH` or `--ipc-path`, so stale shell environment cannot accidentally point dev at the packaged pipe.

MCP stdio IPC:

1. `DOCULIGHT_MCP_IPC_PATH`
2. `DOCULIGHT_MCP_PROFILE`
3. `DOCULIGHT_PROFILE`
4. legacy `DOCULIGHT_IPC_PATH` only when no MCP/runtime profile was explicitly selected
5. default profile-derived IPC path

MCP default must remain packaged-compatible. A dev MCP client should opt in with either:

```powershell
$env:DOCULIGHT_MCP_PROFILE = 'dev'
npm run mcp
```

or:

```powershell
$env:DOCULIGHT_MCP_IPC_PATH = '\\.\pipe\doculight-ipc-dev'
npm run mcp
```

### Dev Launcher

Replace the split `predev` + `dev` lifecycle with a single Node launcher:

- Add `scripts/run-dev.js`.
- Change `package.json` `dev` to `node scripts/run-dev.js`.
- Remove `predev` or make it unused to avoid duplicate rebuild.
- Keep `check:runtime-free` and `rebuild:native:electron` as direct scripts.

Launcher flow:

1. Resolve `profile=dev`.
2. Run `scripts/check-doculight-runtime-free.js --profile=dev` with profile env.
3. Run `scripts/rebuild-electron-native.js` once with `DOCULIGHT_NATIVE_REBUILD_STATUS_FILE=<dev userData>/native-rebuild/native-rebuild-status.json`.
4. Spawn the local Electron executable from `require('electron')`, not a shell command named `electron`.
5. Pass `--dev --profile=dev` and profile env into Electron.
6. Forward additional user argv after the launcher-owned flags so existing flows such as `npm run dev -- locale ja` continue to work.

This avoids Windows `VAR=value command` incompatibility and avoids the previous `'electron' is not recognized` failure mode when a shell cannot resolve the binary.

### Main Process Wiring

In `src/main/index.js`, apply profile before any code reads `app.getPath('userData')` for runtime state:

1. Import the resolver.
2. Resolve runtime profile from `process.argv` and `process.env`.
3. If dev profile:
   - create `profile.userDataDir`;
   - call `app.setName(profile.appName)`;
   - call `app.setPath('userData', profile.userDataDir)`;
   - call `app.setPath('sessionData', profile.sessionDataDir)`.
4. Create `Store` with profile-sensitive `mcpPort` default.
5. Create `SearchEngine` with `profile.indexDataDir`.
6. Create native rebuild manager with `profile.nativeRebuildStatusDir`.
7. Call `requestSingleInstanceLock()` after userData is profile-specific.
8. On `ready`, call `app.setAppUserModelId(profile.appUserModelId)`.
9. Use `profile.ipcPath` for stale socket cleanup and IPC server listen.
10. Delete only `profile.mcpPortFilePath` on quit.

Do not bypass single-instance globally. Verify whether early `app.setPath('userData')` scopes Electron's process singleton on Windows/macOS/Linux. If any platform still collides packaged+dev, add a profile-specific lock helper for dev while preserving default packaged `requestSingleInstanceLock()` behavior.

### Persistence Safety

Profile isolation must cover these paths:

- `config.json` from electron-store
- `index/search-index.sqlite3`
- `index/smart-search.sqlite3`
- `index/hnsw/*`
- `native-rebuild/native-rebuild-status.json`
- `mcp-port`
- main IPC socket/pipe

If a user explicitly configures dev to save documents into the same `mcpAutoSavePath` as packaged, source Markdown files can still be shared by user choice. OPS-ARCH-012 requires runtime and derived index isolation; it should not silently delete or rewrite packaged runtime state.

### MCP Behavior

- Do not add MCP indexing/runtime controls.
- Keep the exact eight-tool contract from `IR-MCP-018` and `CON-MCP-010`.
- Regenerate `src/main/mcp-server.bundle.mjs` after changing `src/main/mcp-server.mjs`.
- Default stdio MCP remains packaged/default.
- Dev stdio MCP must be explicit. If dev profile is requested and dev app is not running, return a clear connection error or documented instruction. Do not launch the installed packaged app for a dev-profile MCP request.

### File Association Guard

Dev profile should not register or overwrite OS file associations. If the Settings UI exposes file association in dev profile, disable it or make the main-process handler reject registration with a profile-aware reason. Packaged/default behavior remains unchanged.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Profile applied too late | Add tests that inspect source order/contract and runtime resolver usage before `new Store()`. |
| Electron singleton is not scoped by changed userData on a platform | Verify in smoke; if needed, add profile-specific lock fallback for dev while leaving packaged default lock untouched. |
| Windows npm env syntax breaks launcher | Use a Node launcher with `spawn(..., { env, shell: false })`; avoid inline `VAR=value`. |
| MCP default compatibility breaks | Test no-env stdio default pipe and eight-tool schema parity. |
| Bundle drift | Run `npm run bundle:mcp` and contract tests after `mcp-server.mjs` changes. |
| Dev file association overwrites packaged association | Disable or reject file association registration when `profile=dev`. |
| User selects the same document store path in dev and packaged | Keep derived runtime/index state isolated; do not promise source Markdown isolation when user explicitly chooses a shared save root. |
| Native rebuild mutates local `node_modules` ABI | Keep one rebuild per `npm run dev`; avoid running Node-side tests in parallel with Electron rebuild. |
