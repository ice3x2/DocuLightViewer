## 언어+버전 주의사항

- **Electron 33 + Node 20** — HTML 수정 후 창 새로고침(Ctrl+R)만으로 반영, 재빌드 불필요
- **CSP 제약** — 인라인 SVG는 허용되지만 인라인 `<script>`는 금지. `onclick` 속성 사용 금지 (Phase 2에서 `addEventListener`로 바인딩)
- **locales JSON 인코딩** — UTF-8 without BOM 유지. JSON comments 금지(JSON5 아님).
- **`disabled` 속성** — HTML5에서 boolean 속성. 값 없이 단순 존재만으로 비활성. Phase 2에서 `btn.disabled = true/false` 프로퍼티로 제어.

---

## LLM 코딩 주의사항

1. **Simplicity**: 별도 CSS 파일 분리 금지, `viewer.css` 내부에 추가. 공통 클래스 도입 여부는 기존 패턴에 맞춰 판단(현재는 ID 셀렉터 반복 방식이므로 그 패턴 유지 가능).
2. **Surgical**: `#sidebar-header` 내 기존 버튼 마크업을 건드리지 않는다. 신규 두 버튼만 추가.
3. **Goal-Driven**: Phase 1 끝난 시점에도 버튼은 disabled. 기능 동작은 Phase 2 구현 후에만 가능해야 한다. Phase 1에서 임의로 JS 바인딩 추가 금지.
4. **i18n 4파일 동시 업데이트** — 한 파일만 수정하고 끝내지 말 것. 누락 시 해당 로케일에서 키 이름이 그대로 노출됨.

## 테스트 시나리오

### 정상 케이스

- **Given**: 앱이 부팅되어 사이드바가 열린다.
  **When**: 사용자가 사이드바 헤더를 본다.
  **Then**: `[🏷️][🔍][접기][펼치기]` 순서로 4개 버튼이 표시되고, 접기/펼치기 버튼은 disabled 상태(회색)다.

- **Given**: 사용자가 OS 언어를 ja로 설정하거나 `npm run dev -- locale ja` 실행.
  **When**: 버튼에 마우스를 올린다.
  **Then**: 툴팁이 "すべてのディレクトリを折りたたむ" 등 일본어로 표시된다.

### 예외 케이스

- **Given**: `src/locales/es.json`에 `sidebar.collapseAll` 키가 누락된 상태.
  **When**: 로케일 es로 앱을 실행한다.
  **Then**: 버튼에 fallback 텍스트(영어 또는 키 이름)가 표시되지만 앱 크래시 없음.

### 경계값

- **Given**: 사이드바 너비가 최소값(200px 등)으로 축소된 상태.
  **When**: 버튼이 렌더된다.
  **Then**: 버튼이 줄바꿈 없이 한 줄에 표시되고 Navigation 레이블이 필요 시 `text-overflow: ellipsis`로 처리된다 (기존 동작 유지).
