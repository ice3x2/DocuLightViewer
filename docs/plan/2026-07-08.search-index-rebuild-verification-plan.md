# Search Index Rebuild Verification Plan

## Purpose

Settings의 `Rebuild search index` 기능이 검색 계약을 깨지 않고 정상 동작하는지 테스트로 검증한다. 검증 대상은 Settings 전용 rebuild 제어, 검색 시점 long rebuild 금지, worker 격리 rebuild, SQLite committed generation 보호, stale index 명시 상태, MCP indexing control 비노출이다.

## Requirement Scope

| Requirement | Scope | Verification Focus |
| --- | --- | --- |
| `IR-APP-010` | Settings IPC owns indexing status and control actions | Settings UI/preload/main IPC가 rebuild/status/cancel 등을 제공하고 MCP tools에는 노출하지 않는다. |
| `FR-DOC-018` | Keyword index lifecycle avoids search-time long rebuilds | 검색 호출은 rebuild를 직접 시작하지 않고 committed/stale/degraded 상태로 응답한다. |
| `REL-DOC-007` | Search index maintenance runs in an isolated worker runtime | Settings rebuild는 worker/controller 경계에서 실행되고 cancel/status 응답성을 유지한다. |

## Verification Strategy

### Tier A: Focused Local Contract Check

빠르게 기능 계약을 확인하는 기본 경로다. 문서나 코드 수정 없이 현재 구현이 rebuild 기능 계약을 만족하는지 확인한다.

1. Settings indexing control 계약 확인
   - Command: `node test/test-settings-indexing-contract.js`
   - Expected:
     - `getIndexingStatus`, `startIndexingRebuild`, `cancelIndexingJob`, `retryIndexingFailures`, `compactSearchIndex`, `clearSearchIndex`, `openIndexDataDir` preload API 존재
     - `indexing:start-rebuild` IPC channel 존재
     - Settings에 rebuild, cancel, retry failed, compact, clear, open data directory 버튼과 상태/진단 표시 존재
     - compact와 clear는 확인 대화상자와 backup/recovery 안내를 요구
     - HTTP 및 stdio MCP tools/list에 indexing control tool이 없음

2. SearchEngine lifecycle 계약 확인
   - Command: `node test/test-search-engine-lifecycle.js`
   - Expected:
     - startup에서 full rebuild를 자동 실행하지 않음
     - rebuild 성공 후 상태가 `ready`
     - save/read/partial failure 시 마지막 committed index 보존
     - dirty 상태 검색이 `rebuild()`를 직접 호출하지 않음
     - `search_documents`/`search_projects` 호환 envelope, project/docType filter, simple-token degraded fallback 계약이 유지됨

3. SQLite keyword index 계약 확인
   - Command: `node test/test-sqlite-keyword-index-contract.js`
   - Expected:
     - explicit rebuild 후 SQLite FTS5 index가 생성되고 검색 가능
     - empty/root/tokenizer metadata mismatch는 `stale`로 표시되고 자동 rebuild하지 않음
     - explicit rebuild 후 현재 source root 문서가 검색 가능
     - legacy JSON index를 document root 아래에 쓰지 않음

4. Worker rebuild 계약 확인
   - Command: `node test/test-search-index-worker-contract.js`
   - Expected:
     - `startRebuild()`가 main process `rebuild()` 직접 호출이 아니라 worker/controller job을 enqueue
     - worker 상태에 phase/progress/currentPath/heartbeatAt/cancelRequested/diagnostic 포함
     - scan/read/tokenize/insert/embedding/HNSW/commit safe checkpoint에서 cancel 확인
     - cancel 전/중 failure가 이전 committed generation을 보존
     - compact/VACUUM 및 clear가 worker boundary와 backup/checkpoint 정책을 통과
     - semantic embedding과 HNSW build/compact가 worker-local provider/service 경로로 실행
     - smart_search request path가 즉석 HNSW rebuild를 수행하지 않음

### Tier B: Responsiveness and Benchmark Check

긴 rebuild에서 UI/MCP 응답성이 유지되는지 확인한다. 로컬 시간이 더 걸릴 수 있으므로 Tier A 통과 후 실행한다.

1. Worker benchmark contract
   - Command: `node test/test-search-index-worker-benchmark-contract.js`
   - Expected:
     - status/cancel latency p95 <= 1000ms
     - status/cancel latency p99 <= 3000ms
     - status/cancel latency max <= 5000ms
     - main-process heartbeat max gap <= 2000ms
     - generated temp corpus와 160 MiB급 sparse Markdown fixture에서 bounded tokenizer evidence 기록
     - rebuild/compact/clear backup은 SQLite backup API, WAL checkpoint 후 DB/WAL/SHM capture, 또는 redacted backup-skip manifest로 증명됨
     - worker native load/degraded state와 semantic/HNSW worker evidence가 기록됨
     - source root 아래에 index artifact를 만들지 않음

2. Focused benchmark script, if deeper evidence is required
   - Command: `npm run bench:search-index-worker`
   - Expected:
     - corpus size, max file size, phase wall time, peak memory, DB/WAL/SHM size, worker native load/degraded state가 artifact로 남음

### Tier C: Package Smoke Check

패키징된 Electron 런타임까지 검증해야 할 때 실행한다. 비용이 큰 검증이므로 release gate 또는 regression 의심 시 사용한다.

1. Build packaged app
   - Command: `npm run build:win`
   - Expected:
     - MCP bundle 생성
     - packaged native repair 실행
     - local Node ABI native rebuild 복구

2. Package smoke
   - Command: `npm run smoke:package`
   - Expected:
     - packaged worker 안에서 `better-sqlite3` native load 성공
     - optional `hnswlib-node`는 load 성공 또는 `native_unavailable` degraded 상태로 보고
     - real `search-index-worker.js` document indexing job이 completed/documentIndexed evidence를 남김
     - save-to-search marker가 `search_documents`와 `smart_search`로 검색됨

## Execution Order

1. Run Tier A commands in order.
2. If Tier A passes, run Tier B benchmark contract.
3. Run Tier C only when packaged-runtime evidence is required.
4. Capture command exit codes and the final “all assertions passed” lines.
5. If any command fails, stop and classify the failure by requirement:
   - `IR-APP-010`: Settings IPC/UI or MCP exposure regression
   - `FR-DOC-018`: search-time rebuild or committed index lifecycle regression
   - `REL-DOC-007`: worker isolation, responsiveness, cancel, generation, package native regression

## Risk Notes

- Tier B and Tier C can be slower than ordinary unit tests because they exercise large-corpus and packaged-runtime behavior.
- `npm run build:win` mutates packaged artifacts under `dist/` and can trigger native rebuild steps; run it only when full release-grade evidence is needed.
- Existing working tree changes are not part of this plan and must not be reverted during verification.
