# Phase 1: Core - frontmatter + MCP Schema + IPC

## Objective

docType 파라미터가 MCP 입력부터 frontmatter 주입, IPC 전파, 윈도우 메타 저장까지 전체 파이프라인을 관통하도록 한다.

## Implementation Checklist

### 1.1 frontmatter.js — DOC_TYPES 상수 + injectFrontmatter 확장

**파일**: `src/main/frontmatter.js`

```javascript
// 추가할 상수 (module.exports에 포함)
const DOC_TYPES = {
  note:       { icon: '📝', labelKey: 'docType.note' },
  plan:       { icon: '📋', labelKey: 'docType.plan' },
  report:     { icon: '📊', labelKey: 'docType.report' },
  completion: { icon: '✅', labelKey: 'docType.completion' },
  issue:      { icon: '🐛', labelKey: 'docType.issue' },
  review:     { icon: '🔍', labelKey: 'docType.review' },
  log:        { icon: '📜', labelKey: 'docType.log' },
  reference:  { icon: '📖', labelKey: 'docType.reference' },
  guide:      { icon: '📘', labelKey: 'docType.guide' },
  spec:       { icon: '📐', labelKey: 'docType.spec' },
};

const DOC_TYPE_VALUES = Object.keys(DOC_TYPES);
```

**변경 사항**:
- `injectFrontmatter(content, { project, docName, description, docType })` — 파라미터에 `docType` 추가
- `docType`이 유효한 값이면 `newFields.docType = docType` 설정
- `docType`이 없거나 무효하면 `newFields.docType = 'note'` (기본값)
- **단, frontmatter 주입 자체가 트리거되려면 기존 조건(`project || docName || description`)에 `docType`도 추가해야 함**
- `module.exports`에 `DOC_TYPES`, `DOC_TYPE_VALUES` 추가

**기존 패턴 재사용**:
- `newFields` 객체에 필드 추가하는 기존 패턴 그대로 따름
- `buildYamlBlock`은 Object.entries 순회하므로 변경 불필요

### 1.2 mcp-server.mjs — Zod 스키마 + 핸들러

**파일**: `src/main/mcp-server.mjs`

**open_markdown**:
- Zod 스키마에 `docType: z.enum([...DOC_TYPE_VALUES]).optional().describe('Document type classification')` 추가
- 핸들러에서 `docType` 추출, `injectFrontmatter` 호출에 전달
- `sendIpcRequest` 호출에 `docType` 포함
- frontmatter 주입 조건: `if (content && (project || docName || description || docType))` 로 확장

**update_markdown**:
- 동일한 Zod 스키마 추가
- 핸들러에서 `docType` 추출, `injectFrontmatter` 호출에 전달
- `sendIpcRequest` 호출에 `docType` 포함

**주의**: `DOC_TYPE_VALUES`는 ESM 파일에서 CJS 모듈 import 필요.
기존 패턴: `import { createRequire } from 'node:module'; const require = createRequire(import.meta.url);` 로 이미 frontmatter.js를 require하고 있음.

### 1.3 mcp-http.mjs — JSON Schema + 핸들러

**파일**: `src/main/mcp-http.mjs`

**TOOLS 배열 (open_markdown, update_markdown)**:
- `inputSchema.properties`에 `docType` 추가:
  ```json
  "docType": {
    "type": "string",
    "enum": ["note","plan","report","completion","issue","review","log","reference","guide","spec"],
    "description": "Document type classification (default: note)"
  }
  ```

**createToolHandlers 내부**:
- `open_markdown` 핸들러: `args` 디스트럭처링에 `docType` 추가, `injectFrontmatter` 호출에 전달, `wm.createWindow`에 전달
- `update_markdown` 핸들러: 동일

### 1.4 window-manager.js — createWindow / updateWindow

**파일**: `src/main/window-manager.js`

**createWindow(opts)**:
- 디스트럭처링에 `docType` 추가
- `pendingReady.set()`의 데이터에 `docType` 포함
- `this.windows[windowId].meta`에 `docType` 저장

**updateWindow(windowId, opts)**:
- 디스트럭처링에 `docType` 추가
- docType 변경 시 `meta.docType` 업데이트
- frontmatter 주입 조건에 `docType` 포함

**기존 패턴**: severity가 meta에 저장되고 createWindow/updateWindow에서 전파되는 패턴과 동일.

### 1.5 index.js — IPC 핸들러

**파일**: `src/main/index.js`

**`case 'open_markdown'`**:
- `params`에서 `docType` 추출
- `windowManager.createWindow()`에 `docType` 전달
- `saveMcpFile()` 호출에 `docType` 전달 (Phase 2에서 사용)

**`case 'update_markdown'`**:
- `params`에서 `docType` 추출
- `windowManager.updateWindow()`에 `docType` 전달
- `saveMcpFile()` 호출에 `docType` 전달

## Test Scenarios

### 정상 케이스

**TC-1-01**: open_markdown에 `docType: "plan"` 전달 → frontmatter에 `docType: plan` 포함 확인
```
Given: MCP open_markdown 호출 with { content: "# Test", docType: "plan", project: "P1" }
When: 뷰어 창이 열림
Then: frontmatter에 docType: plan 필드 존재
```

**TC-1-02**: open_markdown에 docType 미지정 → frontmatter에 `docType: note` 기본값
```
Given: MCP open_markdown 호출 with { content: "# Test", project: "P1" }
When: frontmatter가 주입됨
Then: docType 필드 값이 "note"
```

### 예외 케이스

**TC-1-03**: 잘못된 docType 값 → MCP 에러 반환
```
Given: MCP open_markdown 호출 with { content: "# Test", docType: "invalid" }
When: Zod/JSON Schema 검증
Then: 에러 반환 (enum 위반)
```

**TC-1-04**: docType만 지정하고 project/docName/description 미지정 → frontmatter 주입됨
```
Given: MCP open_markdown 호출 with { content: "# Test", docType: "issue" }
When: frontmatter 주입 조건 체크
Then: frontmatter에 docType: issue, date 필드 존재
```

### 경계값

**TC-1-05**: 기존 frontmatter가 있는 content에 docType 전달 → 머지
```
Given: content = "---\nproject: X\n---\n# Test", docType: "spec"
When: injectFrontmatter 호출
Then: frontmatter에 project: X, docType: spec 모두 존재
```
