# Phase 2: Save Path {type} Token + Search 확장

## Objective

mcpAutoSave 서브디렉토리 포맷에 `{type}` 토큰을 추가하고, search_documents에서 docType 필터링을 지원한다.

## Prerequisites

- Phase 1 완료 (frontmatter에 docType 주입 가능)

## Architecture Reference

- [00-1.architecture.md](./00-1.architecture.md) §2.2 search_documents 호출 시
- [00-2.tech-decisions.md](./00-2.tech-decisions.md) ADR-005

---

## Implementation Checklist

### 2.1 mcp-save.js — {type} 토큰 추가

**파일**: `src/main/mcp-save.js`

**resolveSubDir(format, { project, severity, docType })**:
- 파라미터에 `docType` 추가
- `{type}` 토큰 치환 로직 추가: `docType || 'note'`
- `sanitizeFilenameWithUrlEncode(docType || 'note')` 적용 (기존 project/severity 패턴 동일)

**기존 코드 (severity 패턴)**:
```javascript
const sevVal = sanitizeFilenameWithUrlEncode(severity || 'general');
result = result.replace(/\{severity\}/g, sevVal);
```

**추가할 코드**:
```javascript
const typeVal = sanitizeFilenameWithUrlEncode(docType || 'note');
result = result.replace(/\{type\}/g, typeVal);
```

**buildDestPath, saveMcpFile, mcpManualSave**:
- 파라미터 디스트럭처링에 `docType` 추가
- `resolveSubDir` 호출에 `docType` 전달

### 2.2 index.js — saveMcpFile 호출에 docType 전달

**파일**: `src/main/index.js`

- `case 'open_markdown'`: `saveMcpFile(store, { ..., docType: params.docType })`
- `case 'update_markdown'`: `saveMcpFile(store, { ..., docType: params.docType || entry.meta.docType })`
  - update 시 params에 docType 없으면 기존 meta에서 가져옴 (severity 패턴 동일)

### 2.3 search-engine.js — docType 인덱싱 + 필터

**파일**: `src/main/search-engine.js`

**_createFreshEngine()**:
- `defineConfig`의 필드에 `docType` 추가: `{ name: 'docType', ... }`
  - 가중치: `3` (docName과 동일 — 타입 검색은 중요하지만 본문보다 높아야 함)
- `ovFldNames`에 `'docType'` 추가: `['project', 'docName', 'docType']`

**_indexDocument(filePath, content)**:
- frontmatter에서 `docType` 추출
- BM25 doc에 `docType` 필드 추가
- `docMeta` Map에 `docType` 저장

**search(query, { limit, project, docType })**:
- 파라미터에 `docType` 추가
- 필터 함수에서 `docType` 체크:
  ```javascript
  if (docType && ov.docType !== docType) return false;
  ```
- 반환 결과에 `docType` 포함

**searchProjects(query, limit)**:
- 변경 없음 (프로젝트 검색이므로 docType 무관)

### 2.4 mcp-server.mjs — search_documents 스키마 확장

**파일**: `src/main/mcp-server.mjs`

- search_documents tool의 Zod 스키마에 `docType` 추가:
  ```javascript
  docType: z.enum([...DOC_TYPE_VALUES]).optional().describe('Filter by document type')
  ```
- 핸들러에서 `docType` 추출, `sendIpcRequest`에 전달
- IPC 응답의 `results`에 `docType` 필드 포함

### 2.5 mcp-http.mjs — search_documents 스키마 확장

**파일**: `src/main/mcp-http.mjs`

- TOOLS의 search_documents inputSchema에 `docType` enum 추가
- 핸들러에서 `docType` 추출, `searchEngine.search`에 전달

### 2.6 설정 UI 도움말 — {type} 토큰 안내

**파일**: `src/locales/*.json`

- `settings.mcpSaveSubDirHelpContent`에 `{type}` 토큰 설명 추가
  - 기존에 `{severity}` 설명이 있는 패턴 동일하게 추가

### 2.7 index.js — search_documents IPC 핸들러 확장

**파일**: `src/main/index.js`

- `case 'search_documents'`: `searchEngine.search(params.query, { ..., docType: params.docType })` 전달

## Test Scenarios

### 정상 케이스

**TC-2-01**: {type} 토큰이 docType 값으로 치환
```
Given: mcpSaveSubDir = "{yyyy-mm-dd}/{type}", docType = "plan"
When: saveMcpFile 호출
Then: 서브디렉토리 = "2026-03-18/plan"
```

**TC-2-02**: search_documents에 docType 필터 적용
```
Given: 인덱싱된 문서 3개 (note, plan, issue)
When: search("keyword", { docType: "plan" })
Then: plan 타입 문서만 반환
```

### 예외 케이스

**TC-2-03**: docType 미지정 시 {type}은 "note"로 치환
```
Given: mcpSaveSubDir = "{type}/{yyyy-mm-dd}", docType = undefined
When: resolveSubDir 호출
Then: 서브디렉토리 = "note/2026-03-18"
```

**TC-2-04**: search_documents에 docType 미지정 → 전체 반환
```
Given: 인덱싱된 문서 3개
When: search("keyword", {})
Then: 모든 문서 반환 (필터 미적용)
```

### 경계값

**TC-2-05**: {type} 토큰이 포맷에 없는 경우 무시
```
Given: mcpSaveSubDir = "{yyyy-mm-dd}", docType = "plan"
When: resolveSubDir 호출
Then: 서브디렉토리 = "2026-03-18" (영향 없음)
```
