### 코드 중복 주의

- `tab.renderedHtml` 필드는 `createInitialTab()`, `createBlankTab()`, `createTab()`, `switchTab()`, `saveCurrentTabState()`, `restoreTabContent()` 에서 사용된다. 모두 `tab.markdown` 으로 일관되게 교체해야 한다.
- `renderMarkdown()` 호출 경로가 `window.DocuLight.fn.renderMarkdown` 을 통한다. 탭 모듈에서 이 경로를 사용하는 기존 패턴(`switchTab` 내 `renderFn(data.markdown)`)이 이미 있으므로 동일 패턴을 `restoreTabContent` 에 적용한다.
- `switchTab`에 `checkFileMtime` 후 갱신 경로가 있다. 갱신 경로에서도 `renderedHtml` → `markdown` 전환이 필요하다.
- `renderTabBar()` 내 탭 요소들은 `existingTabs.forEach(el => el.remove())` 로 매번 제거 후 새로 생성하므로 리스너 중복 위험이 없다. 단, `closeTab`의 인덱스 캡처(`closeTab(index)`)가 루프 내 `forEach` 클로저로 되어 있으므로 클로저 캡처 시점을 확인한다.

#### IMPL-003: Find-in-page batch read/write 분리 (`src/renderer/viewer.js`)

- [ ] `updateMarkerTrack()` 함수 (약 1360번 줄) 를 수정한다

  ```javascript
  function updateMarkerTrack() {
    const track = document.getElementById('find-marker-track');
    const viewer = document.getElementById('viewer-container');
    if (!track || !viewer) return;

    track.innerHTML = '';
    if (findMatches.length === 0) {
      track.classList.add('hidden');
      return;
    }

    track.classList.remove('hidden');
    const scrollHeight = viewer.scrollHeight;
    if (scrollHeight === 0) return;

    // ... markersToShow 계산 ...

    const trackHeight = track.offsetHeight;  // ← 1회만 읽기

    // Pass 1: 모든 위치 읽기 (read phase — forced reflow 1회)
    const positions = markersToShow.map(mark => getElementScrollPosition(mark, viewer));

    // Pass 2: DOM 생성 및 삽입 (write phase — no reflow)
    const frag = document.createDocumentFragment();
    for (let i = 0; i < markersToShow.length; i++) {
      const mark = markersToShow[i];
      const top = positions[i];
      const ratio = top / scrollHeight;
      const markerDiv = document.createElement('div');
      markerDiv.className = 'find-marker';
      if (mark === findMatches[findCurrentIndex]) {
        markerDiv.classList.add('find-marker-current');
      }
      markerDiv.style.top = (ratio * trackHeight) + 'px';
      const matchIndex = findMatches.indexOf(mark);
      markerDiv.addEventListener('click', () => {
        // ... 클릭 핸들러 ...
      });
      frag.appendChild(markerDiv);
    }
    track.appendChild(frag);
  }
  ```

##### C. `restoreTabContent` 재렌더링으로 변경 (`src/renderer/tab-manager.js`)

- [ ] 기존 `contentEl.innerHTML = tab.renderedHtml` 를 제거

  ```javascript
  function restoreTabContent(tab) {
    var viewerContainer = document.getElementById('viewer-container');

    if (window.DocuLight && window.DocuLight.state) {
      window.DocuLight.state.currentFilePath = tab.filePath;
      window.DocuLight.state.sidebarTree = tab.sidebarTree;
    }

    // 마크다운 재렌더링
    var renderFn = window.DocuLight && window.DocuLight.fn && window.DocuLight.fn.renderMarkdown;
    if (renderFn && tab.markdown) {
      renderFn(tab.markdown);
    }

    // 스크롤 복원 — renderMarkdown이 async이므로 렌더링 완료 후 복원 필요
    // setTimeout(0)으로 다음 프레임에 복원
    var targetScrollTop = tab.scrollTop;
    setTimeout(function() {
      if (viewerContainer) viewerContainer.scrollTop = targetScrollTop;
    }, 0);

    // 검색 상태 복원
    if (tab.findQuery) {
      setTimeout(() => {
        const findInput = document.getElementById('find-input');
        if (findInput) {
          findInput.value = tab.findQuery;
          // performFind는 viewer.js IIFE 내부 함수이므로 직접 호출
          // viewer.js에 window.DocuLight.fn.performFind 노출 필요
          if (window.DocuLight && window.DocuLight.fn && window.DocuLight.fn.performFind) {
            window.DocuLight.fn.performFind(tab.findQuery);
          }
        }
      }, 100); // 렌더링 완료 후
    }

    // 사이드바 복원
    if (tab.sidebarTree) {
      var renderSidebar = window.DocuLight && window.DocuLight.fn && window.DocuLight.fn.renderSidebarTree;
      if (renderSidebar) renderSidebar(tab.sidebarTree);
    }

    if (tab.currentSidebarPath) {
      var updateHighlight = window.DocuLight && window.DocuLight.fn && window.DocuLight.fn.updateSidebarHighlight;
      if (updateHighlight) updateHighlight(tab.currentSidebarPath);
    }
  }
  ```
- [ ] **스크롤 복원 주의**: `renderMarkdown`이 async이면 렌더링 완료 전에 스크롤 설정이 무효화될 수 있다. `setTimeout(0)` 또는 `MutationObserver`로 렌더링 완료 후 복원한다.

### 언어+버전 주의사항

- **렌더러 프로세스**: `src/renderer/*.js`는 Electron renderer에서 실행된다. `window`, `document`, `requestAnimationFrame`이 모두 사용 가능하다.
- **IIFE 패턴**: `tab-manager.js`와 `viewer.js`는 IIFE `(function() { ... })()` 로 감싸져 있다. 함수 내부에서 선언된 변수와 함수는 모듈 스코프에서만 접근 가능하다. `window.DocuLight.fn.*` 를 통해 외부에 노출된 함수만 탭 모듈에서 접근 가능하다.
- **async 렌더링과 scroll 복원**: `renderMarkdown`이 async function이라면 반환 Promise가 완료되기 전에 `scrollTop` 설정이 무효화될 수 있다. `setTimeout(0)` 은 브라우저 렌더링 사이클 이후 실행을 보장하지 않는다. 더 안전한 방법은 `MutationObserver` 로 `#content` 변경을 감지하거나, `renderMarkdown`이 Promise를 반환하면 `.then()`으로 scroll 복원.
- **`requestAnimationFrame`**: `renderTabBar` 디바운스 용도로 사용. 탭 바 업데이트가 같은 프레임에 여러 번 요청되어도 1회만 실행됨.
- **IMPL-005의 `createInitialTab`**: 이 함수는 페이지 로드 시 호출된다. 이 시점에 `currentMarkdown`이 없을 수 있으므로 `window.DocuLight?.state?.currentMarkdown || ''` 의 기본값 처리가 필요하다.

### LLM 코딩 주의사항

1. **IMPL-005 핵심 원칙**: "innerHTML 캐싱 제거"가 목표이다. `tab.renderedHtml = contentEl.innerHTML` 패턴이 등장하는 모든 곳을 제거한다. 대신 원본 `markdown` 문자열을 보관하고 탭 전환 시 `renderMarkdown(tab.markdown)` 로 재렌더링한다. 검색 상태 복원을 위해 viewer.js의 `performFind()` 함수를 `window.DocuLight.fn` 객체에 노출해야 한다. 이 노출은 IMPL-005 구현 시 함께 수행한다.

2. **스크롤 복원 타이밍**: `renderMarkdown`의 async 특성 때문에 `viewerContainer.scrollTop = tab.scrollTop`을 즉시 설정하면 렌더링 후 DOM이 바뀌면서 스크롤이 초기화된다. `setTimeout(0)` 을 사용하되, 이것이 완벽하지 않을 수 있음을 주석으로 남긴다.

3. **IMPL-028 중복 리스너 여부 재확인**: `renderTabBar()`는 기존 요소를 완전히 제거하고 새로 생성하므로, 리스너 중복이 실제로 문제인지 코드를 다시 읽어 확인한다. 문제가 없다면 `requestAnimationFrame` 가드만 추가하는 것으로 충분하다.

4. **IMPL-045 closeTab 인덱스**: `renderTabBar()` 내 `forEach`의 클로저는 `index`를 올바르게 캡처한다. 단, 탭 삭제 후 남은 탭 요소가 이전 인덱스로 클릭 이벤트를 발생시킬 수 있다. `closeTab` 진입부의 범위 검증으로 방어한다.

5. **viewer.js `currentMarkdown` 노출**: `window.DocuLight.state.currentMarkdown` 에 값을 저장해야 `createInitialTab`에서 접근 가능하다. `renderMarkdown(body)` 함수 시작 부분에서 `currentMarkdown = body` 를 설정하고, `window.DocuLight.state` 를 정의하는 블록에서 getter 형태로 노출하거나 직접 할당한다.

6. **IMPL-004 renderMarkdown async 화**: `hljs.highlightElement` 청크 처리를 위해 해당 렌더링 단계가 async 여야 한다. `renderMarkdown` 함수 또는 그 내부의 hljs 단계를 async로 만들고, 호출자에서 `await`를 사용한다. tab-manager.js에서 `renderFn(data.markdown)` 를 호출하는 부분에서 반환 Promise를 처리하지 않아도 되지만, 스크롤 복원 타이밍에는 영향을 줄 수 있다.

7. **IMPL-002 yield 위치**: Mermaid `for...of` 루프에서 yield는 각 블록 처리 **후** 에 삽입한다. 첫 번째 블록 처리 전에 yield하면 FOUC(Flash of Unstyled Content) 가 발생할 수 있다.
