## 기존 코드 재사용 힌트

### viewer.js cleanups 패턴

> **⚠️ 리뷰 반영 (2026-04-17)**: 실제 코드 확인 결과, `beforeunload` 핸들러는 **이미 존재**한다 (`viewer.js:2433-2434`):
> ```javascript
> window.addEventListener('beforeunload', () => {
>   cleanups.forEach(fn => { if (typeof fn === 'function') fn(); });
> });
> ```
> 따라서 IMPL-026의 범위는 "beforeunload 핸들러 추가"가 아니라 **"기존 beforeunload 핸들러에 timer 정리 코드 병합"**으로 축소된다. `findDebounceTimer`와 `_autoCloseInterval`의 정리만 추가하면 된다.

- viewer.js에는 이미 `const cleanups = [];` 배열과 각 IPC 구독 시 `cleanups.push(unsub)` 패턴이 존재한다.
- `beforeunload` 핸들러도 이미 존재하며 `cleanups.forEach`를 호출한다. **새로운 beforeunload 핸들러를 등록하지 말 것.**
- `findDebounceTimer`와 `_autoCloseInterval`은 모듈 레벨 변수로 선언되어 있으며, 기존 `beforeunload` 핸들러 내부에 `clearTimeout`/`clearInterval` 코드를 추가한다.

### PDF IPC 리스너 패턴
- 현재 `ipcMain.on('window-ready', handler)` 패턴이 사용 중이다. 이를 `pdfWin.webContents.ipc.once('window-ready', handler)`로 전환하면 해당 webContents 소멸 시 자동 정리되고 one-shot 특성도 확보된다.
- Electron `webContents.ipc`는 `ipcMain`의 per-webContents 스코프 버전이다. `once`를 사용하면 한 번 실행 후 자동 제거된다.
- 배치 PDF(IMPL-025)는 반복문마다 새 `pdfWin`을 생성하므로 각 `pdfWin.webContents.ipc.once()` 호출로 자연스럽게 분리된다.

### SSE keep-alive interval 관리
- 현재 `activeSSEConnections`가 `Set<res>` 형태라면 `Map<res, intervalId>`로 전환한다.
- `res.on('close', ...)` 핸들러에서 `clearInterval(intervalId)`와 `activeSSEConnections.delete(res)` 모두 호출한다.
- `res.on('finish', ...)` 핸들러도 추가하여 정상 종료 경로도 정리한다(IMPL-050).
- `_mcpClose()` 함수에서 Map의 모든 엔트리를 순회하여 `clearInterval` 후 `Map.clear()`를 호출한다(IMPL-054).

### 파일 워처 정리 패턴
- `window-manager.js`의 `fileWatchers = new Map<windowId, FSWatcher>` 패턴을 활용한다.
- `stopFileWatcher(windowId)` 함수가 이미 존재하는지 확인하고, 없으면 `fileWatchers.get(windowId)?.close(); fileWatchers.delete(windowId);` 패턴으로 구현한다.
- `navigateTo()` 함수에서 `startFileWatcher()` 호출 직전에 반드시 `stopFileWatcher(windowId)` 호출을 선행한다.

### sidebar-search.js
- `init()` 함수는 페이지 로드 시 1회 호출된다. 문제는 사이드바 검색 모드 진입/종료를 반복할 때 동일 DOM 요소에 리스너가 누적될 수 있다는 점이다.
- `exitSearchMode()` 내부에서 `removeEventListener`를 명시적으로 호출하거나, 이벤트 핸들러를 named function으로 선언하여 remove할 수 있도록 한다.

## 코드 중복 주의

- `clearInterval`/`clearTimeout` 호출 시 null 체크(`if (timer)`)를 반드시 수행한다. timer 변수가 undefined인 경우도 안전하게 처리되어야 한다.
- SSE 정리 로직에서 `res.on('close')` 와 `res.on('finish')` 양쪽 모두에서 동일한 정리 코드가 실행되므로, 정리 함수를 공통 클로저로 추출하고 `once` 패턴을 적용하여 중복 실행을 방지한다.
- PDF 리스너 전환(IMPL-023, IMPL-024) 시 기존 `ipcMain.on()` 코드를 완전히 제거해야 한다. 일부만 전환하면 리스너가 두 곳에서 중복 등록된다.

    ```javascript
    let cleaned = false;
    const cleanup = () => {
      if (cleaned) return;
      cleaned = true;
      const id = activeSSEConnections.get(res);
      if (id) clearInterval(id);
      activeSSEConnections.delete(res);
    };
    res.on('close', cleanup);
    res.on('finish', cleanup);
    ```

    ```javascript
      for (const [res, intervalId] of activeSSEConnections) {
        clearInterval(intervalId);
        try { res.end(); } catch (e) { /* ignore */ }
      }
      activeSSEConnections.clear();
    }
    ```

## 언어+버전 주의사항

- **Electron 33**: `webContents.ipc.once()` 지원 확인. 지원되지 않으면 `ipcMain.once()` + 창 닫힘 시 `removeListener` 패턴을 사용한다.
- **ESM (mcp-http.mjs)**: `import { EventEmitter } from 'events'` 가능. `Set`/`Map` 모두 표준 ES6.
- **CJS (window-manager.js, sidebar-search.js)**: `require` 사용. `fs.watch()` 반환값이 `FSWatcher` 인스턴스임을 확인.
- **viewer.js (renderer)**: `window.addEventListener('beforeunload', ...)` 는 renderer 프로세스에서 동작. Electron sandbox 환경에서도 beforeunload 이벤트는 정상 발생.
- `clearInterval(undefined)` 및 `clearTimeout(undefined)` 는 안전하게 no-op이므로 null 체크는 방어적 코드지만 필수는 아니다. 그러나 가독성을 위해 유지.

- **IMPL-050**: `cleanup` 함수의 `cleaned` 플래그는 반드시 `res` 스코프(클로저) 내부에 선언해야 한다. Map과 별도로 관리.
- **IMPL-026~052 (cleanups)**: `beforeunload` 핸들러가 **이미 viewer.js:2433에 존재**한다. 절대 새로 등록하지 말고 기존 핸들러 내부에 timer 정리 코드를 병합한다.
- **IMPL-035, IMPL-051, IMPL-053**: 이 3개 항목은 **이미 구현되어 있을 가능성이 높다**. 현재 코드를 먼저 확인하고 이미 올바르면 변경하지 않는다. 불필요한 중복 코드 추가 금지.
- **sidebar-search.js (IMPL-029)**: `init()` 함수는 단 1회 호출되므로 `init()` 내부의 리스너는 누적되지 않는다. 실제 누적이 발생하는 경로(`enterSearchMode()` 반복 호출 시)를 확인하고 해당 경로의 리스너만 정리한다.

## 테스트 시나리오

### 정상 케이스 (IMPL-026~052: viewer.js cleanups)

  When: 매 회 완료 후
  Then: `window-ready` 및 `pdf-render-complete` 리스너 수가 이전 회와 동일하게 유지됨 (누적 없음)

### 정상 케이스 (IMPL-029: sidebar-search)

  Then: 검색 입력 요소와 document의 keydown 리스너 수가 초기 상태와 동일

  When: `activeSSEConnections` Map 확인
  Then: Map이 비어 있고 활성 interval이 없음

### 정상 케이스 (IMPL-053: navigateTo 워처)
- Given: 뷰어에서 5회 연속 파일 이동 (navigateTo)
  When: 이동 완료 후
  Then: `fileWatchers` Map에 해당 windowId 엔트리가 1개만 존재

### 예외 케이스
- Given: autoClose가 설정된 창에서 타이머 만료 전 수동으로 창을 닫음
  When: 창이 닫힘
  Then: `_autoCloseInterval`이 clearInterval되어 닫힌 창에 대한 IPC 전송 시도 없음

- Given: SSE 클라이언트가 비정상 종료(네트워크 끊김)
  When: `res.on('close')` 또는 `res.on('finish')` 발생
  Then: cleanup 함수가 1회만 실행되고 interval이 정리됨 (이중 실행 없음)
