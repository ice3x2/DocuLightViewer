## Phase 2: 핵심 비동기 전환 — 3건

### 목표

`link-parser.js`의 동기 파일 I/O(`fs.readdirSync`, `fs.readFileSync`)를 완전 비동기(`fs.promises`)로 전환하여
Electron 메인 프로세스 이벤트 루프 차단을 제거한다.
이후 IMPL-036(에러 처리 강화), IMPL-013(검색 IPC 디바운스)을 순서대로 완료한다.

### 코드 중복 주의

- `buildSidebarTree` 호출 지점이 `window-manager.js`와 `index.js` 양쪽에 있다. 두 파일 모두 수정해야 한다.
- `buildLinkTree` 내부의 재귀 호출은 `for...of`로 순차 처리해야 한다. `globalSeen` Set이 공유 상태이므로 병렬화하면 중복 노드가 생성될 수 있다.
- `buildDirectoryTree` 내부 디렉토리 반복은 `Promise.all`로 병렬화 가능하다 (각 디렉토리가 독립적).
- frontmatter 파싱(현재 `readFileSync`)은 `fs.promises.readFile`로 교체한다.

### 구현 체크리스트

#### IMPL-001: link-parser.js 전면 비동기 전환

##### A. `buildDirectoryTree` 비동기 전환

- [ ] 함수 시그니처 변경: `async function buildDirectoryTree(rootDir, depth = 0, counter = { count: 0 })`
- [ ] `fs.readdirSync(rootDir, { withFileTypes: true })` → `await fs.promises.readdir(rootDir, { withFileTypes: true })`
- [ ] 에러 처리: try-catch 블록 내에서 `await` 사용
- [ ] 디렉토리 재귀 호출 → `await buildDirectoryTree(...)` (순차 or `Promise.all` 중 선택):
  - **권장: `Promise.all`로 병렬화** (각 디렉토리가 독립적이고 `counter` 공유 시 주의)
  - `counter.count` 공유 상태로 인한 경쟁이 있으므로, 디렉토리 재귀는 순차(`for...of await`)로 처리해도 됨
  - 단순성을 위해 **순차 처리** 권장 (정확성 우선)
- [ ] `.md` 파일 frontmatter 읽기: `fs.readFileSync` → `await fs.promises.readFile`:
  - 파일별 읽기는 `Promise.all`로 병렬화 가능 (파일들이 독립적):
    ```javascript
    const fileNodes = await Promise.all(mdFiles.slice(0, available).map(async (file) => {
      const filePath = path.join(rootDir, file.name);
      let fmName = null;
      try {
        const fileContent = await fs.promises.readFile(filePath, 'utf-8');
        // ... frontmatter 파싱 ...
      } catch { /* 읽기 실패 시 null 유지 */ }
      return { path: filePath, title: file.name, frontmatterName: fmName, ... };
    }));
    ```
- [ ] `hasMdFiles()` 는 순수 트리 순회이므로 비동기 변경 불필요
- [ ] 반환값 형태는 기존과 동일한 객체 구조 유지

##### B. `buildLinkTree` 비동기 전환

- [ ] 함수 시그니처: `async function buildLinkTree(filePath, visited, depth = 0, counter = { count: 0 }, globalSeen)`
- [ ] `fs.readFileSync(normalized, 'utf-8')` → `await fs.promises.readFile(normalized, 'utf-8')`
- [ ] 재귀 호출은 **반드시 순차** (`for...of` + `await`):
  - `globalSeen` Set이 모든 재귀 호출에서 공유됨
  - `Promise.all` 로 병렬화하면 동일 파일이 여러 번 확장될 수 있음
  - 올바른 패턴:
    ```javascript
    for (const link of links) {
      counter.count++;
      if (counter.count > MAX_TREE_FILES) break;
      const childNode = await buildLinkTree(link.resolvedPath, new Set(visited), depth + 1, counter, globalSeen);
      if (childNode) {
        children.push(childNode);
      }
    }
    ```
- [ ] `extractMarkdownLinks()` 는 문자열 처리만 하므로 비동기 변경 불필요

##### C. `buildSidebarTree` 비동기 전환

- [ ] 함수 시그니처: `async function buildSidebarTree(filePath)`
- [ ] 내부 `buildLinkTree` → `await buildLinkTree(...)`
- [ ] 내부 `buildDirectoryTree` → `await buildDirectoryTree(...)`
- [ ] `markLinkedNodes`, `buildExternalNodes`, `collectLinkedPaths` 는 동기 유지 (메모리 연산만)

##### D. 모듈 exports 변경

- [ ] `module.exports = { buildSidebarTree }` 는 그대로 유지 (비동기 함수 export)
- [ ] 함수 내부에 `'use strict'` 가 있다면 파일 최상단으로 이동 (이미 파일 레벨에 없음 → 추가 불필요)

### 언어+버전 주의사항

- **CJS 비동기**: `link-parser.js`는 CJS 파일이다. `async function`과 `await`는 CJS에서 완벽히 지원된다. top-level await는 불가능하지만 함수 내부에서 사용 가능.
- **fs.promises**: Node.js 10+ 내장. Electron 33의 Node.js 20에서 완전 지원.
- **Promise.all 주의**: `buildLinkTree` 재귀는 `globalSeen` Set 공유 때문에 반드시 순차(`for...of`) 처리. `buildDirectoryTree` 내 같은 레벨의 독립 디렉토리들은 `Promise.all` 병렬화 가능하지만 `counter` 공유 경쟁에 주의.
- **ipcMain.on 핸들러**: `async` 함수를 핸들러로 직접 등록하면 throw된 에러가 uncaught promise rejection이 될 수 있다. 반드시 외부에서 `.catch()`를 붙이거나 try-catch로 전체 감싼다.
- **`ipcMain.handle` vs `ipcMain.on`**: `ipcMain.handle`은 async handler를 직접 지원한다. `ipcMain.on`은 지원하지 않으므로 `.catch()` 패턴 필수.

### LLM 코딩 주의사항

1. **buildLinkTree 재귀 순차 처리는 필수**: LLM이 성능을 위해 `Promise.all`로 변경하면 안 된다. `globalSeen` Set의 공유 상태 때문에 반드시 `for...of` + `await` 패턴을 사용한다.
2. **함수 시그니처 유지**: `buildSidebarTree(filePath)` 의 외부 시그니처는 변경하지 않는다. 반환값만 `Promise<Object>`로 바뀐다.
3. **에러 전파 vs 억제**: `buildLinkTree` 내 개별 파일 읽기 실패는 억제(catch 후 null 반환)하되 로그를 출력한다. `buildSidebarTree` 전체 실패는 호출자(window-manager.js, index.js)에서 catch한다.
4. **_resendWindowState 확인 필요**: `window-manager.js`의 `_resendWindowState()`도 `buildSidebarTree`를 호출할 수 있다. 해당 메서드를 확인하고 필요하면 비동기화한다.
5. **ipcMain.on 래핑 패턴**: `ipcMain.on`에 async 핸들러를 등록할 때 다음 패턴을 사용한다:
   ```javascript
   ipcMain.on('window-ready', (event, data) => {
     Promise.resolve().then(async () => {
       // async 작업
     }).catch(err => console.error(...));
   });
   ```
6. **`require('./link-parser')` 위치**: `index.js`에서 `buildSidebarTree`를 require 할 때 인라인 require인지 상단 require인지 확인 후 일관성 있게 처리한다. 기존 인라인 require 패턴이 있다면 유지한다.
