# Phase 5: 검색 엔진 견고성

## Phase 5: 검색 엔진 견고성 — 크래시 방지 및 동시성 안전 처리 (6건)

### 목표

BM25 검색 엔진(`search-engine.js`)의 손상된 인덱스, 부분 실패, 초기화 경쟁, rebuild 중 동시 검색으로 인한 크래시와 불완전한 결과를 방지한다. 토크나이저 성능도 CJK 전용 바이그램으로 개선한다.

**포함 항목 (IMPL ID 기준)**:
- IMPL-033 (E-4): `_loadIndex` JSON.parse try-catch
- IMPL-038 (E-9): `Promise.all + catch(null)` → `Promise.allSettled` + 로깅
- IMPL-046 (R-8): `initialize()` 완료 전 검색 요청 방어 (ensureFresh에서 초기화 대기)
- IMPL-042 (R-4): `rebuild()` 중 `search()` 동시 읽기 방어 (`_rebuildPromise` 활용)
- IMPL-014 (MEDIUM): `tokenize()`의 바이그램 생성을 CJK 문자에만 적용
- IMPL-037 (E-8): `readBody()` 에러 로깅 추가

## 기존 코드 재사용 힌트

### search-engine.js 아키텍처 이해
- `wink-bm25-text-search`는 `BM25 = require('wink-bm25-text-search')` 방식으로 사용한다.
- `engine.defineConfig({ fldWeights: {...} })` → `engine.definePrepTasks([tokenize])` → `engine.addDoc(doc, id)` → `engine.consolidate()` 순서로 초기화한다.
- `consolidate()`는 **최소 3개 문서**가 있어야 정상 동작하므로, `_fallbackSearch` 패턴(engine 없이 직접 문자열 매칭)을 보존해야 한다.
- `_rebuildPromise` 변수가 이미 존재할 수 있다 — rebuild 중복 방지 dedup 패턴이므로 절대 제거하지 않는다.
- `_isInitialized` (또는 유사 플래그) 변수가 초기화 완료 여부를 나타낸다.

### IMPL-033: JSON.parse try-catch
- `_loadIndex()` 함수에서 `fs.readFileSync(indexPath, 'utf8')` 후 `JSON.parse()` 호출 시 try-catch 추가.
- 실패 시 빈 상태 `{ docs: {}, index: null }` 반환하고 WARNING 로그 출력.
- `JSON.parse` 실패는 손상된 파일, 불완전한 쓰기(앱 강제 종료), 인코딩 문제 등에서 발생.

### IMPL-038: Promise.allSettled 전환
- 현재 패턴:
  ```javascript
  await Promise.all(docs.map(d => indexDoc(d).catch(() => null)));
  ```
- 변경 후 패턴:
  ```javascript
  const results = await Promise.allSettled(docs.map(d => indexDoc(d)));
  const failed = results.filter(r => r.status === 'rejected');
  if (failed.length > 0) {
    console.warn(`[search-engine] ${failed.length} docs failed to index:`, failed.map(r => r.reason));
  }
  ```
- `Promise.allSettled`는 일부 실패해도 나머지 결과를 반환한다. `Promise.all`의 catch(null) 패턴은 실패를 묵살한다.

### IMPL-046: 초기화 대기 패턴
- `initialize()` 진행 중임을 나타내는 `_initPromise` 변수를 추가.
- `ensureFresh()` 또는 검색 진입점에서:
  ```javascript
  if (_initPromise) await _initPromise;
  ```
- `initialize()` 시작 시: `_initPromise = _doInitialize(); await _initPromise; _initPromise = null;`
- 초기화 중 검색 요청은 초기화 완료 후 처리됨을 보장.

### IMPL-042: rebuild 중 search 방어
- `_rebuildPromise` dedup 패턴이 이미 있는 경우 활용:
  ```javascript
  async function search(query) {
    if (_rebuildPromise) {
      // rebuild 완료 후 현재 엔진 사용
      await _rebuildPromise;
    }
    return _doSearch(query);
  }
  ```
- Node.js는 단일 스레드이므로 진정한 동시 실행은 없다. 그러나 `async/await` 체인에서 rebuild 중 다른 microtask가 search를 호출할 수 있다.
- 가장 간단한 방어: `search()` 진입 시 `if (_rebuildPromise) await _rebuildPromise;`

### IMPL-014: CJK 바이그램 최적화
- `tokenizer.js`의 `tokenize()` 함수에서 바이그램 생성 부분을 찾는다.
- CJK Unicode 범위: `\u1100-\u11FF` (한글 자모), `\uAC00-\uD7AF` (한글 완성형), `\u4E00-\u9FFF` (한자), `\u3040-\u30FF` (히라가나/카타카나) 등.
- 바이그램 생성 전 문자가 CJK 범위인지 체크하는 헬퍼 함수 추가:
  ```javascript
  function isCJK(char) {
    const code = char.charCodeAt(0);
    return (code >= 0xAC00 && code <= 0xD7AF) || // 한글 완성형
           (code >= 0x1100 && code <= 0x11FF) || // 한글 자모
           (code >= 0x4E00 && code <= 0x9FFF) || // CJK 통합 한자
           (code >= 0x3040 && code <= 0x30FF);   // 히라가나/카타카나
  }
  ```
- 바이그램 루프에서 `if (isCJK(chars[i]) || isCJK(chars[i+1]))` 조건 추가.

### IMPL-037: readBody 에러 로깅
- `mcp-http.mjs`의 `readBody()` 함수에서 `data` 이벤트 누적 중 에러 발생 시 처리 추가.
- `req.on('error', ...)` 핸들러 추가 및 reject 시 로깅:
  ```javascript
  req.on('error', (err) => {
    console.error('[mcp-http] readBody error:', err.message);
    reject(err);
  });
  ```
- HTTP 클라이언트에 적절한 에러 응답(400/500) 반환 경로 확인.

## 코드 중복 주의

- `_rebuildPromise` dedup 패턴은 rebuild 중 중복 rebuild 방지에도 사용된다. IMPL-042 구현 시 이 패턴을 search 방어에도 재사용하되, rebuild 중복 방지 로직을 변경하지 않는다.
- `_initPromise`와 `_rebuildPromise`는 별개의 변수다. 혼용 금지.
- `Promise.allSettled`로 전환 시 기존의 `.catch(() => null)` 체인을 완전히 제거한다. 혼용하면 rejected Promise가 `null`로 resolved되어 `allSettled`에서 fulfilled로 잘못 분류된다.
- `isCJK()` 함수는 `tokenizer.js` 모듈 레벨에 단 1개만 정의한다. 바이그램 루프에 인라인 조건으로 중복 구현하지 않는다.

## 언어+버전 주의사항

- **Node.js 20 CJS**: `Promise.allSettled`는 Node.js 12.9.0+에서 지원. Node.js 20에서 완전 지원.
- **wink-bm25-text-search v3.1.2**: `consolidate()` 호출 전 최소 3개 문서 필요. `_fallbackSearch` 패턴을 제거하지 않는다.
- **tokenizer.js CJS**: Unicode 코드 포인트 비교는 `charCodeAt(0)` 기반. 서로게이트 쌍(이모지 등) 처리가 필요한 경우 `codePointAt(0)` 사용 고려. 한글/한자 범위는 BMP 내에 있으므로 `charCodeAt`으로 충분.
- **mcp-http.mjs ESM**: `import` 문법. `readBody`는 `Promise` 기반 함수. `req.on('error', handler)` 추가 시 이미 등록된 `data`, `end` 이벤트 핸들러를 방해하지 않음.
- **search-engine.js `_initPromise`**: 동일한 초기화가 두 번 실행되지 않도록 dedup 패턴 적용. `if (!_initPromise) _initPromise = _doInit();` 방식.

## LLM 코딩 주의사항

- **wink-bm25 3개 문서 제약**: `consolidate()` 전 문서 수를 확인하는 기존 로직을 절대 제거하지 않는다. `_fallbackSearch`는 consolidate 불가 시 사용되는 중요 경로다.
- **`_rebuildPromise` dedup**: IMPL-042 구현 시 기존 rebuild dedup 로직을 그대로 두고, `search()` 진입부에 await만 추가한다. rebuild 로직 자체를 리팩토링하지 않는다.
- **IMPL-046 최대 대기**: `_initPromise`를 무한정 await하면 앱이 응답하지 않을 수 있다. `Promise.race([_initPromise, timeout(10000)])` 패턴으로 최대 대기 시간을 설정한다.
- **IMPL-014 CJK 범위**: 한글 자모(1100-11FF)는 완성형(AC00-D7AF)과 별개의 범위다. 검색 품질을 위해 양쪽 모두 포함한다. 추가로 CJK 통합 한자 확장 A/B(3400-4DBF, 20000-2A6DF)는 BMP 외부이므로 surrogates 처리가 필요 — 일반적인 사용에서는 불필요하므로 기본 범위(4E00-9FFF)만 포함.
- **IMPL-038 로깅 수준**: 실패한 문서가 많을 경우 로그가 폭발할 수 있다. 처음 5개 실패만 상세 로그하고 나머지는 카운트만 출력하는 방식 고려.
