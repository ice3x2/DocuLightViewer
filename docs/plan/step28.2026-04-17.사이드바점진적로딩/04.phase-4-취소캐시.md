# Phase 4: 취소 + 캐시 + 경합 방지 — 3건

## Phase 4: 폴더 전환 시 즉시 취소와 재방문 최적화

### 목표

렌더러에서 폴더를 전환할 때 **이전 로드를 즉시 abort**하고, 최근 스캔한 루트 디렉토리에 대해 5분 TTL 캐시를 적용하여 재방문 시 **100ms 내 표시**되도록 한다.

### 선행 조건

- Phase 3 완료 (스피너/증분 렌더링 동작)

### 코드 중복 주의

- `AbortController` 생성/관리는 Phase 2에서 이미 `_startSidebarTreeLoad` 내부에 둠. Phase 4에서는 **캐시 히트 시 링크 파서를 호출하지 않는 분기**만 추가.
- 렌더러 측 loadId 추적은 Phase 3에서 이미 `_currentTreeLoadId` 로 구현. 여기서는 **폴더 전환 시 cancel invoke**만 추가.
- 캐시 키는 `path.resolve` 정규화. 동일 경로의 심볼릭 링크/대소문자 변형이 같은 키로 매핑되도록.

#### IMPL-28-012: 경합 제거 완결 (loadId 가드 엄격화)

**대상**: `src/main/window-manager.js`, `src/renderer/viewer.js`

- [ ] 메인: `_startSidebarTreeLoad`에서 `onBatch` 콜백 앞에 이미 있는 loadId 비교 유지
- [ ] 메인: `sidebar-tree-done` 전송 직전에도 `this._currentLoadIds.get(windowId)?.loadId === loadId` 재확인:
  ```javascript
  const still = this._currentLoadIds.get(windowId);
  if (!still || still.loadId !== loadId) {
    // 이미 새 로드가 시작됨 — done 이벤트 드롭
    return;
  }
  ```
- [ ] 렌더러: 각 리스너(`batch`/`done`/`error`) 시작부에 `if (loadId !== _currentTreeLoadId) return;` 패턴 재확인 (Phase 3 완성본)

  - 또는 사이드바 트리 노드 클릭으로 다른 .md 전환 직전
  - 실패 시에도 계속 진행 (best-effort)

#### IMPL-28-014: `sidebarTreeCache` (TTL 5분)

**대상**: `src/main/window-manager.js`

- [ ] 모듈 또는 클래스 상단에 상수:
  ```javascript
  const SIDEBAR_CACHE_TTL_MS = 5 * 60 * 1000;
  ```
- [ ] 캐시 맵은 Phase 2에서 선언한 `this.sidebarTreeCache` 재사용
- [ ] `_startSidebarTreeLoad` 시작부(loadId 생성 직후)에 캐시 조회:
  ```javascript
  const rootPath = path.resolve(path.dirname(filePath));
  const cached = this.sidebarTreeCache.get(rootPath);
  const now = Date.now();
  if (cached && (now - cached.timestamp) < SIDEBAR_CACHE_TTL_MS) {
    try {
      entry.win.webContents.send('sidebar-tree-start', { loadId, rootPath, fromCache: true });
      entry.win.webContents.send('sidebar-tree-done', { loadId, tree: cached.tree });
      entry.win.webContents.send('sidebar-tree', { tree: cached.tree });  // 호환
    } catch {}
    this._currentLoadIds.delete(windowId);
    return;
  }
  ```
- [ ] 성공 경로 끝에서 캐시 저장:
  ```javascript
  this.sidebarTreeCache.set(rootPath, { tree, timestamp: Date.now() });
  ```
- [ ] 캐시 크기 방어 (선택적이지만 권장):
  ```javascript
  if (this.sidebarTreeCache.size > 32) {
    // 가장 오래된 엔트리 제거
    const oldest = [...this.sidebarTreeCache.entries()]
      .sort((a, b) => a[1].timestamp - b[1].timestamp)[0];
    if (oldest) this.sidebarTreeCache.delete(oldest[0]);
  }
  ```
- [ ] 렌더러: `onSidebarTreeStart({ fromCache: true })` 수신 시 스피너 표시하지 않음 (이미 Phase 3 체크리스트의 start 리스너에서 `if (!fromCache) showSidebarSpinner()`로 구현됨 — 재확인)

### 언어+버전 주의사항

- **`path.resolve`**: Windows에서 대소문자 무관 파일시스템이어도 문자열 비교는 대소문자 구분. Windows에서 일관된 키 형식을 위해 `path.resolve`만 사용하고 `toLowerCase` 강제는 하지 않음 (링크 트리의 case sensitive 정렬과 충돌 위험).
- **`AbortController`와 Promise 타이밍**: abort 호출 이후에도 `buildSidebarTree` Promise가 즉시 reject되지 않을 수 있음. Phase 1에서 배치 경계마다 체크하도록 구현되어 있어 최대 1 배치(≤ 50 파일) 지연.
- **메모리**: 캐시는 tree 객체 통째로 보관. MAX_TREE_FILES=65535 × 다수 엔트리 시 메모리 증가 가능 → 상한 32 권장.

---

### LLM 코딩 주의사항

1. **캐시 키 정규화 필수**: `path.resolve` 없이 원본 rootPath를 키로 쓰면 `..` 포함 경로와 절대경로가 다른 키로 인식됨.
2. **캐시 히트 시 loadId도 유지**: start/done을 같은 loadId로 전송해야 renderer 경합 가드가 정상 동작. 캐시 경로에서 loadId를 증가시키지 말 것 (이미 증가한 loadId 사용).
3. **`fromCache: true` 시 스피너 노출 금지**: 사용자가 "깜빡이는 스피너"를 본다고 느끼면 UX 손해. 즉시 done 이벤트가 오므로 show/hide 호출 안 함.
4. **캐시 무효화는 범위 외**: 파일 변경 감시 기반 무효화는 별도 과제(ADR-4). 단, 수동 "사이드바 새로고침"이 있다면 해당 경로에서 캐시 `.delete(rootPath)` 명시 삭제 (선택적 스코프).
5. **aborted 시 DOM 초기화 금지**: 다음 start가 곧 `innerHTML = ''` 로 초기화. 중간에 렌더러가 초기화하면 깜빡임.
6. **Surgical**: 창별 캐시 격리 금지 — 전역 캐시 유지. 다중 창에서도 같은 폴더 재방문 시 혜택.

### 테스트 시나리오

#### 정상 케이스
- **Given**: 1000 파일 폴더를 처음 열기
  **When**: 정상 로드 완료
  **Then**: `sidebarTreeCache.get(rootPath)` 존재, timestamp 현재 시각

- **Given**: 같은 폴더를 5분 이내 재방문
  **When**: 다른 .md 파일을 같은 루트에서 열기
  **Then**: `sidebar-tree-start {fromCache: true}` + 즉시 `sidebar-tree-done` (100ms 이내), 스피너 표시 없음

- **Given**: 5분 경과 후 재방문
  **When**: 같은 폴더 열기
  **Then**: 정상 스캔 경로로 재실행, 캐시 갱신

#### 예외 케이스
- **Given**: 대용량 폴더 로딩 중(배치 3/10 시점) 다른 폴더 파일 열기
  **When**: `cancelSidebarTreeLoad(oldLoadId)` → 새 start
  **Then**: 이전 loadId의 `sidebar-tree-error {reason:'aborted'}` 도착, 새 loadId로 start/batch/done 정상 진행, 이전 DOM은 새 start의 `innerHTML=''`에서 정리

- **Given**: abort 직후(수 ms) 새 로드 시작
  **When**: 연속 폴더 전환
  **Then**: 이전 AbortController.aborted === true, 새 AbortController는 정상

- **Given**: 같은 폴더를 연속 2회 재방문
  **When**: 캐시 히트 반복
  **Then**: 첫 번째 히트에서 timestamp 갱신 안 함(정책: 히트 시 timestamp 유지). 5분 기준 재스캔.

#### 경계값
- **Given**: 캐시 크기 32 도달 후 33번째 폴더 방문
  **When**: 새 캐시 저장
  **Then**: 가장 오래된 엔트리 제거, 새 엔트리 추가

- **Given**: `fromCache: true` start 후 renderer가 `_currentTreeLoadId=loadId` 설정
  **When**: 즉시 이어 오는 done 이벤트
  **Then**: `renderSidebarTree(tree)` 정상 실행, 스피너 토글 없음
