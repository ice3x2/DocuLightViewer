# Phase 2: IPC 배치 이벤트 채널 — 4건

## Phase 2: 메인 ↔ 렌더러 간 배치 스트리밍 IPC 확장

### 목표

Phase 1에서 구현한 `onBatch`/`AbortSignal`을 Electron IPC로 노출한다. 4종 이벤트(start/batch/done/error) + 1종 invoke(cancel)를 통해 렌더러가 점진적 UI 업데이트와 취소 요청을 할 수 있게 한다.

- Phase 1 완료 (`onBatch`/`AbortSignal` 지원)

### 코드 중복 주의

- 기존 `sidebar-tree` IPC 이벤트는 **제거하지 않음**. 캐시 히트나 `sidebar-tree-done` 도착 시 기존 스키마와 호환되도록 같은 페이로드 구조 유지.
- `window-manager.js`에 `buildSidebarTree` 호출 지점이 여러 곳이므로 **단일 헬퍼 `_startSidebarTreeLoad(win, filePath)`** 로 통합.
- `index.js`의 3곳(`file-dropped`, `read-file-for-tab`, window-manager 내부)에서 동일 헬퍼 호출로 중복 제거.

### 구현 체크리스트

#### IMPL-28-004: `buildSidebarTreeAsync` + onBatch 포워딩

**대상**: `src/main/window-manager.js`

- [ ] `WindowManager` 클래스에 내부 상태 필드 추가:
  ```javascript
  this._currentLoadIds = new Map();  // windowId → { loadId, controller }
  this._treeLoadCounter = 0;
  this.sidebarTreeCache = new Map();  // rootPath → { tree, timestamp }  (Phase 4에서 사용)
  ```
- [ ] 신규 메서드 `_startSidebarTreeLoad(windowId, filePath)` 구현:
  ```javascript
  async _startSidebarTreeLoad(windowId, filePath) {
    const entry = this._windows.get(windowId);
    if (!entry || entry.win.isDestroyed()) return;

    // 이전 로드 취소
    const prev = this._currentLoadIds.get(windowId);
    if (prev) prev.controller.abort();

    const loadId = ++this._treeLoadCounter;
    const controller = new AbortController();
    this._currentLoadIds.set(windowId, { loadId, controller });

    const rootPath = path.resolve(path.dirname(filePath));

    // 캐시 히트 경로는 Phase 4에서 구현

    try { entry.win.webContents.send('sidebar-tree-start', { loadId, rootPath, fromCache: false }); }
    catch {}

    const { buildSidebarTree } = require('./link-parser');
    const onBatch = (nodes) => {
      const cur = this._currentLoadIds.get(windowId);
      if (!cur || cur.loadId !== loadId) return;  // 경합 방지
      if (entry.win.isDestroyed()) return;
      try { entry.win.webContents.send('sidebar-tree-batch', { loadId, nodes }); } catch {}
    };

    try {
      const tree = await buildSidebarTree(filePath, { onBatch, signal: controller.signal });
      entry.meta.tree = tree;
      if (!entry.win.isDestroyed()) {
        entry.win.webContents.send('sidebar-tree-done', { loadId, tree });
        entry.win.webContents.send('sidebar-tree', { tree });  // 기존 이벤트 호환 유지
      }
      // 캐시 저장은 Phase 4
    } catch (err) {
      if (!entry.win.isDestroyed()) {
        const reason = (err && err.name === 'AbortError') ? 'aborted' : 'error';
        entry.win.webContents.send('sidebar-tree-error', { loadId, reason, message: err.message });
      }
    } finally {
      const cur = this._currentLoadIds.get(windowId);
      if (cur && cur.loadId === loadId) this._currentLoadIds.delete(windowId);
    }
  }
  ```
- [ ] `onWindowReady` 및 관련 호출부에서 `await buildSidebarTree(...)` 블록을 `this._startSidebarTreeLoad(windowId, filePath)` 한 줄 호출로 교체
- [ ] 창 종료 시 `cleanup`에서 해당 windowId의 controller abort:
  ```javascript
  const live = this._currentLoadIds.get(windowId);
  if (live) { live.controller.abort(); this._currentLoadIds.delete(windowId); }
  ```

  ```javascript
  ipcMain.handle('cancel-sidebar-tree-load', (event, { loadId } = {}) => {
    const win = BrowserWindow.fromWebContents(event.sender);
    if (!win) return { cancelled: false };
    const windowId = windowManager.findWindowId(win);
    if (!windowId) return { cancelled: false };
    const cur = windowManager._currentLoadIds.get(windowId);
    if (!cur) return { cancelled: false };
    if (typeof loadId === 'number' && cur.loadId !== loadId) return { cancelled: false };
    cur.controller.abort();
    return { cancelled: true };
  });
  ```


### 언어+버전 주의사항

- **`AbortController`**: Node.js 20 내장. `new AbortController()` 정상 작동.
- **`win.isDestroyed()` 가드**: `webContents.send` 호출 전에 필수. 창이 사라진 상태에서 send 시도 시 에러.
- **`ipcMain.handle` vs `ipcMain.on`**: `cancel-sidebar-tree-load`는 응답이 필요하므로 `ipcMain.handle`. async 핸들러는 `ipcMain.handle`이 자연 지원.
- **CJS require 순환**: `require('./link-parser')`는 인라인 require 패턴 유지(step27 Phase 2 관례). 상단 require로 올리지 말 것.

---

### LLM 코딩 주의사항

1. **기존 `sidebar-tree` 이벤트 유지**: 제거하면 renderer의 기존 수신 경로 전체가 깨진다. 호환성을 위해 `done` 이벤트와 함께 기존 이벤트도 함께 전송.
2. **loadId 경합 가드 필수**: `onBatch` 콜백에서 현재 loadId와 비교해 구 로드의 잔여 이벤트를 드롭. 이 체크가 없으면 폴더 전환 후에도 이전 배치가 UI에 반영됨.
3. **`finally` 블록에서 현재 loadId와 비교**: 같은 windowId에 이미 새 로드가 시작된 경우 `this._currentLoadIds.delete` 호출 금지 (새 로드의 상태를 지울 위험).
4. **헬퍼 중복 방지**: `_startSidebarTreeLoad`는 단일 진입점. `window-manager.js` 내 기존 `buildSidebarTree` 호출 모두 이 헬퍼로 교체.
5. **Simplicity**: IPC 이벤트 추가 외 리팩토링 금지. 기존 창 상태 관리 로직에 손대지 말 것.
6. **에러 스키마**: `{ loadId, reason: 'aborted' | 'error', message? }`. 다른 필드 추가 금지(Phase 3/4에서 파싱할 스키마와 일치).

### 테스트 시나리오

#### 정상 케이스
- **Given**: 200개 MD 파일 폴더를 연 창
  **When**: `_startSidebarTreeLoad` 실행
  **Then**: `sidebar-tree-start` 1회 → `sidebar-tree-batch` 4회(50×4) → `sidebar-tree-done` 1회 → 기존 `sidebar-tree` 호환 이벤트 1회 (모두 동일 loadId)

#### 예외 케이스
- **Given**: 로드 진행 중 같은 창에서 다른 파일 열기
  **When**: 두 번째 `_startSidebarTreeLoad` 호출
  **Then**: 첫 번째 loadId에 대한 `sidebar-tree-error {reason:'aborted'}` 전송 + 두 번째 loadId로 새 start 시작

- **Given**: 로드 진행 중 창 닫기
  **When**: 창 cleanup
  **Then**: AbortController abort, 이후 webContents.send 시도 없음 (isDestroyed 가드)

- **Given**: `cancelSidebarTreeLoad(loadId)` 호출 (정상 loadId)
  **When**: invoke 실행
  **Then**: `{ cancelled: true }` 반환 + `sidebar-tree-error {reason:'aborted'}` 전송

- **Given**: `cancelSidebarTreeLoad(999)` (존재하지 않는 loadId)
  **When**: invoke 실행
  **Then**: `{ cancelled: false }` 반환, 진행 중 로드에는 영향 없음

#### 경계값
- **Given**: 파일 0개인 빈 폴더
  **When**: 로드 실행
  **Then**: `sidebar-tree-start` 1회 → `sidebar-tree-batch` 0회 → `sidebar-tree-done` 1회
