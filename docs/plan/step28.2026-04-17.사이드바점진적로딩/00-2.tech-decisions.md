# 기술 결정 기록 (ADR) — step28

## ADR-1: 비동기화 방식으로 "fs.promises 청크 스트리밍" 채택

**상태**: Accepted (2026-04-17)
**컨텍스트**: `link-parser.js` 동기 I/O로 인한 수 분 UI 프리징. 해결 방식으로 worker_threads, fs.promises 스트리밍, 상한 강화 3가지 옵션이 있었음.
**결정**: **옵션 A (fs.promises 청크 스트리밍)**.
**근거**:
1. worker_threads는 진행률 피드백이 어렵다 — 스피너만 표시되고 부분 트리를 못 보여줌.
2. 상한 강화는 근본 해결이 아니다.
3. Electron 33의 Node.js 20은 `AbortController` + `fs.promises`를 완전 지원한다.
4. 기존 IPC 이벤트 패턴(`sidebar-tree`)과 자연스럽게 확장 가능.

**결과**: 배치 단위 IPC 스트리밍으로 1~2초 내 초기 응답. 기존 코드와의 충돌 최소.

## ADR-2: 배치 크기 50파일 고정

**상태**: Accepted
**컨텍스트**: 배치가 너무 작으면 IPC 오버헤드 증가, 너무 크면 첫 배치 지연.
**결정**: `BATCH_SIZE = 50` 상수.
**근거**:
- Electron IPC는 1회 메시지당 수십 KB 수준은 무시할 만한 지연.
- 50파일 × 평균 frontmatter 파싱 ≈ 50~200ms (디스크 캐시 상태에 따라).
- 소규모 폴더는 단일 배치로 끝나 체감 차이 없음.

**대안 고려**: 파일 크기 기반 동적 배치. 복잡도 대비 이득 적음 → 기각.

## ADR-3: AbortController를 `window-manager`에서 관리

**상태**: Accepted
**컨텍스트**: 렌더러가 취소를 요청할 주체는 창. 창 단위로 현재 진행 중인 `loadId`와 `AbortController`를 매핑해야 함.
**결정**: `WindowManager._currentLoadIds: Map<windowId, {loadId, controller}>`.
**근거**: 창이 닫힐 때 `controller.abort()` 자동 호출 가능. 창별 독립 상태 유지.

## ADR-4: TTL 5분 캐시, 파일 감시 미포함 (MVP)

**상태**: Accepted
**컨텍스트**: 매번 재스캔은 낭비. 그러나 파일 시스템 이벤트 감시는 별도 과제 수준의 복잡도.
**결정**: `sidebarTreeCache: Map<rootPath, {tree, timestamp}>` + TTL 5분.
**근거**:
- 사용자는 보통 짧은 시간 내에 같은 폴더를 재탐색.
- 파일 변경 반영 지연 5분은 수용 가능 (수동 새로고침 가능).
- `chokidar` 도입은 이슈 범위 초과.

**후속 과제**: 파일 변경 감시 기반 무효화는 별도 step에서 다룬다.

## ADR-5: 스피너 요구사항을 시각적으로 정확 구현

**상태**: Accepted
**컨텍스트**: 사용자 원안: "회색원 원 세 개가 번갈아가며 커졌다 작아졌다".
**결정**: CSS `@keyframes spinner-pulse` + `animation-delay`로 3개 원이 순차 펄스.
- 색상: `var(--text-muted, #888)` (light/dark 테마 모두에서 회색 보장)
- 크기: 10px → 1.2배 → 0.6배 반복
- 주기: 1.4초, 각 원 0.2초 간격 지연

**근거**: 추가 라이브러리 없이 순수 CSS로 구현 가능. 테마 토큰 재사용으로 light/dark 일관성.

## ADR-6: 부분 렌더링은 단순 `appendChild` + DocumentFragment

**상태**: Accepted
**컨텍스트**: 배치 수신 시 렌더러에서 DOM을 다시 빌드하면 리페인트 폭증.
**결정**: 배치 수신 시 `DocumentFragment`에 새 노드만 생성 후 단일 `appendChild`.
**근거**:
- 65535 노드 전체 재빌드 대비 수~수백 배 빠름.
- Virtual DOM 라이브러리 도입 불필요.
- step27 Phase 7의 IMPL-010(diff 렌더링) 범위와 분리 유지.

## ADR-7: step27 Phase 2를 선행 필수로 가정, 병합하지 않음

**상태**: Accepted
**컨텍스트**: step27 Phase 2가 이미 `link-parser` async 전환을 계획 중. step28이 이를 재구현하면 중복.
**결정**: step28은 step27 Phase 2 완료를 **선행 조건**으로 하고, 그 위에 onBatch/AbortSignal 확장만 추가.
**근거**: 관심사 분리. step27은 "이벤트 루프 비차단", step28은 "체감 UX".
**위험**: step27 Phase 2 미실행 상태에서 step28을 시작하면 버전 충돌. 본 계획의 Phase 0 가드(선행 조건 검증)로 방지.
