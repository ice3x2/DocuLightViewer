# 아키텍처 설계 — 사이드바 점진적 로딩

## 데이터/제어 흐름

```
┌──────────────────────────────────────────────────────────────┐
│ Renderer (viewer.js)                                         │
│                                                              │
│  openFile(path) ──▶ (1) cancelSidebarTreeLoad(prevLoadId)    │
│                 ──▶ (2) IPC: request via existing flow       │
│                                                              │
│  onSidebarTreeStart(loadId) ──▶ showSidebarSpinner()         │
│  onSidebarTreeBatch({loadId, nodes}) ──▶ appendToTree()      │
│  onSidebarTreeDone({loadId}) ──▶ hideSidebarSpinner()        │
│  onSidebarTreeError({loadId, reason:'aborted'|'error'}) ──▶  │
│      hideSpinner + 필요 시 에러 토스트                         │
└───────────────────────▲─────────────────────┬────────────────┘
                        │                     │
                        │ IPC events          │ IPC invoke
                        │ (main → renderer)   │ (renderer → main)
                        │                     ▼
┌──────────────────────────────────────────────────────────────┐
│ Main Process                                                 │
│                                                              │
│  WindowManager.buildSidebarTreeAsync(win, path)              │
│    ├── loadId = ++this._treeLoadCounter                      │
│    ├── this._currentLoadIds.set(windowId, {loadId, abort})  │
│    ├── cacheHit? → send ...-start, -batch(full), -done 즉시  │
│    └── send sidebar-tree-start {loadId, rootPath}            │
│                                                              │
│  link-parser.buildDirectoryTree(root, {                      │
│    onBatch: (nodes) => send sidebar-tree-batch {loadId,nodes}│
│    signal: abortController.signal                            │
│  })                                                          │
│    ├── fs.promises.readdir                                   │
│    ├── 50파일 청크 × Promise.all(fs.promises.readFile)       │
│    ├── 배치 수집 → onBatch(partial)                          │
│    └── AbortError 처리                                       │
│                                                              │
│  linkTree 병합 후 send sidebar-tree-done {loadId, fullTree}  │
│  실패 시 send sidebar-tree-error {loadId, reason}            │
│  캐시 저장: sidebarTreeCache.set(rootPath, {tree,timestamp}) │
└──────────────────────────────────────────────────────────────┘
```

## 컴포넌트 책임

| 컴포넌트 | 책임 | 변경 범위 |
|----------|------|----------|
| `link-parser.js` | 디렉토리/링크 트리 구성, 배치 yield, Abort 협력 | `buildDirectoryTree`/`buildLinkTree` 시그니처 확장 |
| `window-manager.js` | 창별 loadId·AbortController 관리, 캐시, IPC 이벤트 송신 | `buildSidebarTreeAsync` 신규, 기존 `buildSidebarTree` 호출부 대체 |
| `index.js` | IPC handle 등록(`cancel-sidebar-tree-load`) | 추가 |
| `preload.js` | contextBridge로 4종 리스너 + 1 cancel invoke 노출 | `window.doclight` 확장 |
| `viewer.js` | 스피너 표시, 증분 DOM 추가, 폴더 전환 시 cancel 호출 | `renderSidebarTree` 부분 업데이트 분기 |
| `viewer.html`/`viewer.css` | 스피너 DOM + pulse 애니메이션 | 신규 요소 |

## 데이터 모델

### IPC 이벤트 페이로드

```ts
// sidebar-tree-start
{ loadId: number, rootPath: string, fromCache: boolean }

// sidebar-tree-batch
{ loadId: number, nodes: TreeNode[] }  // nodes는 DirectoryTree의 부분 자식 목록

// sidebar-tree-done
{ loadId: number, tree: FullSidebarTree }  // 기존 'sidebar-tree' 스키마와 동일한 완성본

// sidebar-tree-error
{ loadId: number, reason: 'aborted' | 'error', message?: string }

// cancel-sidebar-tree-load (renderer → main, invoke)
{ loadId: number } → { cancelled: boolean }
```

### 캐시 엔트리

```ts
sidebarTreeCache: Map<string /* rootPath */, {
  tree: FullSidebarTree,
  timestamp: number,       // Date.now()
}>
const CACHE_TTL_MS = 5 * 60 * 1000;
```

### link-parser 옵션 확장

```ts
buildDirectoryTree(rootDir: string, {
  depth?: number,
  counter?: {count: number},
  onBatch?: (nodes: TreeNode[]) => void,
  signal?: AbortSignal,
  batchSize?: number,  // default 50
}): Promise<DirectoryTreeNode>
```

## 비기능 요구사항

| 항목 | 목표 |
|------|------|
| 초기 스피너 표시까지 | ≤ 200ms (loadId=1 IPC start 수신까지) |
| 첫 배치 DOM 추가 | ≤ 2초 (50파일 스캔 + readFile + IPC) |
| 폴더 전환 → abort 반영 | ≤ 300ms |
| 캐시 히트 시 렌더 | ≤ 100ms |
| 메모리 상한 | 기존 `MAX_TREE_FILES=65535` 유지 |

## 보안/안전성

- AbortSignal 미준수 경로 발생 시 로그 + 다음 배치 경계에서 강제 종료
- 폐쇄된 `BrowserWindow`로 `webContents.send` 호출 방지 (`win.isDestroyed()` 가드)
- 캐시 키는 `path.resolve(rootPath)` 로 정규화 (대소문자 차이/상대경로 공격 방지)
