### 구현 체크리스트

#### E2E 시나리오 파일 신규 작성

**대상**: `test/sidebar-async.e2e.js`

- [ ] 테스트 setup: tmp 디렉토리에 500개의 `.md` 파일 자동 생성
  ```javascript
  // pseudo
  const tmp = await fs.mkdtemp(path.join(os.tmpdir(), 'dl-async-'));
  for (let i = 0; i < 500; i++) {
    await fs.writeFile(path.join(tmp, `note-${i}.md`), `# Note ${i}\n`);
  }
  ```
- [ ] 테스트 teardown: tmp 디렉토리 삭제

##### 시나리오 1: 대용량 폴더 스피너 표시

- [ ] 500개 파일 디렉토리 내 `.md` 파일 열기
- [ ] `#sidebar-loading-spinner` 가 200ms 이내 visible 상태가 됨
- [ ] 2초 이내 첫 번째 자식 노드가 `#sidebar-tree` 내부에 존재
- [ ] done 이벤트 수신 후 스피너 숨김
- [ ] 최종 사이드바에 500개 노드 존재

##### 시나리오 2: 연속 폴더 전환

- [ ] 500개 파일 폴더 A와 10개 파일 폴더 B 준비
- [ ] A 열기 → 로딩 중(배치 2/10 시점 가정 100ms 대기) → B 열기
- [ ] 최종 사이드바에 B의 10개 노드만 존재 (A의 잔여 노드 없음)
- [ ] `sidebar-tree-error {reason:'aborted'}` 이벤트가 A의 loadId에 대해 발생했음을 로그로 확인

##### 시나리오 3: 캐시 히트

- [ ] 폴더 A 열고 완료 대기
- [ ] A 내의 다른 `.md` 파일 열기
- [ ] 스피너 표시 없음(150ms 이내 done 이벤트)
- [ ] 사이드바 노드 수 동일

##### 시나리오 4: 캐시 TTL 만료

- [ ] 폴더 A 열고 완료
- [ ] (테스트 헬퍼로 캐시 timestamp를 6분 전으로 조작)
- [ ] 같은 폴더 재방문 시 스피너 표시 + 정상 재스캔

##### 시나리오 5: 회귀 - 소규모 폴더

### 성능 목표 검증

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| 스피너 표시까지 | ≤ 200ms | E2E `toBeVisible()` 타이머 |
| 첫 배치 DOM 추가 | ≤ 2초 | batch 이벤트 수신 시각 기록 |
| 폴더 전환 → abort 반영 | ≤ 300ms | cancel invoke → error 이벤트 수신 간격 |
| 캐시 히트 렌더 | ≤ 150ms | start(fromCache:true) → renderSidebarTree 완료 |
| 500 파일 스캔 전체 | ≤ 10초 (SSD 기준) | 참고용, 프리징 없는 진행 |
