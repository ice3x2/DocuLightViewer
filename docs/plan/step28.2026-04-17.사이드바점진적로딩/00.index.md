## 개요

Downloads처럼 `.md` 파일이 수천 개 있는 폴더를 열 때 **수 분간 UI 프리징**이 발생하는 문제를 **사용자 체감 UX 관점에서 해결**하는 계획이다.

연구 결과 **옵션 A (fs.promises 청크 스트리밍)** 를 권장 방식으로 채택한다.

- **step27 Phase 2**는 `link-parser.js`의 동기 I/O를 async로 전환(백엔드 블로킹 해소)
- **step28(본 계획)** 은 그 위에 **배치 스트리밍 + 로딩 스피너 + 증분 렌더링 + 취소 + 캐시**를 얹어 **체감 반응 1~2초 내 확보**

## 사용자 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 배치 크기 | `BATCH_SIZE = 50` | 일반적 UI 응답성 + 이벤트 수 균형 |
| 캐시 TTL | 5분 | 단기 폴더 전환 루프 최적화, 파일 변경 반영 지연 허용 범위 |
| 스피너 모양 | 회색 원 3개 펄스(커졌다 작아짐) | 사용자 원안 "회색원 세 개 번갈아 커졌다 작아졌다" 그대로 구현 |
| 폴더 전환 시 | 이전 로드 **즉시 abort** + 스피너 재시작 | 체감 반응성 우선 |
| 캐시 무효화 | 명시적 트리거 없음(시간만), 파일 변경 감시는 별도 과제 | MVP 범위 축소 |
| Worker thread | 도입하지 않음 (옵션 B 기각) | 진행률 피드백 불가 + 구현 복잡도 |
