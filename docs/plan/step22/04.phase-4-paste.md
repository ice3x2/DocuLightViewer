### 4-1. `paste` 이벤트 리스너 (viewer.js)

> 📌 **재활용**: 기존 `isEmpty` 체크 패턴 (`showContextMenu()` line 786), 기존 `render-markdown` 이벤트 플로우

- [ ] `paste` 이벤트 리스너 추가 (기존 IPC handlers 섹션 근처)
  ```javascript
  document.addEventListener('paste', function(e) {
    // 빈 페이지 체크 (기존 패턴 재사용)
    var contentEl = document.getElementById('content');
    var isEmpty = !currentFilePath && (!contentEl || !contentEl.hasChildNodes() ||
                  !!contentEl.querySelector('.empty-state'));
    if (!isEmpty) return;  // 기존 콘텐츠 있으면 무시

    // input/textarea 포커스 시 무시 (검색바 등 보호)
    var active = document.activeElement;
    if (active && (active.tagName === 'INPUT' || active.tagName === 'TEXTAREA')) return;

    // Find bar 열려 있으면 무시
    if (findBarVisible) return;

    // 클립보드에서 텍스트 가져오기
    var text = null;
    if (e.clipboardData) {
      text = e.clipboardData.getData('text/plain');
    }
    if (!text || !text.trim()) return;

    e.preventDefault();

    // 상태 초기화
    originalContent = text;
    currentFilePath = null;
    if (typeof saveAsFilePath !== 'undefined') saveAsFilePath = null;
    if (typeof savedFilePath !== 'undefined') savedFilePath = null;

    // 메인 프로세스에 렌더링 요청
    window.doclight.renderPastedContent(text);
  });
  ```

### 4-3. IPC 핸들러 (index.js)

> 📌 **재활용**: 기존 `render-markdown` 이벤트 전송 패턴, 기존 `extractTitleFromContent()` (mcp-save.js에서 import)

- [ ] `render-pasted-content` invoke 핸들러:
  ```javascript
  ipcMain.handle('render-pasted-content', async (event, content) => {
    const win = BrowserWindow.fromWebContents(event.sender);
    if (!win) return;

    const { extractTitleFromContent } = require('./mcp-save');
    const title = extractTitleFromContent(content) || 'Pasted';

    win.webContents.send('render-markdown', {
      markdown: content,
      filePath: null,
      title: title,
      source: 'paste'
    });
  });
  ```

  > **핵심**: 새 이벤트를 만들지 않고 기존 `render-markdown` 이벤트를 재사용.
  > 렌더러의 `onRenderMarkdown` 핸들러가 자동으로 처리한다:
  > - `currentFilePath = null` (data.filePath 없음)
  > - `originalContent = data.markdown` (content 기반)
  > - `renderMarkdown()` 호출로 렌더링

### 4-4. `onRenderMarkdown` 핸들러 수정 (viewer.js)

Phase 1에서 이미 `source` 필드 처리가 추가된 경우:
- `source === 'paste'` → `isMcpDocument = false` (MCP 문서가 아님)

Phase 1 없이 병렬 실행하는 경우:
- `isMcpDocument` 변수가 없으면 이 수정 불필요 (Phase 1 머지 후 통합)

## 설계 결정 상세

### 왜 `render-pasted-content` IPC가 필요한가?

직접 렌더러에서 `renderMarkdown(text)`를 호출하는 것도 가능하지만:

1. `onRenderMarkdown` 핸들러에는 부수 효과가 많다:
   - `currentFilePath` 설정
   - `originalContent` 설정
   - 탭 상태 업데이트 (`tabManager` 연동)
   - 사이드바 하이라이트 업데이트
   - `DocuLight.state` 갱신
   - 제목 설정

2. 이 부수 효과를 수동으로 복제하면 코드 중복 + 향후 유지보수 문제

3. 기존 `render-markdown` 이벤트를 재사용하면 **0줄 렌더러 수정**으로 해결

### 왜 빈 페이지에서만 동작하는가?

- 기존 콘텐츠가 있는 페이지에서 paste는 텍스트 선택, 코드 블록 내 복사 등 기존 동작과 충돌
- "편집" 기능은 DocLight 범위 밖 (뷰어 전용)
- 빈 페이지 한정으로 안전하게 제한

## 테스트 시나리오

### 정상 케이스

**TC-4-01: 빈 페이지에 MD 텍스트 붙여넣기**
- Given: 빈 뷰어 (drop zone 표시)
- When: 클립보드에 `"# Hello\n\nWorld"` → Ctrl+V
- Then: H1 "Hello", p "World" 렌더링됨. drop zone 사라짐

**TC-4-02: 붙여넣기 후 Save As 가능**
- Given: TC-4-01 완료 (MD가 렌더링된 상태)
- When: Ctrl+Shift+S
- Then: Save As 다이얼로그 열림, 기본 파일명 "Hello.md"

### 예외 케이스

**TC-4-03: 기존 콘텐츠에서 Ctrl+V**
- Given: 마크다운이 이미 렌더링된 상태
- When: Ctrl+V
- Then: 아무 동작 없음 (기존 브라우저 동작)

**TC-4-04: 빈 클립보드에서 Ctrl+V**
- Given: 빈 페이지, 클립보드 비어있음
- When: Ctrl+V
- Then: 아무 동작 없음

**TC-4-05: 검색바 포커스 중 Ctrl+V**
- Given: 빈 페이지, 검색바 (Ctrl+F) 열림, 입력란 포커스
- When: Ctrl+V
- Then: 검색 입력란에 텍스트 붙여넣기 (빈 페이지 렌더링 아님)

### 경계값

**TC-4-06: 대용량 텍스트 붙여넣기**
- Given: 빈 페이지
- When: 5MB 마크다운 텍스트 Ctrl+V
- Then: 기존 대용량 문서 경고 로직 동작 (렌더링 가능하지만 느릴 수 있음 안내)

**TC-4-07: 탭 모드 빈 탭**
- Given: 탭 모드 활성, 빈 탭 (Ctrl+T로 생성)
- When: Ctrl+V
- Then: 해당 탭에 마크다운 렌더링됨
