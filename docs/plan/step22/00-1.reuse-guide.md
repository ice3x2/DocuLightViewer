## 2. 컨텍스트 메뉴 — 사이드바용 새 메뉴 함수 최소화

### 기존 코드: `viewer.js:772-981`

`showContextMenu(e)`는 뷰어 전용으로 항목이 많다. 사이드바용은 2개 항목만 필요.

### 재활용 방법: 메뉴 생성/위치/닫기 로직을 인라인 재사용

사이드바 컨텍스트 메뉴에서 **공유하는 코드**:

| 로직 | 기존 위치 | 재활용 |
|------|----------|--------|
| `.ctx-menu` div 생성 | line 774-778 | 동일 패턴 |
| `.ctx-menu-item` div 생성 | line 797 등 | 동일 패턴 |
| 뷰포트 보정 위치 계산 | line 954-960 | 동일 코드 복사 |
| mousedown/keydown 닫기 핸들러 | line 962-980 | 동일 코드 복사 |
| CSS 클래스 | `.ctx-menu`, `.ctx-menu-item` | 기존 CSS 그대로 사용 |

**헬퍼 함수 추출 고려**: 위치 계산 + 닫기 핸들러를 별도 함수로 추출하면 코드 중복 제거 가능.

```javascript
// 추출 대상 (선택적)
function positionAndBindContextMenu(menu, e) {
  document.body.appendChild(menu);
  var rect = menu.getBoundingClientRect();
  var x = e.clientX, y = e.clientY;
  if (x + rect.width > window.innerWidth) x = window.innerWidth - rect.width - 4;
  if (y + rect.height > window.innerHeight) y = window.innerHeight - rect.height - 4;
  menu.style.left = x + 'px';
  menu.style.top = y + 'px';

  function closeMenu(ev) { if (!menu.contains(ev.target)) { menu.remove(); document.removeEventListener('mousedown', closeMenu); document.removeEventListener('keydown', escH); } }
  function escH(ev) { if (ev.key === 'Escape') { menu.remove(); document.removeEventListener('mousedown', closeMenu); document.removeEventListener('keydown', escH); } }
  setTimeout(function() { document.addEventListener('mousedown', closeMenu); document.addEventListener('keydown', escH); }, 0);
}
```

이 함수를 추출하면 `showContextMenu()`에서도 사용할 수 있어 기존 코드 줄 수가 줄어든다.

## 4. `saveMcpFile()` — 리팩터링, 복제 아님

### 기존 코드: `mcp-save.js:36-85`

### 재활용 방법: 기존 함수를 수정하되 새 함수를 만들지 않기

**`mcpManualSave()`가 필요한 이유**: `saveMcpFile()`은 `mcpAutoSave=true` 체크가 내장되어 있음. 수동 저장은 이 체크를 건너뛰어야 함.

**최소 코드 접근**: `saveMcpFile()` 내부에서 공통 로직을 추출.

```javascript
// 방법 A (권장): 내부 로직 공유
function buildSavePath(store, { filePath, title, content, project }) {
  // 포매터 해석, 파일명 생성, 경로 조합 — 공통 로직
  // saveMcpFile()과 mcpManualSave() 모두 이 함수를 호출
}

async function saveMcpFile(store, opts) {
  if (opts.noSave) return null;
  if (!store.get('mcpAutoSave', false)) return null;
  const savePath = store.get('mcpAutoSavePath', '');
  if (!savePath) return null;
  return await writeToPath(store, opts);  // 공통 저장 로직
}

async function mcpManualSave(store, opts) {
  const savePath = store.get('mcpAutoSavePath', '');
  if (!savePath) return { success: false, errorKey: 'viewer.saveErrorNoDir' };
  return await writeToPath(store, opts);  // 동일 공통 로직
}
```

이렇게 하면 파일명 생성, 포매터 해석, 디렉토리 생성, 파일 쓰기 로직이 한 곳에만 존재.

## 5. 키보드 단축키 — 기존 핸들러에 추가

### 기존 코드: `viewer.js:1665-1790`

단일 `keydown` 리스너 내에 모든 단축키가 등록되어 있다.

### 재활용 방법: 기존 리스너에 블록 추가 (새 리스너 등록하지 않기)

```javascript
// 기존 keydown 리스너 안에 추가할 블록:

// Ctrl+S: MCP manual save (FR-22-001)
if (mod && !e.shiftKey && !e.altKey && e.key === 's') {
  e.preventDefault();
  handleMcpSave();
  return;
}

// Ctrl+Shift+C: Copy path (FR-22-003)
if ((e.ctrlKey || e.metaKey) && e.shiftKey && e.key === 'C') {
  e.preventDefault();
  handleCopyPath();
  return;
}
```

**주의**: `Ctrl+S`는 `Ctrl+Shift+S`(Save As)보다 **뒤에** 배치해야 한다. Shift 체크 순서에 주의.
실제로는 `Ctrl+Shift+S`가 먼저 매칭되므로(e.shiftKey 체크) 순서 무관하나, `!e.shiftKey && !e.altKey` 가드를 명시한다.

## 9. 파일 탐색기 열기 — 기존 IPC 재활용

### 기존 코드

- Preload: `showFileInExplorer: (filePath) => ipcRenderer.send('show-in-explorer', filePath)`
- Main: `shell.showItemInFolder(filePath)` (index.js:856)

### 디렉토리용 확장

`shell.showItemInFolder()`는 **디렉토리에도 동작**한다 (디렉토리를 선택한 상태로 탐색기 열림).
따라서 **별도 `openDirectory` IPC가 불필요**할 수 있다.

검증 결과에 따라:
- `shell.showItemInFolder(dirPath)` → 부모 디렉토리에서 해당 폴더를 선택한 상태로 열림
- `shell.openPath(dirPath)` → 해당 디렉토리 내부를 직접 열림

사용자 기대: "파일 탐색기에서 열기" → 디렉토리 **내부**를 보여주는 것이 자연스러움.
따라서 디렉토리는 `shell.openPath()`, 파일은 기존 `shell.showItemInFolder()` 사용.

```javascript
// index.js 기존 핸들러 수정 (새 핸들러 추가 대신)
ipcMain.on('show-in-explorer', (event, filePath) => {
  if (!filePath) return;
  // 디렉토리 여부를 체크하여 분기
  try {
    const stat = fs.statSync(filePath);
    if (stat.isDirectory()) {
      shell.openPath(filePath);
    } else {
      shell.showItemInFolder(filePath);
    }
  } catch {
    shell.showItemInFolder(filePath);
  }
});
```

이렇게 하면 **`openDirectory` IPC를 새로 만들 필요 없음**. 기존 `showFileInExplorer()` API 하나로 파일/디렉토리 모두 처리.
