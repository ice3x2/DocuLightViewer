# Technical Decisions

## TD-1 — SQL aggregation instead of JS filtering

- Decision: active semantic job progress를 SQLite aggregate로 계산한다.
- Reason: 전체 row materialization과 recursive redaction이 실제 3,606 jobs에서 1초 이상 걸렸다.
- Rejected: `getIndexJobs({ status })`를 두 번 호출. job_type filter가 없고 여전히 row/object cardinality가 O(n)이다.

## TD-2 — Add a predicate/order index without schema-version bump

- Decision: `idx_index_jobs_type_status_updated(job_type, status, updated_at DESC, job_id)`를 idempotent하게 생성한다.
- Reason: 기존 설치 DB에도 안전하게 적용되고 query predicate를 직접 지원한다.
- Rejected: schema version 2 migration. additive index만으로 충분해 recovery/migration blast radius가 불필요하다.

## TD-3 — No whole-job fallback in SearchEngine

- Decision: aggregate API가 없으면 `null`을 반환한다.
- Reason: compatibility fallback이 다시 production freeze 경로를 열어두면 hotfix invariant가 깨진다.
- Consequence: custom/mock ledger는 새 API를 제공하도록 테스트를 갱신한다.

## TD-4 — Testable poll coordinator plus per-IPC single-flight

- Decision: pure/testable poll coordinator가 indexing/embedding refresh를 `Promise.allSettled`로 묶고 `finally`에서 다음 timeout을 정확히 한 번 예약한다. 각 IPC에도 Promise guard를 둔다. 별도 embedding `setInterval`은 삭제한다.
- Reason: 한 scheduler가 active/idle cadence를 결정하고 느린 IPC가 중복 호출로 증폭되지 않는다.
- Rejected: fixed 3 s embedding interval 유지. active 500 ms loop와 위상이 겹쳐 중복 요청이 남는다.

## TD-5 — Coalesce every nonterminal worker status, flush terminal/cancel

- Decision: timer status와 `onRebuildStatus`의 파일별 event를 공통 latest-value coalescer에 넣어 500 ms마다 최대 한 번 보낸다. terminal/cancel/failure 전에는 pending latest status를 flush하고 terminal event를 즉시 보낸다.
- Reason: timer만 늦추면 per-file rebuild callback이 throttle을 우회해 동기 SQLite write가 계속 폭증한다.
- Rejected: 완전한 change-only suppression. 긴 단계에서 durable heartbeat가 stale해질 수 있다.

## TD-6 — Preserve rebuild meaning, remove startup content retention

- Decision: full rebuild 후 active documents 전체 derived requeue는 유지한다.
- Reason: keyword 외 chunk/link/classification/HNSW derived state도 reset되므로 semantic disabled만으로 queue를 생략할 수 없다.
- 추가 결정: startup recovery는 검증용 content를 queue item에 저장하지 않고 known document identity와 verified content hash만 전달한다.
- Follow-up: 매우 큰 corpus의 producer job pagination/history retention은 별도 요구사항과 부하 시험 후 진행한다.

## TD-7 — Tests combine structural and measured evidence

- Decision: source contract assertions, actual temp SQLite aggregate, integration contracts를 함께 둔다.
- Reason: timing-only test는 CI 편차에 취약하고 source-only test는 production cardinality 회귀를 잡지 못한다.

## TD-8 — New regression tests are release-gated

- Decision: aggregate, poll concurrency, coalescing, lazy recovery tests를 `npm run test:wave2`에 포함한다.
- Reason: 기존 package smoke는 Settings와 large persisted backlog 경로를 실행하지 않아 이 회귀를 놓쳤다.
