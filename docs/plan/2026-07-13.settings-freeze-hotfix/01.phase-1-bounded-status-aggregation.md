## Expected RED

새 ledger method가 없고 SearchEngine이 `getIndexJobs({})`를 호출하므로 테스트가 실패해야 한다. 실패가 확인되기 전에 production 코드를 수정하지 않는다.

## Acceptance

- pendingCount와 sums가 exact하다.
- indexing job이 하나라도 있으면 state는 `indexing`, 아니면 `queued`이다.
- 반환 객체 크기는 job cardinality와 무관하다.
- existing `getIndexJobs` API는 다른 진단/테스트 호환을 위해 유지한다.
- 100,000 terminal/unrelated rows는 result와 JS intermediate cardinality를 늘리지 않는다.
- 기존 대형 temp history에서 index cold creation 시간도 기록하며 무제한 startup stall을 만들지 않는지 확인한다.
