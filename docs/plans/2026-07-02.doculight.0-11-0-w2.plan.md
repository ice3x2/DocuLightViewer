Implement DocuLight 0.11.0-w2 smart-search and knowledge-store lifecycle: SQLite source-of-truth ledger, shared redaction, embedding settings and governance, built-in HNSW degraded lifecycle, background indexing, persistent link graph with canonical broken-link diagnostics, no-viewer `save_document`, read-only `smart_search`, bounded local linked Markdown import, legacy knowledge-store adoption, and typed eight-tool MCP package conformance.

### 1.2 In Scope

- All non-discarded active target requirements for `0.11.0-w2`: 28 planned requirements plus verified Korean tokenizer compatibility `FR-DOC-023`.
- TDD contract tests before implementation.
- Settings-only indexing/model controls; no MCP indexing/import/reconciliation control expansion.
- HTTP MCP, stdio MCP, generated bundle, package smoke, and client-profile conformance.
- Local embedding endpoint tests may read `model-api.txt`; committed code and fixtures must not hard-code that endpoint or model.

### 1.3 Out Of Scope

- Changing the existing `search_documents` response contract into semantic search.
- Adding MCP tools for rebuild, clear, retry, cancel, status, model changes, recursive import, bulk scan, or broken-link reconciliation.
- Retrieval evaluation set implementation; it remains a roadmap item in `AGENTS.md`.
- Vendor-specific live LLM client benchmarks for MCP client-profile conformance.

### 1.4 Assumptions

- Wave 1 and Wave 1.5 foundations remain green.
- `hnswlib-node@3.0.0` is the default HNSW native candidate unless implementation evidence forces a new SRS decision.
- Broken links are non-blocking diagnostics. Only `resolved` edges can rank or satisfy `linkedTo`/`linkedFrom`.
- Existing dirty worktree changes are preserved; implementation tasks must not revert unrelated user edits.
