# S33 Windows PG-09 통합 증거

관련 이슈: #56. 요구사항: `IR-APP-013`, `REL-DOC-007`, `REL-DOC-009`, `OPS-ARCH-009/012/013`.

- 작성 브랜치의 제품·canary 커밋은 `1388078ae6ce78703417be7d141719bc91267836`, 작성 sourceHash는 `dd1ee26f184b4a72061578442e582b23e1917c5ae11fea35826265d2a244c2d3`이다. 서명 없는 Windows x64 portable SHA-256은 `ff50eecf53f527e5ffe6be34839f0bec58a17bb581134baab4f653c46e752cfb`이고 작성 worktree의 [불변 5회 원시 보고서](./p0-pg09-win32-x64-1388078-five-run.json)는 증거 커밋 `a8b6f7ced9247e7d63d0b3d06710e72533261987`에 보존됐다. 작성 worktree의 물리 보고서 SHA-256은 `46a4cf5e13f907c558720958f728690d644fe235acad51e00a7c735849f650e9`이다.
- 통합 커밋은 `f68b892`, `18dcc08`, `2782d91`, `15b6b5a0550ffeb9340be2e25899ba6474ebbce7`이다. 현재 Windows 통합 checkout sourceHash는 `fe1c96e4331f106851f1bbcdc5113bbd5e88efe2854fbf92ec741983e131ce4e`다. 작성 브랜치와 통합 브랜치의 #56 관련 Git blob은 같지만, 통합 checkout의 CRLF 작업 파일 바이트와 이후 `docs/spec`의 저장 용량 정책 AC 편집 때문에 전체 sourceHash가 다르다. 통합 checkout의 물리 보고서 SHA-256은 `6fe46c26412995bd6cb4c5d0c855601d4a16b43dad14540b471d36fde5231d3d`이며 작성 보고서와 같은 Git blob `7797058a8806af9f0b551ad2c72c9cc3b20077e2`을 가리킨다. 다섯 packaged 표본은 통합 커밋이 아니라 작성 제품 커밋 `1388078`의 실행 증거다.
- 작성 브랜치의 5/5 콜드 표본은 서로 다른 packaged 앱 PID·격리 프로필, 실제 owner worker 1개와 legacy/checker 0개, 동일 B: NTFS 볼륨의 `FILE_FLAG_NO_BUFFERING` 읽기/쓰기·정렬·체크섬, direct I/O 시작/종료와 상태·포커스·닫기·취소의 공통 단조 시각 교집합, 취소의 정확한 job 터미널 이벤트·영속 상태, 저장 파일과 완료된 linked import 보존을 기록한다. 상태 최대 **22.825ms**, 포커스 **20.101ms**, 닫기 **23.851ms**, 취소 **1.147ms**, 메인 heartbeat 최대 **48.810ms**로 원래 기준 이내다. 원시 실패 5/5 C: 보고서와 조기 종료 3/5 B: 보고서는 별도 역사 기록으로 보존했다.
- 통합 커밋에서 `node test/test-pg09-canary-contract.js`, `node test/test-p0-release-canaries.js`, `node test/test-package-native-owner-evidence.js`가 각각 exit 0이었다. 독립 검토는 작성 보고서의 해시·직접 I/O 마커·요청 겹침·소유 PID·종료와 역사 기록을 확인했다. 취소된 `index_jobs`의 durable `status=cancelled`, `cancel_requested=true`는 기록됐지만 `phase`는 null이므로 완료 phase를 주장하지 않는다. 이 Windows 결과를 macOS/Linux 또는 전체 릴리스 승인으로 확장하지 않는다.
