## Count and priority contract

Traversal checks cancel, lexical/canonical containment, visited identity, depth, file count, existence, byte budget, destination policy, read size, publication, and owner ACK in that order. Only confirmed `imported`, `updated`, or `existing` candidates consume cumulative bytes and file slots. A candidate whose publication fails contributes a stale/ambiguous diagnostic. A published candidate without a confirmed owner receipt contributes `unconfirmedCount` and `ack_unknown`, outside canonical edge status counts. `counts` records document outcomes and canonical edge statuses; `diagnosticCounts` records reasons such as `skipped_depth` and `skipped_total_bytes` independently.
