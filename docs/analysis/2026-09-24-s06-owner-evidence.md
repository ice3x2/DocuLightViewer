The case starts one persistent worker through `START(ownerConfig)`. The worker opens and integrity-checks the source ledger and keyword SQLite databases before READY. An audited real `better-sqlite3` constructor reports two opens on the same worker thread ID. A main-thread module-load probe sees zero SQLite loads during this new route. Concurrent read queries, cancel of an absent job, unknown type, duplicate ID, bounded/redacted cached STATUS, and shutdown rejection complete without hanging. The test seeds an already-completed import ledger identity and two Markdown files, terminates the worker, observes cached failure, restarts, and verifies the import identity and file bytes survived. A separate worker that exits during startup rejects with `owner_worker_failed`.

The restart sequence is monotonic across worker epochs and old worker events cannot overwrite a new worker's status. A committed keyword index built for another source root, or queried without a configured root, is marked stale before READY; queries return no old-root hits and no automatic rebuild starts. A missing committed keyword generation reports `keyword_index_missing` while the owner remains live. The START ownerConfig passes `keywordTokenizerProvider` (default `garu`) and `keywordTokenizerMaxAnalysisChars`; the worker initializes the same real tokenizer used by SearchEngine before checking committed metadata. A real garu cache remains queryable, while a true provider mismatch remains stale. Controller `query('get_status')` returns the same canonical snapshot and monotonic sequence as `getStatus()` after restart.

Malformed request IDs settle with `owner_invalid_id` before `postMessage`. After a worker `error`, restart waits for that specific worker to exit before creating a replacement; late old-worker events are ignored. `CANCEL{id,target}` places `target` at the envelope top level, and `COMMAND{id,type=shutdown}` returns a RESULT correlated to the caller's ID.

Raw worker tests also cover unknown type, duplicate in-flight ID, CANCEL and SHUTDOWN RESULT correlation. A concurrent controller query plus shutdown settles both promises, does not create a second owner, and rejects a later query with `owner_shutdown`. SHUTDOWN is terminal at the raw port; messages sent after it are outside the supported wire lifetime.

Private `resolve_origin` forwards either `documentId` or indexed `filePath` to the existing read-only S05 ledger lookup; the real fixture resolves the same document ID, `indexedPathInternal`, `sourceRootInternal`, and `sourceRelativePath` by both selectors. Path comparison accounts for the ledger's Windows lowercase normalization. It does not add a public path field.

`accept_save` is present in the single private type registry and currently returns stable `owner_not_implemented`; S08 owns its durable ingress, atomic publication, and two-save write workload. S07 owns read scheduling. Current tests therefore establish the lifecycle/protocol and connection owner for the new route, but do not prove post-save write routing or the product-wide sole-writer state. No public MCP tool or response contract changed. Independent [architecture review](2026-09-24-s06-architecture-review.json) and [TDD/runtime review](2026-09-24-s06-tdd-review.json) passed with no remaining findings; the original pre-implementation RED transcript/source snapshot was not archived, so historical test-first chronology is author-reported rather than independently reconstructable from this final tree.
