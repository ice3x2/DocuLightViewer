A later test-first CAS assertion exited **1** with `ASSERTION_FAIL case=s11 assertions=9 completion CAS rejects wrong actual hash and retains retryable F`; the fix leaves the current document dirty when a wrong actual hash rejects completion.

After source-only refresh, `node test/r3/run-node.cjs --case s11` first reached **0** with `PASS case=s11 assertions=16`. The fixture uses awaited publish/accept callbacks as barriers and no fixed sleeps. It proves A processing followed by B save, B processing followed by C save, stale terminal jobs unable to complete or clear the newest pending revision, changed file after ACK becoming a new desired revision, repeated observation of the same stale claim staying at that revision, wrong-hash completion rejection, cancel and failure preserving the saved file and retryable work, and restart retry completing from the file. ## Independent review repair

Two reviewers identified a real gap between the final same-handle read and SQLite completion: a cooperative S08 publisher in another process could replace the file in that interval. A test hook placed at that exact interval produced **exit 1**, `ASSERTION_FAIL case=s11 assertions=16 root publication gate keeps A file current through final-read completion CAS`. The hook starts a separate child process that calls the actual S08 `publishSave`; the child reports that it has begun its attempt. `runClaimedDesiredJob` now holds the same root-wide `.publication.lock` used by S08 from the final contained read through the short completion transaction. The child publisher waits for that gate, so its new file becomes a later desired revision and pending job. This is a cooperative publisher guarantee; the test does not claim atomicity against an unrelated OS actor that ignores the gate.

The completion CAS originally cancelled a same-claim job with a wrong actual hash but left `current_job_id` pointing at that terminal job. The added discovery assertion produced **exit 1**, `ASSERTION_FAIL case=s11 assertions=9 completion CAS rejects wrong actual hash and retains retryable F`. The owner now queues a fresh retry in the same transaction for current-job completion rejection, failure, or cancellation; the latest pending page enumerates it. A separate `cancel_requested` assertion produced **exit 1**, `ASSERTION_FAIL case=s11 assertions=12 same-claim cancel_requested cannot complete and leaves G retryable`. The processor checks cancellation before downstream work and before completion, and the ledger CAS also requires `cancel_requested=0`.

An abruptly interrupted claim previously remained `indexing` with `dirty=0`, invisible to pending-page enumeration. The test created that exact persisted state, then produced **exit 1**, `ASSERTION_FAIL case=s11 assertions=18 abrupt indexing claim has owner startup recovery contract`. The single owner now reconciles bounded pages on startup: it marks an interrupted current claim failed and queues a retry, while an older interrupted claim is cancelled without replacing a newer current job. The real owner restart test checks both outcomes and preservation of saved Markdown. A genuine latest completion also asserts an empty pending page.

The focused S09 regression exits **0**, `PASS case=s09 assertions=37`. The first S10 regression run exited **1** at assertion 24, `owner retries a transient startup acceptance failure without a caller re-save`. The assertion observed no matching recovered row within its 200 × 10 ms poll; the test did not record the worker attempt state, so the run alone could not distinguish a missed retry from a delayed attempt. A repeat exited **0**, `PASS case=s10 assertions=46` in 4.90 seconds. Inspection showed that the S10 fixture waited a fixed 100 ms before removing its fault trigger and then polled the row, without establishing that the worker had attempted and failed while the trigger was active. The owner replay path schedules another attempt after failure. The fixture now uses test-only `STATUS` phase events on the existing wire tag as barriers for the failed attempt and later successful replay. It drops the trigger only after the failed attempt and reads SQLite only after the accepted event. Following source-only refresh, this targeted S10 test exits **0**, `PASS case=s10 assertions=46` in 3.57 seconds. No product replay timing or public wire type changed. A missed retry remains detectable by the bounded R3 harness instead of being hidden by a poll deadline.

The new startup behavior made one S10 assertion about keeping an interrupted job active obsolete; it failed at assertion 11. The S10 regression fixture now asserts that startup retires that job, preserves the newer dirty revision and saved file, and leaves no active interrupted job. A later independent review found that the recovery query included every `indexing` job. The S11 fixture inserted a real `keyword_rebuild` job and produced **exit 1**, `ASSERTION_FAIL case=s11 assertions=23 document recovery never mutates unrelated keyword rebuild indexing job`. Recovery now selects only `job_type='index_document'`. The separate publisher child disconnects in a `finally` block, including assertion failure; a read-only process scan after the case found no live `s11-publisher.cjs` process.
