# S05 read-only origin selection evidence

Issue [#28](https://github.com/ice3x2/DocuLightViewer/issues/28) starts at `f29e34fbd401806ba30bfe2deaaaa2c66f79a036` on `feature/issue-24-s01-sol-medium`. Requirements `FR-DOC-036` AC-1–12, `DR-DOC-014` AC-1/4–7, and `IR-MCP-019` apply. All three are `in_progress/evolving` in `docs/spec/`; no draft/deprecated gate applies. The S04 handoff in [#27](https://github.com/ice3x2/DocuLightViewer/issues/27) states that the public `findDocumentSourceAliasByCanonicalPath` remains `LIMIT 1` and cannot select all aliases.

The focused `test/r3/cases/s05.cjs` creates two real lexical directory junctions to one canonical original and a separate contained indexed copy. After ledger initialization and fixture writes, it retargets the first ordered alias to another directory. It snapshots full source-ledger SQLite file bytes, SQLite sidecar bytes if present, fixture file contents/link targets, and document/alias/job rows around each resolver call. The measured resolver calls do not run ledger startup migration. The fixture then checks changed original content, 10 MiB+1 original, simulated `EACCES`, missing originals, missing copy, and a hash-only legacy alias. Selection fields and stable failure messages contain no raw fixture path. Existing same-handle/TOCTOU, viewer, HTTP/stdio/bundle contract assertions remain in `test/test-indexed-origin-open-contract.js`.

Before product code changed, the case was registered in both Node runner lists and the source-only snapshot was refreshed using the existing Node ABI 137 and Electron ABI 130 roots. `node test/r3/run-node.cjs --case s05` exited **1**, `ASSERTION_FAIL case=s05 assertions=1 a valid second lexical alias wins after the first alias retargets`. This was a real SQLite/resolver selection failure, not an unknown case, fixture error, or native ABI error. The first resolver revision then exited **0**, `PASS case=s05 assertions=5`.

The case gained further assertions. One intermediate run returned `SETUP_ERROR` because the test fixture omitted `documents.canonical_path_hash` required for indexed `filePath` lookup; adding `canonicalPathInternal: copy` fixed the fixture. Another intermediate assertion failure revealed the test expected `read_failed` from the second candidate while the first was still retargeted; the junction was restored before the oversized check. Neither result is counted as the initial TDD RED. The final source-only refresh took about one second and `node test/r3/run-node.cjs --case s05` exited **0**, `PASS case=s05 assertions=23` (Node v24.16.0, ABI 137, Windows x64).

The existing `node test/test-indexed-origin-open-contract.js` initially failed at line 275 on `non-null lexical origin is immutable across alternate-path reopen`: it assumed one alias after a second lexical path was registered, which conflicts with S04's approved 1:N ledger. Its oracle now checks two separate alias IDs, both lexical paths, and their shared canonical target. It preserves both aliases in the later hash-only fixture using distinct hashes. Another run exposed the deterministic failure-status choice when one alias was missing and the other denied; a fixed priority now reports `unreadable` over `missing` and `path_mismatch` over either. The generated MCP bundle was absent in the isolated worktree, so `npm run bundle:mcp` created the ignored local artifact required by that existing test. After the oracle adjustment and bundle generation, the existing contract test exited **0**, `test-indexed-origin-open-contract: all assertions passed`. No public tool or response field changed.

Implementation: the internal ledger owner lookup reads all aliases ordered by completeness, update time, and alias ID, returning a private `originCandidates` array with per-alias fingerprint data and one indexed copy locator. The resolver validates each candidate with the existing bounded same-handle reader and returns the first validated original. If none validates, it reads the contained copy and reports a deterministic failure status; if that also fails, the existing `indexed_document_unavailable` error is retained. Search, registrar, viewer, and worker protocol paths were not changed. Independent [origin security review](2026-09-24-s05-origin-review.json) and [TDD/compatibility review](2026-09-24-s05-tdd-review.json) passed with no remaining finding; the author's original pre-implementation RED transcript was not archived, so that chronology is not independently reconstructable from the final tree.
