- Production route: main-process `searchEngine.getSaveDocumentOwner` lazily creates one `OwnerWorkerController` for the configured lexical document root, its validated equivalent canonical publication root, and same-volume private ingress. HTTP and stdio IPC `save_document` call the shared adapter. That adapter validates the existing strict input, builds frontmatter, publishes through S08 with a new-save vacancy guard, calls owner `acceptPublishedSave`, and maps only an accepted queued receipt into the canonical response. Main does not call its old SQLite queue on this save path.
- Preserved file behavior: if publication succeeds and acceptance fails or is cancelled, the Markdown remains in the store, the private intent remains for retry, and the response has `saved=true`, `indexing.state=enqueue_failed`, `warnings[{code=index_enqueue_failed,...}]`, and no `jobId`. An owner receipt replay returns the same document ID, desired revision, and job ID. A fault before publication returns `saved=false`.
