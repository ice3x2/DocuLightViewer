# S21 Settings action gate follow-up

Issue: #44. Requirements: `IR-APP-013` AC-3/4/11/13/15, `REL-DOC-008` AC-3, `FR-APP-006`, `FR-APP-007`. Active target: `0.11.0-w2`. Base: `67680f0`. Standard R3 source hash: `bd2209c0583a3f11ea6f70e35341dec3d8ca867d544b113297d19a68f8d65331`.

The real Electron S21 scenario first failed assertion 14 because a legacy rebuild plus cached owner `READY` enabled Rebuild and Compact. A registry assertion then failed because an active owner `rebuilding` snapshot mapped to `COLD` instead of `KEYWORD_REPAIRING`; the Electron owner action assertion failed too. Subsequent Electron assertion failures caught owner clear wrongly enabling Cancel, owner degraded Retry losing keyboard focus after its private IPC result, and owner full rebuild wrongly enabling visible Stop. Independent review then found a private IPC bypass: a direct Settings cancel during owner clear still reached the owner. The actual extracted private handler invoked through Electron IPC failed assertion 29 before the handler rejected it. Another real Electron RED failed assertion 26 because a retained failed count enabled Retry during an active owner document job. The final real Electron scenario passed 35 assertions on Windows x64, Electron 33.4.11, ABI 130.

Settings now disables Rebuild/Compact while legacy indexing runs even when the owner is READY. Owner `rebuilding` maps to `KEYWORD_REPAIRING` in the private canonical registry. The cached Settings payload adds a boolean `ledgerOwnerActive` without a DB query or public MCP field. Owner document indexing can use the existing private Cancel path and retains focus; full owner and legacy rebuilds keep visible Stop disabled under `REL-DOC-008` AC-3, and owner clear does not offer Cancel under the P0 matrix. The private Settings handler now rejects direct Cancel for active owner clear or rebuild with a false response and does not call the owner; direct owner cancellation remains available to internal maintenance tests. Owner keyword degradation (`READY_KEYWORD_DEGRADED`) offers the existing private owner Retry route, retaining focus and reporting the actual result. An active owner document job suppresses Retry even when legacy failedCount remains positive. No locale keys changed.

At the same source hash, real Node S23 passed 45 assertions, including actual private Settings owner Retry after a failed rebuild starting and completing a durable job. The registry, Settings indexing, Settings poller, status coalescer, Wave 2 MCP, and embedding removal contracts passed. The ko/en/ja/es locale files each have the same 270 keys. Real Electron S26 passed 49 assertions: main-process writable SQLite opens were zero, and status, focus, and close did not increase the main SQLite open count. Its final-hash raw result is retained in `docs/analysis/2026-09-25-s21-s26-bd2209c0583a3f11ea6f70e35341dec3d8ca867d544b113297d19a68f8d65331-raw.json`; the historical S26 sample remains unchanged. `git diff --check` passed.

`IR-APP-013` AC-15 also requires `retry-check` in `CORRUPT_DEGRADED` and `INTERRUPTED`. The owner has no retry-check command or dispatcher: its command registry and worker dispatch contain only manage-index, save/adoption, and shutdown operations, while health checks run during START. A failed START closes the DBs and worker port. `manage_index('retry')` is a keyword rebuild admitted only after recovery and is not a safe substitute for retry-check. AC-15 and the larger Cartesian/release gates remain unverified; #44 must stay open. This follow-up does not mark the requirement verified, commit, push, or mutate GitHub.
