## 1. Purpose

DocuLightViewer의 코드 역추출 baseline SRS와 후속 smart-search 요구사항을 관리한다. 현재 후속 목표는 두 Wave와 중간 Wave 1.5로 나뉜다. 0.11.0-w1은 MCP 저장/검색 인덱싱 기반 안정화이고, 0.11.0-w1.5는 Wave 2 전에 단일 JSON BM25 인덱스를 SQLite FTS5 기반 keyword derived cache로 대체한다. 0.11.0-w2은 SQLite 원장, background indexing, embedding, HNSW 파생 인덱스, persistent link graph, document-only save_document MCP 도구, bounded local linked-Markdown import, read-only smart_search MCP 도구를 도입한다.

## 9. Design Decisions

| ID | Decision | Impact | Status |
|---|---|---|---|
| DD-SMART-001 | smart_search v1 returns canonical JSON in MCP `content[0].text`; `structuredContent` is deferred until the runtime and target MCP clients require it. | MCP client compatibility and conformance fixtures | closed |
| DD-SMART-002 | Native default candidate is `better-sqlite3 + hnswlib-node`; an alternative requires an explicit SRS change with packaging and HNSW behavior evidence. | CI matrix, asarUnpack, rebuild/prebuild strategy | closed |
| DD-SMART-003 | Package smoke is release-gating for Windows x64, macOS arm64, and Linux x64; Windows arm64, macOS x64, and Linux arm64 are best-effort until CI capacity is confirmed. | Release workflow cost and support policy | closed |
| DD-SMART-004 | clearSearchIndex is settings-only, requires user confirmation plus backup/recovery warning, and must never be exposed as an MCP tool. | Data loss prevention and Settings UI confirmation design | closed |
| DD-SMART-005 | Raw absolute path is internal-only for canonicalization and containment; duplicate prevention uses source identity ledger keys and stable `documentId`, not destination path or content hash alone. | Linked local import deduplication, redaction, and move/copy ambiguity handling | closed |
| DD-SMART-006 | Existing Markdown already inside the knowledge-store root is indexable as a legacy knowledge-store document without rewrite; broken links are stored as missing/diagnostic edges rather than treated as indexing failure. | Legacy adoption, link graph reconciliation, and smart_search diagnostics | closed |
| DD-SMART-007 | Broken Markdown link edges use a canonical lifecycle: non-resolved statuses are non-blocking diagnostics, only `resolved` edges participate in link ranking and linkedTo/linkedFrom filters, raw href/path values remain internal-only, and save_document may only feed ordinary background indexing rather than MCP reconciliation controls. | Link graph indexing, smart_search ranking, diagnostics, and MCP non-expansion policy | closed |
| DD-SMART-008 | Wave 2 MCP tool usability is verified through deterministic client-profile fixtures, not vendor-specific adapters or live multi-vendor model benchmarks. | Keeps Codex/Claude Code/OpenCode/OpenClo/Hermes-style compatibility testable without adding tools | closed |
