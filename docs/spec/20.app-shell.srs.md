## 1. Scope Overview

이 문서는 DocuLight 메인 프로세스의 셸 계층을 정의한다. Electron 앱 생명주기, 단일 인스턴스 락, 시스템 트레이, ndjson 기반 IPC 소켓 서버(Named Pipe / Unix socket), electron-store 설정 관리, preload contextBridge API, i18n 로케일 로딩, Windows `.md` 파일 연결을 포함한다.

## 2. Scope Boundaries

### In Scope

- 앱 생명주기, 단일 인스턴스 락, 시스템 트레이
- ndjson IPC 소켓 서버 및 action 핸들러 라우팅
- electron-store 설정 스키마와 get/save 핸들러
- preload contextBridge API (window.doclight)
- i18n 로케일 로딩 (ko/en/ja/es)
- Windows `.md` 파일 연결 등록/해제
- 최근 파일 목록, zoom, always-on-top IPC

### Out of Scope

- BrowserWindow 생명주기 세부 (WIN)
- MCP 도구 핸들러 비즈니스 로직 (MCP)
- 렌더러 UI 동작 (RENDER)
- 문서 저장/검색 로직 (DOC)

## 3. Assumptions and Constraints

- Windows에서는 Named Pipe `\\.\pipe\doculight-ipc`, Unix에서는 `/tmp/doculight-ipc.sock`(0o600)를 사용한다.
- 설정은 `%APPDATA%/doclight/config.json`(Windows)에 저장한다.
- 로케일은 CLI 인자 `locale <lang>` 또는 `DOCULIGHT_LOCALE` 환경변수로 override 가능하다.

#### Requirement

시스템은 일반 앱 실행(개발 모드와 패키징된 앱 모두)에서 이미 실행 중인 인스턴스가 있을 때 두 번째 인스턴스가 single instance lock 획득에 실패하면 즉시 종료해야 하고, 1차 인스턴스는 second-instance 이벤트의 argv에서 .md 경로를 추출하여 해당 파일을 열거나 경로가 없으면 기존 뷰어 창에 포커스를 주고 창이 없으면 빈 뷰어를 열어야 한다. 단, package smoke 전용 실행은 독립 smoke 루틴을 위해 lock을 우회할 수 있다.

#### Rationale

트레이 상주형 단일 인스턴스 앱으로서 OS 가 .md 파일을 외부에서 열 때 기존 프로세스로 위임해야 중복 실행과 창 난립을 막는다. 개발 모드도 고정 named pipe, userData cache, tray 리소스를 공유하므로 다중 인스턴스를 허용하면 IPC EADDRINUSE와 Electron cache lock 충돌이 발생할 수 있다.

#### Acceptance Criteria

- [ ] AC-1: app.requestSingleInstanceLock() 가 false 를 반환하면 app.quit() 이 호출된다.
- [ ] AC-2: second-instance 핸들러가 extractMdPathsFromArgv(argv) 로 .md 경로를 추출하여 openFileFromPath 로 각 파일을 연다.
- [ ] AC-3: .md 경로가 없고 열린 창이 있으면 첫 창을 restore/focus 하고, 창이 없으면 createEmptyWindow() 를 호출한다.
- [ ] AC-4: 개발 모드는 single instance lock을 우회하지 않으며, package smoke 전용 실행만 gotTheLock=true로 lock을 우회할 수 있다.
- [ ] AC-5: npm run dev/start preflight는 native rebuild 또는 Electron launch 전에 기존 DocuLight IPC server 연결 가능 여부를 확인하고, 활성 인스턴스가 있거나 IPC 확인이 timeout되면 종료 방법을 안내한 뒤 Electron을 시작하지 않는다.

사용자는 다시 만들기가 삭제 후 재작성 의미를 갖기 때문에 별도 삭제 버튼이 중복이고 혼란스럽다고 지정했다. 기존 IR-APP-010은 verified Wave 1 요구사항이므로 직접 변경하지 않고 Wave 2 follow-up 요구사항으로 사용자-facing UI를 supersede한다.

#### Acceptance Criteria

- [ ] AC-1: 검색 인덱스 관리 화면에는 indexing-clear-btn 또는 동등한 삭제 버튼이 존재하지 않는다.
- [ ] AC-2: Settings renderer는 clearSearchIndex()를 호출하지 않고 삭제 확인 대화상자를 표시하지 않는다.
- [ ] AC-3: 검색 인덱스 다시 만들기 버튼 설명은 문서 저장소를 다시 읽어 검색 파생 상태를 처음부터 다시 만든다는 의미를 유지한다.
- [ ] AC-4: stdio와 HTTP MCP tools/list에는 rebuild, clear, cancel, retry, status 계열 indexing control tool이 추가되지 않는다.

#### Requirement

시스템은 renderer가 제한된 preload IPC를 통해 Mermaid 또는 이미지 전용 media viewer 창 열기와 다운로드를 요청할 수 있게 해야 한다. main process는 media viewer를 sandboxed, context-isolated BrowserWindow로 독립 생성해야 하며, 부모 Markdown viewer가 닫혀도 media viewer는 닫히지 않아야 한다. 부모 viewer의 always-on-top 상태가 변경되면 연결된 media viewer 창도 같은 상태로 갱신되어야 한다.

#### Rationale

전용 media viewer는 Markdown viewer의 보조 창이지만 부모 창 close에 종속되면 사용자가 확대한 그래프나 이미지를 계속 확인할 수 없다. 반대로 always-on-top 상태는 사용자가 현재 viewing mode로 선택한 창 정책이므로 main process에서 연결 media viewer에 동기화해야 한다.

#### Acceptance Criteria

- [x] AC-1: preload는 renderer에 media viewer open 요청, media viewer payload 수신, media asset download 요청을 위한 제한된 IPC bridge를 제공한다.
- [x] AC-2: main process는 media viewer BrowserWindow를 `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`로 생성하고 local preload만 사용한다.
- [x] AC-3: media viewer BrowserWindow는 Markdown viewer의 Electron `parent` child window로 생성되지 않아 부모 close에 의해 자동 close되지 않는다.
- [x] AC-4: main process는 parent viewer window id와 linked media viewer window id registry를 유지하고 media viewer close 시 registry를 정리한다.
- [x] AC-5: 부모 Markdown viewer가 닫혀도 열린 media viewer 창은 닫히지 않고 마지막 payload와 pin state를 유지한다.
- [x] AC-6: 부모 Markdown viewer의 always-on-top 상태가 toggle, set, release 동작으로 변경되면 연결된 media viewer 창들에도 같은 값이 적용된다.
- [x] AC-7: 부모 Markdown viewer가 이미 닫힌 뒤에는 media viewer가 마지막 inherited always-on-top 상태를 유지하고 stale parent reference 때문에 예외를 던지지 않는다.
- [x] AC-8: media viewer open/download IPC는 raw absolute local path, remote credential, unsafe network error detail을 renderer-visible response에 포함하지 않는다.
- [x] AC-9: media viewer 창 title과 user-visible error/status text는 기존 strings payload/API와 ko/en/ja/es locale key를 사용한다.
