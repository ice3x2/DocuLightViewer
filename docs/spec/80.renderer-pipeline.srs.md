## 1. Scope Overview

이 문서는 DocuLight 렌더러 UI와 마크다운 렌더링 파이프라인을 정의한다. marked 파싱부터 DOMPurify 정화, heading ID 생성, 이미지 resolve, Mermaid 렌더, highlight.js 적용, TOC 생성에 이르는 파이프라인과 테마, 설정 UI, 탭 멀티문서, 사이드바 파일 검색, PDF export, 이미지 경로 resolve를 포함한다.

## 2. Scope Boundaries

### In Scope

- 마크다운 렌더링 파이프라인 (marked → DOMPurify → heading IDs → images → mermaid → highlight → TOC)
- 라이트/다크 테마와 코드 테마 적용
- 설정 편집 UI (settings)
- 탭 기반 멀티문서 뷰 (tab-manager)
- 사이드바 파일 검색/필터 (sidebar-search)
- PDF export 모달 UI (pdf-export-ui)
- 상대 이미지 경로 resolve (image-resolver: file:// → data URI)
- 컨텍스트 메뉴, 찾기, 줌

### Out of Scope

- 메인 프로세스 IPC 핸들러 (APP)
- 사이드바 트리 빌드 알고리즘 (TREE)
- BrowserWindow 생명주기 (WIN)

## 3. Assumptions and Constraints

- marked v17은 heading ID를 생성하지 않으므로 렌더 후 slug 기반 ID를 부여한다 (CJK 지원).
- DOMPurify는 USE_PROFILES html 프로필 + details/summary 태그 허용으로 정화한다.
- 렌더러는 contextIsolation/sandbox 환경에서 contextBridge API만 사용한다.
- 탭 기능은 enableTabs 설정으로 제어한다.

| Field | Value |
| --- | --- |
| Type | functional |

#### Requirement

시스템은 사용자가 뷰어 안에서 로컬 Markdown 링크를 따라 이동한 방문 경로를 뷰어 상단의 얇은 breadcrumb navigation bar로 표시해야 한다. 같은 문서를 반복 방문한 경우도 방문 순서대로 보존해야 하며, breadcrumb의 이전 항목을 클릭하면 해당 문서를 렌더링하고 표시 trail은 선택 항목까지 truncate해야 한다. 긴 trail은 줄바꿈하지 않고 bar 내부에서 가로 스크롤로 탐색할 수 있어야 한다.

#### Rationale

기존 history back/forward는 숨은 상태라 사용자가 링크로 이동한 문맥을 한눈에 볼 수 없고, 긴 문서 그래프를 따라갈 때 현재 위치와 이전 방문 경로를 빠르게 되짚기 어렵다. 상단 breadcrumb는 링크 traversal 문맥을 시각화하고 중간 지점으로 즉시 돌아가는 경량 navigation affordance를 제공한다.

#### Acceptance Criteria

- [x] AC-1: 로컬 Markdown 링크 이동 시 breadcrumb trail에 새 문서를 append하고, 같은 문서를 반복 방문해도 중복 제거하지 않는다.
- [x] AC-2: trail 길이가 2 이상이면 뷰어 상단 본문 위에 28-32px 높이의 옅은 회색 breadcrumb navigation bar를 표시한다.
- [x] AC-3: breadcrumb는 문서 항목 사이에 > 구분자를 표시하고, 마지막 항목은 현재 문서로 aria-current 상태를 가진다.
- [x] AC-4: 이전 breadcrumb 항목을 클릭하거나 키보드로 활성화하면 해당 문서를 렌더링하고 trail은 선택 항목까지 truncate한다.
- [x] AC-5: 외부 URL, anchor-only link, javascript/data 등 위험 스킴, missing file, non-Markdown target, 권한 오류처럼 실패하거나 문서 이동이 아닌 navigation은 trail을 변경하지 않는다.
- [x] AC-6: 긴 breadcrumb trail은 줄바꿈하지 않고 bar 내부에서 horizontal overflow와 하단 가로 스크롤로 탐색할 수 있다.
- [x] AC-7: content-only, empty window, PDF export mode에서는 breadcrumb bar가 숨김 또는 empty trail 상태로 동작하여 렌더링 본문과 PDF 출력에 섞이지 않는다.

- [x] AC-9: breadcrumb label, segment aria-label, current aria-label은 ko/en/ja/es locale key를 통해 제공된다.

#### Acceptance Criteria

#### Research / Analysis

- 현재 viewer.js는 렌더 완료 후 미디어를 wrapper로 감싸 확장 버튼만 추가하고 viewer.css는 max-width:100%만 적용한다. CSS transform은 문서 흐름과 실제 레이아웃 크기가 어긋나므로 제외한다. wrapper에 본문 폭 기준 퍼센트 상태를 두고 ResizeObserver로 본문 폭과 표시 높이 변화를 관찰하는 방식을 채택한다.

#### Implementation Notes

- TDD로 인라인 sizing/toolbar 계약과 Electron E2E를 먼저 실패시킨다. 각 wrapper는 currentPercent, autoFitPercent, userAdjusted 상태를 관리하고 width를 퍼센트로 반영한다. 초기 비율은 min(100, 높이 90%를 만족하는 비율)이며 수동 단계는 10%p다. 기존 media-viewer 창 코드는 변경하지 않는다.
- [2026-07-10] `현재 문서 표시 영역 높이`는 breadcrumb, tab bar, sidebar를 제외한 문서 scroll viewport인 `#viewer-container.clientHeight`로 정의한다. autoFitPercent는 높이 제한을 넘지 않도록 0.01% 단위로 내림한다. minPercent는 `min(25, autoFitPercent)`이고, 확대는 `min(100, currentPercent + 10)`, 축소는 `max(minPercent, currentPercent - 10)`으로 계산한다. 예를 들어 autoFitPercent가 18.43이면 확대 후 28.43, 다시 축소하면 18.43이다. disabled 경계 비교 허용오차는 0.01%다.
- [2026-07-10] `현재 문서 본문 폭`은 `#content` 내부에서 미디어가 배치되는 가용 block formatting context의 폭으로 정의한다. 최상위 미디어는 `#content` 폭과 같고, table/list/blockquote 등 중첩 미디어는 직접 parent block 폭을 사용하여 컨테이너 침범을 방지한다. autoFitPercent가 0.01% 이상이면 0.01% 단위로 내림하고, 0.01% 미만이면 높이 90% 제한을 지키도록 계산된 원시 양수 비율을 보존한다.

#### Requirement

시스템은 인라인 Markdown 이미지와 Mermaid 결과의 hover/focus toolbar를 각 미디어의 상단 Y 좌표에 맞추되, toolbar의 우측 경계를 현재 문서 본문 컨테이너(#content)의 우측 경계에 맞춰 표시해야 한다. toolbar는 미디어 wrapper의 자식으로 유지하여 hover/focus 및 keyboard 접근성을 보존하고, 본문 또는 wrapper 레이아웃 변경 시 위치를 다시 계산해야 한다.

#### Rationale

높이가 긴 미디어는 자동 맞춤으로 문서 폭보다 좁아질 수 있다. 이때 조작 버튼을 미디어 내부 좌측 상단에 겹치면 내용 가독성이 낮아지므로, 같은 Y 위치의 문서 우측 끝으로 분리해 표시한다.

#### Acceptance Criteria

- [x] AC-1: 인라인 image와 Mermaid 각각에서 toolbar의 상단은 해당 media wrapper의 상단과 같은 Y 좌표(허용 오차 1 CSS px)에 놓이고, toolbar의 우측 경계는 #content의 우측 경계(허용 오차 1 CSS px)에 맞는다.
- [x] AC-2: 자동 맞춤 또는 수동 축소로 media wrapper가 #content보다 좁아질 경우 toolbar는 미디어의 우측 밖, 같은 Y 좌표의 문서 우측 끝에 표시된다. media wrapper가 본문 폭 100%이면 문서 우측 경계와 미디어 우측 경계가 같으므로 toolbar는 그 모서리에 표시된다.
- [x] AC-3: toolbar는 media wrapper의 DOM 자식으로 유지되며 wrapper hover, toolbar hover, keyboard focus-within에서 표시되고 기존 새 창 열기·축소·확대 기능, 순서, aria/title locale 및 disabled 동작을 유지한다.
- [x] AC-4: 문서 본문 폭, viewport 크기 또는 media wrapper의 레이아웃 위치가 변경되면 image와 Mermaid toolbar 모두 새 #content 우측 경계에 재정렬되며 문서 본문 크기나 미디어 비율을 변경하지 않는다.
- [x] AC-5: 전용 media viewer와 PDF export는 기존 동작을 유지한다.

- 현재 toolbar는 `.media-expand-wrapper`의 position:relative 안에서 top:6px; left:6px로 배치되어 있다. `right` offset을 wrapper 기준으로 계산하면 toolbar가 wrapper의 DOM 자식인 상태로 #content 우측 경계에 고정되어 hover/focus propagation을 보존한다.

#### Implementation Notes
