## 1. Scope Overview

이 문서는 DocuLight 사이드바 트리 빌더(link-parser.js)와 smart-search용 Markdown link graph 추출 계약을 정의한다. 마크다운 링크/위키링크 기반 runtime tree와 파일시스템 디렉토리 트리를 각각 만들고, 두 트리를 병합하여 디렉토리 트리에서 링크된 노드를 마킹한다. 0.11.0-w2에서는 기존 사이드바 동작을 보존하면서 outgoing link, backlink, broken link, anchor 상태를 persistent graph로 저장할 수 있어야 한다.

## 2. Scope Boundaries

### In Scope

- 링크 기반 트리 빌드 (buildLinkTree)
- 디렉토리 트리 빌드 (buildDirectoryTree)
- 병합 트리 빌드 (buildSidebarTree)와 linked-node 마킹
- 마크다운 링크/위키링크 추출 (extractMarkdownLinks)
- 파일명 정렬 (compareFileNames)
- 트리 한계치 (MAX_DIR_FILES, MAX_TREE_FILES, MAX_DEPTH)
- smart-search indexing-only link extractor contract
- persistent link graph edge fields, resolve status, backlink/broken-link diagnostics

### Out of Scope

- 트리 로드 오케스트레이션과 스트리밍 전송 (WIN)
- 사이드바 렌더링/표시 (RENDER)
- link graph ranking weight와 SQLite schema ownership (DOC)

## 3. Assumptions and Constraints

- MAX_DIR_FILES = 65535, MAX_TREE_FILES = 65535, MAX_DEPTH = 10.
- `.md` 파일만 트리 노드로 포함한다.
- 트리 노드는 재귀 구조 { name, path, children[], isLinked } 를 따른다.
- smart-search link graph indexing은 sidebar tree 출력 구조를 변경하지 않는 별도 indexing-only path로 확장한다.

#### Requirement

시스템은 시작 파일의 마크다운 링크를 추출하여 각 링크 대상 파일을 재귀적으로 따라가며 링크 기반 트리를 구성해야 한다. 시스템은 각 노드의 제목을 frontmatter title, 첫 H1, 파일명 순으로 결정하고, visited 분기 셋과 globalSeen 셋으로 순환 참조와 중복 확장을 방지해야 한다.

#### Acceptance Criteria

- [ ] AC-2: 노드 title은 frontmatter title 매칭이 있으면 그 값, 없으면 첫 H1(^#\s+) 매칭, 둘 다 없으면 path.basename을 사용한다 (L262-L270)
- [ ] AC-3: 정규화 경로가 visited 셋에 이미 있으면 순환 참조로 간주하여 null을 반환한다 (L250-L251)
- [ ] AC-4: globalSeen 셋에 이미 있는 경로는 children이 빈 leaf 노드로 반환하여 중복 확장을 방지한다 (L284-L288)
- [ ] AC-5: 파일 읽기에 실패하면 exists 가 false 인 노드를 반환한다 (L255-L259)
- [ ] AC-6: frontmatterName 은 name 필드가 있으면 그 값을, 없고 frontmatter title 이 있으면 title 을 대체로 사용한다 (L272-L282)
