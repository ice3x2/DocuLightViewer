## 1. Scope Overview

이 문서는 DocuLight의 BrowserWindow 관리와 네비게이션을 정의한다. 창 생성/갱신/종료, named-window upsert, cascading 위치, 네비게이션 history, 파일 와처, 사이드바 트리 로드 오케스트레이션, severity/auto-close/progress 등 창 단위 기능을 포함한다.

## 2. Scope Boundaries

### In Scope

- BrowserWindow 생명주기 (createWindow, updateWindow, closeWindow, createEmptyWindow)
- named-window upsert (nameToId 매핑)
- cascading 위치 (30px offset), 창 크기 resolve (s/m/l/f/auto)
- 네비게이션 history (back/forward, 최대 50)
- 파일 와처 (autoRefresh)
- 사이드바 트리 로드 오케스트레이션과 스트리밍 배치 전송
- 창 메타데이터 (tags, severity, progress, autoClose, alwaysOnTop)

### Out of Scope

- 사이드바 트리 빌드 알고리즘 (TREE)
- IPC 소켓 서버와 action 라우팅 (APP)
- 렌더링 파이프라인 (RENDER)

## 3. Assumptions and Constraints

- 창 상태는 WindowManager.windows Map에 WindowEntry로 저장한다.
- createWindow와 onWindowReady 간 상태는 pendingReady Map으로 전달한다.
- 사이드바 트리 캐시는 TTL 5분, 최대 32 엔트리 LRU를 사용한다.

#### Requirement

시스템은 창 크기 프리셋과 auto 모드를 작업 영역에 맞게 해석하고, auto 기본 크기에서 마지막 창 위치와 크기를 저장하고 복원해야 한다. Markdown viewer 창은 사용자가 200x300 미만으로 줄일 수 없도록 최소 크기를 적용해야 한다.

#### Rationale

사용자가 창 크기와 위치를 기억하도록 하고 프리셋으로 일관된 창 크기를 제공한다.

#### Acceptance Criteria

- [ ] AC-1: size가 s, m, l이면 해당 프리셋 크기를 사용하고 작업 영역 크기로 clamp한다
- [ ] AC-2: size가 f이면 작업 영역 전체 크기를 반환하고 창을 maximize한다
- [ ] AC-3: size가 auto이면 저장된 lastWindowBounds 크기를 쓰고 없으면 m 프리셋으로 폴백한다
- [ ] AC-4: defaultWindowSize가 auto이고 첫 창이며 저장된 bounds 좌표가 있으면 그 위치로 창을 배치한다
- [ ] AC-5: 창 close 시 defaultWindowSize가 auto이고 최대화나 최소화 상태가 아니면 현재 bounds를 lastWindowBounds에 저장한다
- [ ] AC-6: Markdown viewer 창 생성 경로는 `minWidth=200`, `minHeight=300`을 적용하고 저장된 lastWindowBounds 또는 프리셋 복원 크기도 200x300 미만으로 내려가지 않도록 clamp한다
