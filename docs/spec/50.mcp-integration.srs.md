## 1. Scope Overview

이 문서는 DocuLight의 MCP(Model Context Protocol) 서버 통합을 정의한다. 0.10.16 baseline은 두 transport(stdio, HTTP JSON-RPC 2.0)로 6개 도구(open_markdown, update_markdown, close_viewer, list_viewers, search_documents, search_projects)를 노출한다. 0.11.0-w2 save/search target은 document-only `save_document`와 read-only `smart_search`를 추가해 strict 8-tool transport parity 계약을 확장한다.

Active 0.11.0-w2 MCP contract는 `IR-MCP-018`과 `CON-MCP-007`이다. `save_document`는 required `content`와 typed optional metadata만 받아 persistent document store에 저장하며, 응답은 `documentId`와 `indexing{state,jobId?}` 중심의 canonical JSON을 사용한다. `smart_search.limit` 기본값은 20이고 hard maximum은 50이다. MCP에는 alias 저장 도구, viewer-only 필드, caller destination path, rebuild/clear/retry/cancel/status/model-change 같은 indexing control 도구를 추가하지 않는다.

## 2. Scope Boundaries

### In Scope

- baseline 6개 MCP 도구와 `save_document`, `smart_search` 확장 도구의 스키마, 설명, 입력 검증, response envelope
- stdio MCP 서버 (@modelcontextprotocol/sdk + Zod, mcp-server.mjs)
- HTTP JSON-RPC 2.0 서버 (mcp-http.mjs): initialize, tools/list, tools/call, ping
- Streamable HTTP transport (SSE 스트림, CORS preflight)
- OAuth/OpenID discovery probe stub 응답
- 바운드 포트 파일 기록 ({userData}/mcp-port)

### Out of Scope

- IPC 소켓 브리지와 action 라우팅 (APP)
- 문서 저장/검색 엔진 구현 (DOC)
- 창 동작 구현 (WIN)

## 3. Assumptions and Constraints

- stdio 서버는 Electron에 IPC 소켓으로 연결한다.
- HTTP 서버는 Electron 메인 프로세스에 내장되어 동적 import로 로드된다.
- 기본 HTTP 포트는 설정값 mcpPort를 사용한다.
- 두 transport의 도구 정의는 동등하게 유지되어야 한다.

#### Requirement

시스템은 open_markdown 도구 호출에서 content 또는 filePath 중 최소 하나가 제공되면 뷰어 창을 생성하거나 windowName 이 기존 창과 일치할 때 해당 창을 갱신(upsert)해야 하며, title, foreground, size(s/m/l/f), severity(info/success/warning/error), tags, progress(-1~1.0), noSave, project/docName/description/docType/projectPath frontmatter 메타데이터 파라미터를 수용하고, content 와 filePath 가 모두 없으면 isError 응답을 반환해야 한다.

#### Rationale

외부 AI 도구가 뷰어 창을 생성하거나 이름 기반으로 재사용하는 핵심 진입점이다.

#### Acceptance Criteria

- [ ] AC-1: content 와 filePath 가 모두 없으면 isError true 와 'content or filePath is required.' 텍스트를 반환한다
- [ ] AC-2: stdio transport 는 content 가 MAX_CONTENT_SIZE(10MB)를 초과하면 isError true 를 반환한다 (HTTP transport 는 크기 검사를 수행하지 않는다)
- [ ] AC-3: size enum 은 s/m/l/f 로 제한되고 미지정 시 m 으로 기본 설정된다
- [ ] AC-4: severity enum 은 info/success/warning/error 로 제한된다
- [ ] AC-5: progress 는 -1 이상 1 이하 숫자로 검증된다
- [ ] AC-6: result.upserted 가 true 이면 갱신 메시지를, false 이면 생성 메시지를 windowId 와 함께 반환한다
- [ ] AC-7: stdio 와 HTTP 두 transport 가 open_markdown 을 노출하며 HTTP 스키마는 추가로 alwaysOnTop 파라미터를 포함한다

#### Requirement

시스템은 0.11.0-w2에서 source stdio MCP 서버, HTTP MCP 서버, generated stdio bundle이 `save_document`와 `smart_search`를 포함한 8개 도구 이름 집합, strict schema, model-visible descriptions, canonical JSON response envelope, redaction behavior, forbidden tool/field policy를 동등하게 제공하도록 machine-readable conformance를 제공해야 한다.

### IR-MCP-018 — Strict save_document and smart_search expose typed schemas and deterministic response envelopes

| Field | Value |
| --- | --- |
| Type | interface |
| Target | 0.11.0-w2 |
| Status | verified |
| Priority | critical |
| Tags | wave-2, smart-search, mcp, save-document, tool-parity, eight-tools, strict-schema, typed-schema, limit-default-20, no-indexing-controls, feasibility:high |
| Risk | high |
| Stability | stable |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | docs/research/knowledge_store/knowledge.md |

#### Requirement

시스템은 0.11.0-w2에서 stdio MCP와 HTTP MCP에 `save_document`와 read-only `smart_search`를 포함한 정확한 8개 도구 인터페이스를 제공해야 한다. `save_document`는 field-level typed strict schema로 Markdown 콘텐츠를 DocuLight persistent document store에 저장하는 write-capable no-viewer 도구이며, `smart_search`는 BM25와 embedding 기반 hybrid search를 수행하는 read-only 검색 도구다.

#### Rationale

2차 평가에서는 optional metadata type/length, `gitContextPath` local-only 제약, `indexing.queued` 의미가 아직 모호하다고 확인되었다. MCP schema와 response envelope는 stdio/HTTP/bundle 간 drift 없이 생성될 수 있을 만큼 구체적이어야 한다.

#### Acceptance Criteria

- [x] AC-1: stdio와 HTTP `tools/list`는 `open_markdown`, `update_markdown`, `close_viewer`, `list_viewers`, `save_document`, `search_documents`, `search_projects`, `smart_search`의 8개 도구 이름을 동일하게 노출하고, `save_markdown`, `store_document`, `remember_document` 같은 alias 도구를 노출하지 않는다.
- [x] AC-2: `save_document` input schema는 flat object이며 `additionalProperties=false` 또는 동등한 strict rejection을 적용한다. required field는 `content` string(1..10MB) 하나다.
- [x] AC-3: `save_document` optional metadata type은 `title` string(1..200 chars), `project` string(1..120 chars), `docName` string(1..160 chars), `description` string(0..1000 chars), `docType` DOC_TYPE_VALUES enum, `category` string(1..120 chars), `documentTags` string array(max 32 items, each 1..64 chars), `gitContextPath` local filesystem path string(1..1024 chars)로 고정한다.
- [x] AC-4: `gitContextPath`는 git metadata 수집용 local-only transient context이며 저장 위치를 고르지 않는다. URL-like value, remote URI, credential-bearing string, destination-like field value, configured save root override는 validation failure로 거부하고 raw value를 response/diagnostics/log/export에 echo하지 않는다.
- [x] AC-5: `save_document` schema는 `noSave`, `windowId`, `windowName`, `foreground`, `alwaysOnTop`, `size`, `severity`, `progress`, `tags`, `appendMode`, `query`, `limit`, `mode`, `filters`, `forceIndex`, `rebuild`, `clearIndex`, `cancel`, `retry`, `status`, `filePath`, `sourceFilePath`, `path`, `savePath`, `outputPath`, `destinationPath`, `directory`, `mcpAutoSavePath`, `projectPath`를 거부한다.
- [x] AC-6: `save_document` 도구 설명 첫 문장은 "Save Markdown content to DocuLight's persistent document store for future retrieval by search_documents and smart_search."와 동등한 의미를 가져야 하며, 뷰어 창을 open/show/focus/update/close하지 않는다고 명시한다.
- [x] AC-7: `open_markdown` 설명 첫 문장은 visible DocuLight viewer를 열거나 갱신하는 도구라고 설명하고, 문서만 저장하려는 경우 `save_document`를 사용하라고 명시한다. `update_markdown` 설명은 existing viewer/windowId 갱신용이라고 구분한다.
- [x] AC-8: `save_document` field descriptions는 `documentTags`가 persistent document metadata이고 `tags`는 viewer/window grouping metadata라서 save_document에서 허용되지 않는다고 명시한다.
- [x] AC-9: `search_documents`와 `smart_search` 설명은 기존 저장 문서를 검색하는 도구이며 새 콘텐츠를 저장하지 않는다고 구분한다. `smart_search.limit` 설명은 생략 시 20개를 반환하며 더 필요한 경우에만 1..50 범위에서 늘리라고 설명한다.
- [x] AC-10: `save_document` 성공 응답은 MCP `content[0].text`에 canonical JSON 문자열을 넣고 `schemaVersion=save_document.v1`, `saved=true`, required `documentId`, `sourceRelativePath` 또는 `redactedPath`, `resolvedTitle`, `project`, `docType`, `category`, `documentTags`, `indexing{state,jobId?}`, `warnings[]`를 포함한다. Required `queued` boolean은 응답 schema에 포함하지 않는다.
- [x] AC-11: `indexing.state` enum은 `queued`, `enqueue_failed`, `degraded`를 포함한다. `jobId`가 있더라도 diagnostic-only 값이며 status/cancel/retry/rebuild를 위한 MCP control handle이 아니라고 response schema 설명과 conformance fixture가 검증한다.
- [x] AC-12: `warnings[]` item은 `code`, `message`, `retryable`을 가진다. save_document 실패 응답은 `isError=true`와 canonical JSON `error{code,message,retryable}`를 사용하며 error code는 `missing_content`, `storage_not_configured`, `validation_failed`, `write_failed`, `path_policy_violation`을 구분한다.
- [x] AC-13: `save_document` 응답과 diagnostics는 `windowId`, `windowName`, raw absolute saved path, app userData index path, full Markdown content, embedding API key, credential-bearing URL, index rebuild/control handle, raw `gitContextPath`를 포함하지 않는다.
- [x] AC-14: `smart_search` input schema는 `query` required string(1..500 chars), `mode` enum(`auto`,`keyword`,`hybrid`, default `auto`), `limit` integer(1..50, default 20), `filters` object(`project`, `docType`, `category`, `documentTags`, `tagMode=any|all`, `pathPrefix`, `linkedTo`, `linkedFrom`, `includeStale=false`), `includeSnippets=true`, `includeScores=false`, `includeTrace=false`, `includeDiagnostics=false`, `allowDegraded=true`를 두 transport에서 동등하게 제공한다.
- [x] AC-15: caller가 `smart_search.limit`을 생략하면 최대 20개 결과를 반환하고, caller가 20보다 큰 값을 제공하면 schema hard maximum 50 안에서 더 많은 결과를 반환할 수 있다.
- [x] AC-16: `smart_search` response는 MCP `content[0].text`에 canonical JSON 문자열을 넣고 `schemaVersion`, `mode.requested`, `mode.used`, `degraded`, `degradationReasons[]`, `results[]`, `indexFreshness`, `staleFilteredCount`, optional `diagnostics{indexStatus,provider,policyHash,warnings[]}`를 포함한다.
- [x] AC-17: 각 `smart_search` result는 `rank`, `documentId`, `title`, `sourceRelativePath` 또는 `redactedPath`, `docType`, `category`, `documentTags`, `snippet{text,headingPath,lineRange}`, optional `scoreDetails{total,keyword,semantic,metadata,link,freshness,stalePenalty}`를 포함하고 internal absolute path를 포함하지 않는다.
- [x] AC-18: `smart_search` 호출은 rebuild, cancel, retry, embedding model change, index clear 같은 indexing control side effect를 수행하지 않는다. `save_document` 호출은 FR-DOC-028의 post-save enqueue 외 indexing control side effect를 수행하지 않는다.
- [x] AC-19: `search_documents`와 `search_projects`의 기존 keyword 검색 동작과 응답 형식은 `save_document`와 `smart_search` 추가로 변경되지 않는다.
- [x] AC-20: degraded 또는 error `smart_search` response도 동일한 JSON envelope를 유지하며 `results=[]`, `error{code,message,retryable}`를 추가할 수 있고 `degradationReasons`는 `embedding_disabled`, `semantic_stale`, `native_unavailable`, `provider_unavailable`, `policy_blocked`, `index_unavailable`, `keyword_only` 중 하나 이상을 사용한다.
