# DocuLight Viewer v1.0.6 Release Notes

## Links to Documents with Non-ASCII Names Now Work

- **Percent-decoded link targets** -- The markdown parser runs every href through `encodeURI()`, so a link to `한글문서.md` reached the navigation code as `%ED%95%9C%EA%B8%80...md` and was used verbatim as a filesystem path. Links to documents whose names contain Korean, Japanese, Chinese, accented, or spaced characters now open the file they name.
- **One resolver for window and tab navigation** -- Href decoding and markdown-target classification moved into a single main-process module. The renderer no longer decodes hrefs or assembles filesystem paths, so single-window and tab navigation cannot drift apart.
- **Names containing a literal percent sign** -- Decoding runs per escape sequence instead of all-or-nothing, because the parser re-emits an encoded `%` as a bare one. A document named `진행률 80%.md` now opens from a link.
- **Resolved paths are never decoded twice** -- Sidebar, breadcrumb, document-navigation, and search results hand over real filesystem paths. Those keep literal percent sequences and `#` characters in file names intact.
- **Root-relative links in tab mode** -- A root-relative href such as `/docs/a.md` normalizes to a drive-relative path on Windows. Tab navigation used to re-check that shape and never agree it was resolved, looping instead of opening the document.

## Security

- Scheme, network-location, and NUL guards now run on the decoded value and again on the normalized path, so percent-encoded disguises such as `javascript%3A`, `%2F%2Fhost`, and `a%00.md` are rejected. These passed the previous checks.
- A relative link with no base document is rejected rather than resolved against the process working directory.

## Verification

- Contract tests and Playwright end-to-end tests cover single-window and tab navigation, sidebar tree clicks, sidebar file search, blocked schemes, and non-markdown extensions.
- Verified on Windows and on Linux (WSL2, Electron 33 Linux build).

# DocuLight Viewer v1.0.6 릴리즈 노트

## 비ASCII 이름 문서로 가는 링크 정상화

- **링크 주소 퍼센트 디코딩** -- 마크다운 파서가 모든 링크 주소에 `encodeURI()`를 적용하기 때문에 `한글문서.md`로 가는 링크는 `%ED%95%9C%EA%B8%80...md` 형태로 내비게이션 코드에 전달되었고, 그 문자열이 그대로 파일 경로로 사용되었습니다. 이제 한국어, 일본어, 중국어, 악센트 문자, 공백이 포함된 이름의 문서도 링크로 열립니다.
- **창 이동과 탭 이동의 단일 해석기** -- 링크 주소 디코딩과 마크다운 대상 분류를 메인 프로세스의 단일 모듈로 옮겼습니다. 렌더러는 더 이상 링크 주소를 디코딩하거나 파일 경로를 조립하지 않으므로 창 모드와 탭 모드가 서로 어긋날 수 없습니다.
- **이름에 퍼센트 기호가 포함된 문서** -- 파서가 인코딩된 `%`를 다시 맨 `%`로 되돌리기 때문에, 디코딩을 전체 단위가 아니라 이스케이프 연속 구간 단위로 수행하도록 바꾸었습니다. `진행률 80%.md` 같은 문서도 링크로 열립니다.
- **해석이 끝난 경로의 재디코딩 방지** -- 사이드바, 이동 경로 표시줄, 문서 하단 이동, 검색 결과는 실제 파일 경로를 전달합니다. 이제 파일 이름에 포함된 리터럴 퍼센트 시퀀스와 샤프 문자가 보존됩니다.
- **탭 모드의 루트 상대 링크** -- `/docs/a.md` 같은 루트 상대 주소는 Windows에서 드라이브 상대 경로로 정규화됩니다. 기존 탭 이동은 그 형태를 다시 검사하여 해석이 끝났음을 인정하지 못했고, 문서를 열지 못한 채 반복 요청에 빠졌습니다.

## 보안

- 스킴, 네트워크 위치, NUL 차단 검사를 디코딩 이후 값과 경로 정규화 이후 값에 각각 다시 적용합니다. 따라서 `javascript%3A`, `%2F%2Fhost`, `a%00.md` 처럼 퍼센트 인코딩으로 위장한 입력이 거부됩니다. 이 입력들은 이전 검사에서는 통과했습니다.
- 기준 문서가 없는 상대 링크는 프로세스 작업 디렉터리를 기준으로 해석하지 않고 거부합니다.

## 검증

- 계약 테스트와 Playwright 종단 테스트로 창 모드 이동, 탭 모드 이동, 사이드바 트리 클릭, 사이드바 파일 검색, 차단 스킴, 비마크다운 확장자를 확인합니다.
- Windows와 Linux(WSL2, Electron 33 리눅스 빌드) 양쪽에서 검증했습니다.
