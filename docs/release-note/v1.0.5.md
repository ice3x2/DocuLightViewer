# DocuLight Viewer v1.0.5 Release Notes

## Verified Original Documents for Indexed Search Results

- **Original-path preservation** -- External Markdown indexing now keeps the lexical path and its canonical target in internal-only ledger columns. Public search and MCP results never expose those raw paths.
- **Safe source selection** -- Opening an indexed result by `documentId` prefers the original only after extension, canonical-path, containment, file identity, readability, and UTF-8 checks. If validation fails, DocuLight uses the verified indexed copy.
- **TOCTOU and link-retarget protection** -- Content is read from one read-only file handle and checked before and after the read. Symlink or junction retargeting fails closed with a stable redacted status.
- **Backward compatibility** -- Existing databases receive nullable columns through an additive migration. Legacy hash-only aliases continue to open their indexed copies and gain paths only when the same original is explicitly reopened.
- **MCP/API compatibility** -- `open_markdown` accepts an indexed `documentId` over both stdio and HTTP while the eight-tool contract and read-only search behavior remain unchanged.

## Verification and Recovery

- TDD coverage includes readable, changed, missing, unreadable, mismatched, retargeted, legacy, and fully unavailable sources.
- Windows, macOS, and Linux releases remain gated by the complete regression suite, worker responsiveness benchmark, and packaged-app smoke test.
- Rollback to v1.0.4 is safe: the schema change is additive, and v1.0.4 ignores the new nullable columns.

# DocuLight Viewer v1.0.5 릴리즈 노트

## 인덱스 검색 결과의 검증된 원본 문서 열기

- **원본 경로 보존** -- 외부 Markdown을 인덱싱할 때 사용자가 지정한 경로와 정규화된 실제 대상 경로를 내부 전용 원장 열에 함께 저장합니다. 공개 검색 및 MCP 결과에는 실제 경로를 노출하지 않습니다.
- **안전한 원본 선택** -- `documentId`로 인덱스 결과를 열면 확장자, 정규 경로, 저장소 포함 관계, 파일 동일성, 읽기 권한, UTF-8을 확인한 뒤에만 원본을 사용합니다. 검증 실패 시 확인된 인덱스 복사본으로 대체합니다.
- **TOCTOU 및 링크 재지정 방어** -- 하나의 읽기 전용 파일 핸들에서 내용을 읽고 전후 상태를 다시 검사합니다. symlink 또는 junction 대상이 바뀌면 비식별화된 고정 상태로 안전하게 실패합니다.
- **이전 버전 호환** -- 기존 DB에는 nullable 열을 추가하는 방식으로 자동 마이그레이션합니다. 해시만 가진 예전 별칭은 인덱스 복사본을 계속 사용하며, 동일 원본을 명시적으로 다시 열었을 때만 경로를 보강합니다.
- **MCP/API 호환** -- stdio와 HTTP의 기존 `open_markdown`에 인덱스 `documentId` 입력을 추가하면서 8개 도구 계약과 읽기 전용 검색 동작은 유지합니다.

## 검증 및 복구

- 읽기 가능, 변경됨, 삭제됨, 권한 거부, 경로 불일치, 링크 재지정, 레거시 데이터, 원본·복사본 동시 유실 시나리오를 TDD로 검증합니다.
- Windows, macOS, Linux 릴리스는 전체 회귀 테스트, 워커 응답성 벤치마크, 패키지 앱 스모크 테스트를 모두 통과해야 게시됩니다.
- v1.0.4로 롤백해도 안전합니다. 스키마 변경은 열 추가뿐이며 v1.0.4는 새 nullable 열을 무시합니다.
